#Результат

Репозиторий содержит собственную согласованную документацию, которая описывает текущую реализацию и проходит строгую проверку самим Docgent.

#Область изменения

  • docs/;
  • README.md.

#Не входит в задачу

  • изменение поведения CLI или JSON schema;
  • публикация release artifacts;
  • генерация и добавление output portal в Git.

#Критерии приёмки

  • ✓AC-01 Самодокументация проходит docgent check --strict без замечаний.
  • ✓AC-02 Модули, сценарии, правила, roadmap и CLI-контракт связаны стабильными ID.
  • ✓AC-03 README содержит прямую ссылку на исходную документацию проекта.

#План

  • ✓Зафиксировать текущее состояние, архитектуру и продуктовый охват.
  • ✓Описать модули, use cases, бизнес-правила и публичные контракты.
  • ✓Добавить риски, ADR, руководство проверки и справочник параметров.
  • ✓Связать документы, запустить strict-check и полный Go-цикл.

#Проверка

  • AC-01 → go run ./cmd/docgent check ./d[o]cs --strict --stale-days 0
  • AC-02 → go test ./... -run 'TestKnowledgeModel|TestMinimalDocumentationCheckAndBuild'
  • AC-03 → grep -q 'Проектная документация Docgent' README.md
  • ALL → go test ./...
  • DOCS → go run ./cmd/docgent check ./docs --strict --stale-days 0

#Влияние на документацию

Созданы исходные проектные документы в docs/. README теперь ведёт на docs/index.md; сгенерированный портал остаётся build artifact.
