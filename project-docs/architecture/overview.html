Архитектура Docgent

Docgent реализован как один Go-модуль с линейным конвейером: Markdown-файлы преобразуются в проверенную проектную модель, из которой формируются HTML и JSON-представления.

Docgent реализован как один Go-модуль с линейным конвейером: Markdown-файлы преобразуются в проверенную проектную модель, из которой формируются HTML и JSON-представления.

#Контекст

Источником истины является каталог Markdown в репозитории. Docgent читает его локально и не требует базы данных, сервера, npm или сетевого доступа. Встроенный browser bundle Mermaid является vendored asset и не добавляет runtime-зависимость. Человек работает с Markdown и HTML, агент или CI — с CLI exit code и JSON ProjectReport schema v2.

#Поток данных

  1. CLI нормализует входные параметры и repository root.
  2. Сканер читает Markdown без перехода по символическим ссылкам.
  3. Парсер выделяет заголовки, метаданные, списки, ссылки, секции и Mermaid fences.
  4. Валидаторы строят связи модулей, сценариев, процессов, правил, задач,

roadmap, экранов и переходов.

  1. check возвращает diagnostics, а task context — ограниченный срез модели.
  2. build создаёт автономный портал, полный каталог процессов, Screen Map,

проигрываемые сценарии и ProjectReport.

  1. Только task verify --run запускает объявленные команды из корня репозитория.

Подробные визуальные представления вынесены в отдельные документы:

  • сборка автономного портала;
  • проверка документационного контракта;
  • локальный просмотр портала;
  • работа с проверяемой задачей.

#Границы доверия

  • Markdown и локальные assets считаются недоверенным содержимым для HTML.
  • Mermaid выполняется только в браузере с securityLevel: strict; конфигурация

из diagram source запрещена.

  • Пути output, repository links и report проходят проверки выхода за границы.
  • Команды work item считаются доверенным кодом и требуют явного запуска.
  • Сгенерированные build/, dist/ и example/site/ не являются источником

истины.

#Отказоустойчивость

Ошибки модели не приводят к выполнению команд. task verify --run сначала применяет локальный validation gate выбранной задачи. Timeout завершает дерево процессов, а stdout и stderr сохраняются ограниченным хвостом.

#Ограничения архитектуры

  • пакет намеренно остаётся плоским, пока разделение не уменьшает связанность;
  • собственный Markdown subset увеличивает ответственность тестов;
  • публичная JSON-схема меняется только с сохранением явной совместимости или

новой версии.
