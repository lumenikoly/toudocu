Системная граница Docu-docu

Docu-docu ограничен одним локальным процессом, который читает документацию и репозиторий, строит проверенную модель и выдаёт diagnostics либо производные представления. Встраивающий Go-код вызывает тот же фасад модели и операций без отдельного процесса. В serve процесс принимает ограниченные editor-запросы и атомарно сохраняет выбранный workspace-файл. Пользователь, библиотечный потребитель, агент, CI и браузер остаются взаимодействующими сторонами за этой границей. Release installer также остаётся снаружи: это отдельный bootstrap, который использует сеть только до запуска Go runtime.

#Область

Ответ описывает границу одного Go runtime, доступного через CLI или публичный пакет, и его внешние взаимодействия. Команды, форматы, Go-фасад и причины dependency-free поставки остаются в CLI-контракте, Go API-контракте и ADR-001.

#Взаимодействующие стороны

  • разработчик или агент выбирает вход, repository root и операцию;
  • библиотечный потребитель вызывает экспортируемый фасад api.go и получает

типизированную модель или отчёт;

  • CI использует exit code и ProjectReport schema v1;
  • файловая система предоставляет Markdown, локальные assets и разрешённые

repository targets;

  • браузер читает автономный портал через file://; через serve он также

читает revision/editor API и явно сохраняет разрешённый исходник;

  • shell и дочерние процессы доступны только явному task verify --run.

#Что остаётся снаружи

Docu-docu не хранит серверное состояние, не обращается к базе данных и не интерпретирует пользовательский запрос. Граница между детерминированным CLI и смысловой работой исполнителя зафиксирована в ADR-002. Загрузка release assets и запись бинарника в user install dir принадлежат отдельному installer workflow, описанному в руководстве по установке.
