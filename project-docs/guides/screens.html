Карта экранов и проигрываемые пользовательские сценарии

Docgent строит карту, каталог, пошаговые сценарии и traceability из документов screens/SC- .md . Отдельный screens/map.md не используется.

Docgent строит карту, каталог, пошаговые сценарии и traceability из документов screens/SC-*.md. Отдельный screens/map.md не используется.

Страницу карты можно явно включить или отключить:

bash
docgent build ./docs --screen-map
docgent build ./docs --no-screen-map

При отключённой общей карте каталог, страницы use cases с пошаговым режимом и машинная модель сохраняются.

В навигации портала раздел «Экраны» открывает каталог и содержит документы отдельных экранов. При включённой общей карте она доступна отдельным дочерним пунктом; --no-screen-map убирает этот пункт и страницу, не меняя каталог. UC-* находятся в самостоятельном разделе «Пользовательские сценарии», а FLOW-* — в «Процессах». Экранная карта и пошаговый режим выбранного сценария встроены в каноническую страницу /use-cases/UC-*.html.

#Документ экрана

md
# SC-AUTH-LOGIN: Вход

- Идентификатор: SC-AUTH-LOGIN
- Тип: Экран
- Модуль: MOD-AUTH
- Статус: В работе
- Маршрут: `/login`
- Превью: `../assets/screens/login.webp`
- Родительский экран: SC-PUBLIC-HOME

## Состояния

| ID | Название | Превью |
|---|---|---|
| DEFAULT | Исходное | `../assets/screens/login.webp` |
| INVALID-CREDENTIALS | Неверные данные | — |

## Переходы

| ID | Сценарий | Действие | Условие | Результат | Состояние | Ошибка |
|---|---|---|---|---|---|---|
| TR-AUTH-001 | UC-AUTH-01 | Войти | Успех | SC-ACCOUNT-HOME | DEFAULT | — |
| TR-AUTH-002 | UC-AUTH-01 | Войти | Неверные данные | SC-AUTH-LOGIN | INVALID-CREDENTIALS | INVALID_CREDENTIALS |

Обязательны ID, тип, модуль и статус. Поддерживаются Экран, Страница, Модальное окно, Панель, Внешняя страница и Системное состояние. DEFAULT существует неявно. Переход без сценария является глобальным и участвует во всех достижимых проигрываемых сценариях. Родительский экран определяет sitemap, а не порядок user flow.

Переходу обязательны ID, действие, условие и результат. Дополнительно можно указать состояние, ошибку, сообщение, контракт и тип:

ТипОтображение на карте
navigationсплошная направленная линия
errorпунктирная линия
redirectштриховая линия
returnлиния с обратным изгибом
externalдвойная линия

Маршруты автоматически используют свободные коридоры между карточками. Подпись перехода размещается отдельно от линии, не пересекает карточки и показывает действие и условие максимум в двух строках. Полный текст всегда доступен при выборе перехода в боковой панели.

Переход на тот же экран допустим только с состоянием, ошибкой или сообщением, которое объясняет наблюдаемое изменение.

#Use case

Экранный сценарий задаёт:

md
- Начальный экран: SC-AUTH-LOGIN
- Конечные экраны: SC-ACCOUNT-HOME
- Разрешить цикл: Да

Docgent добавляет переходы выбранного UC-* и глобальные переходы, вычисляет достижимые экраны, тупики, циклы и пути к terminal screens.

Неконечный достижимый экран должен иметь выход. Цикл без выхода считается ошибкой, если use case явно не содержит Разрешить цикл: Да.

#Карта

Карточка показывает preview или placeholder, ID, название, маршрут, статус, модуль и количество входящих и исходящих переходов. Доступны:

  • общая карта с группами модулей;
  • фильтр выбранного модуля;
  • фильтр выбранного use case;
  • фильтр статуса и поиск;
  • режим только незавершённых экранов;
  • sitemap по родительским связям.

Клик выбирает экран и открывает боковую панель. Двойной клик открывает документ. Связь также можно выбрать: панель покажет действие, условие, source, target, use case, состояние и ошибку.

Управление мышью и touch:

  • колесо — zoom относительно указателя;
  • drag по свободному месту — pan;
  • кнопки — zoom in, zoom out, fit, reset и fullscreen.

Ctrl/Cmd вместе с колесом остаётся browser zoom. С клавиатуры работают +, -, 0, Esc и Enter.

#Пошаговое прохождение

Viewer начинает с начального экрана use case. Доступные действия формируются из переходов выбранного сценария и глобальных переходов. Каждый шаг сохраняет предыдущий экран и состояние в памяти страницы.

  • Назад восстанавливает предыдущий шаг;
  • Сначала очищает историю;
  • ошибка или сообщение отображается рядом с preview;
  • состояние выбирает собственный preview, если он объявлен;
  • terminal screen показывает «Начать заново», «Показать карту» и

«Открыть use case».

История после перезагрузки страницы не сохраняется. Viewer является симуляцией документации и не выполняет реальные API-запросы.

#Ошибки и previews

Коды ошибок объявляются в contract document:

md
## Ошибки

| ID | Сообщение |
|---|---|
| INVALID_CREDENTIALS | Неверный email или пароль. |

Preview допускает PNG, JPG, JPEG, WEBP, AVIF и GIF внутри repository root. Отсутствующий файл даёт placeholder и warning. SVG, HTML, XML, JavaScript, absolute path, traversal и symlink блокируются.

#Hotspots

Необязательный screens/hotspots.json хранит процентные координаты:

json
{
  "SC-AUTH-LOGIN": [
    {
      "transition": "TR-AUTH-001",
      "x": 31.5,
      "y": 59.2,
      "width": 37,
      "height": 8.4
    }
  ]
}

Некорректная зона исключается из HTML, но список действий flow продолжает работать. Валидная зона всегда остаётся доступной кнопкой: в скрытом режиме она проявляется при наведении или клавиатурном фокусе, а переключатель «Показать интерактивные зоны» делает все hotspots постоянно видимыми.

Координаты и размеры должны быть положительными, лежать в диапазоне 0–100 и не выводить прямоугольник за границы preview. Один переход не дублируется на экране без явного allowDuplicate.

#Traceability

Задача объявляет затронутые переходы, символическую связь и отдельно команду:

md
- Переходы: TR-AUTH-001

## Проверка

- `AC-01` → `TR-AUTH-001` → `TestSuccessfulLogin`
- `AC-01` → `go test ./... -run TestSuccessfulLogin`

Generated portal содержит /screens/index.html, каталог, /use-cases/UC-*.html с вкладками #overview, #map, #play, #links, /traceability.html и top-level screen model в report.json schema v1. Все страницы работают через file://.

#Что проверяет CLI

Для экранов проверяются ID, тип, статус, существование модуля, уникальность маршрута, preview и безопасность пути. Для переходов — ID, обязательные поля, target, use case, state, error definition и осмысленность self-transition.

Для flow проверяются start и terminal screens, достижимость, тупики, ветвления, циклы и выходы из ошибочных состояний. Для hotspots проверяются ссылки, координаты, границы и дублирование. Work items проверяются на существующие SC-*, TR-* и связи AC → TR → verification.

Ошибка screen graph блокирует только карту, а ошибка отдельного flow — только его запуск. Остальные документы и каталоги продолжают генерироваться. Отсутствие preview создаёт warning и placeholder, но не останавливает сборку.
