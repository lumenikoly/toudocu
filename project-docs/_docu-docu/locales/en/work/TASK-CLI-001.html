#Result

The CLI provides a deterministic path from searching documentation and creating framework to readiness, context and explicit verification of the selected task.

#Behavior change

#Before

The CLI provided only task context and the task check execution command; frameworks, readiness and source-level search were missing.

#After

The CLI provides search, task init, scaffold, task ready, extended task context and task verify; The old task check command is missing.

#Scope

  • internal/app/cli.go
  • internal/app/types.go
  • report_types.go
  • internal/app/knowledge.go
  • internal/app/task_verify.go
  • internal/app/task_context.go
  • search.go
  • internal/app/scaffold.go
  • internal/app/task_ready.go
  • docs/
  • skills/docu-docu/

#Out of scope

  • interpretation of natural-language request inside Docu-docu;
  • automatic selection or filling of entities;
  • automatic change of statuses and acceptance checkboxes;
  • new external dependencies.

#Acceptance criteria

  • ✓AC-01 New CLI forms are parsed deterministically, and task check is rejected.
  • ✓AC-02 Search, init and scaffold respect ranking, ID-based paths and atomic create.
  • ✓AC-03 Ready and context return the full local contract without modifying files or executing commands.
  • ✓AC-04 Verify supports dry-run, targeted and full run with secure reporting and limited output.
  • ✓AC-05 All public JSON reports use a single schema v1.

#Plan

  • ✓Expand parser, report types and task contract.
  • ✓Implement search, wireframes and readiness.
  • ✓Expand context and replace check with verify.
  • ✓Synchronize documentation, skills and tests.
  • ✓Run a full verification cycle.
