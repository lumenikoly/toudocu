#Result

docs/architecture/overview.md is a required architecture map, and every other Markdown document in architecture/ responds to one explicit architectural question and is directly listed in the overview.

#Behavior change

#Before

The architecture/ directory was an optional set of specialized Markdown documents without mandatory map, explicit question and increased strictness of local links.

#After

Regular check requires a correct architecture overview, one non-empty question for each detailed document, a direct recursive document map and secure existing local links. Skill provides separate RU/EN templates, safe init and semantic gate ARCH001–ARCH013.

#Scope

  • internal/app/docs_core.go;
  • documentation_links.go;
  • internal/app/markdown_parse.go;
  • integration_test.go;
  • screens_test.go;
  • skill_templates_test.go;
  • skills/docu-docu/;
  • docs/;
  • example/docs/;
  • project-docs/;
  • example/project-docs/;
  • README.md;
  • CHANGELOG.md;
  • AGENTS.md.

#Out of scope

  • new Go command docu-docu init;
  • changing ProjectReport schema v1 or documents[].type type;
  • automatic migration of legacy architecture;
  • checking punctuation, question words or architectural meaning in the CLI;
  • Docu-docu documents about deployment or data ownership without confirmation

architectural issue.

#Acceptance criteria

  • ✓AC-01 A regular check produces stable errors for a missing or

mistyped overview, missing question and document out direct recursive map overview.

  • ✓AC-02 Architectural broken/blocked links are errors, and

a non-punctuation non-blank question is acceptable.

  • ✓AC-03 JSON schema remains v1, and overview is serialized with

type: architecture.

  • ✓AC-04 RU/EN skill assets contain separate overview/detail templates,

minimal init creates index.md and overview, and legacy architecture stops init without automatic migration.

  • ✓AC-05 Managed guidance and semantic gate synchronously set type boundaries,

direct overview map and codes ARCH001–ARCH013.

  • ✓AC-06 Docu-docu and Service Desk architecture divided into confirmed

question-oriented documents, and both portals are reassembled only from original Markdown after independent review.

#Plan

  • ✓Add metadata aliases and structural architecture diagnostics.
  • ✓Expand behavioral and schema contract tests.
  • ✓Update templates, init workflow, managed guidance and semantic gate.
  • ✓Migrate Docu-docu and demo Service Desk documentation.
  • ✓Perform an independent semantic review and eliminate the comments.
  • ✓Go through full Go/Docu-docu verification and rebuild portals.
