UC-DOCS-02: Проверить документацию

Разработчик или CI-процесс проверяет документационный контракт без генерации сайта и без выполнения команд рабочих задач.

UC-DOCS-02

Разработчик или CI-процесс проверяет документационный контракт без генерации сайта и без выполнения команд рабочих задач.

#Входные данные

  • каталог документации;
  • repository root;
  • необязательный режим --strict;
  • формат результата text или json.

#Предусловия

  • Docgent доступен для запуска;
  • инициатор имеет права чтения документации и repository root.

#Основной сценарий

  1. Инициатор вызывает docgent check ./docs.
  2. Docgent читает Markdown-файлы и строит связанную модель проекта.
  3. Docgent проверяет структуру, ID, ссылки, roadmap и рабочие задачи.
  4. Docgent выводит diagnostics в текстовом виде или возвращает

ProjectReport при --format json.

  1. Инициатор использует exit code и отчёт для принятия результата проверки.

#Ошибочные сценарии

  • на шаге 2 недоступный входной каталог или неверный repository root завершает

команду с кодом 1;

  • ошибки структуры, ссылок или связей попадают в отчёт и дают код 1 в любом

режиме;

  • без --strict предупреждения остаются в отчёте, но не меняют успешный exit

code;

  • с --strict любое предупреждение также приводит к коду 1;
  • ошибка чтения отдельного файла отражается в diagnostics с путём к документу.

#Постусловия

Исходные документы не изменены, сайт не создан, команды рабочих задач не выполнены. Каждый diagnostic содержит стабильный code и, когда возможно, путь и номер строки.

#Бизнес-правила

Правила определены в документах соответствующих модулей:

  • BR-MODEL-001 — roadmap является единственным источником глобального охвата.
  • BR-MODEL-002 — ссылки не выходят за repository root.
  • BR-MODEL-003 — готовая к работе задача имеет полный проверяемый контракт.
  • BR-CLI-002 — проверки задач запускаются только явно.

  • Проектная модель и валидация
  • CLI и workflow задач
  • Правила проверки

#Проверка

  • позитивные fixtures полной и минимальной модели;
  • негативные тесты правил структуры, ссылок и связей;
  • отдельный тест, что check не вызывает command runner;
  • проверка различия обычного и strict-режимов.
