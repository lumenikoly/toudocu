#RISK-01: Расхождение с полным Markdown

  • Статус: Открыт
  • Вероятность: Средняя
  • Влияние: Среднее
  • Владелец: Команда Docgent

Собственный безопасный Markdown-парсер поддерживает только документированное подмножество синтаксиса. Пользователь может ожидать поведение другого Markdown движка.

#План снижения риска

  • ✓Зафиксировать поддерживаемые конструкции в README.
  • ✓Покрыть рендеринг и экранирование поведенческими тестами.
  • Добавлять новый синтаксис только вместе с позитивными и негативными тестами.

#RISK-02: Выполнение доверенных команд задачи

  • Статус: Риск принят
  • Вероятность: Низкая
  • Влияние: Высокое
  • Владелец: Пользователь репозитория

Команды в разделе проверки work item исполняются через системную оболочку и имеют права запустившего Docgent пользователя.

#План снижения риска

  • ✓Никогда не выполнять команды при check, build или task context.
  • ✓Требовать явный вызов task verify --run.
  • ✓Ограничивать время и объём сохранённого вывода команды.

#RISK-03: Ошибка при очистке output

  • Статус: Снижается
  • Вероятность: Низкая
  • Влияние: Высокое
  • Владелец: Команда Docgent

Ошибочная реализация --clean способна повредить данные вне каталога генерации.

#План снижения риска

  • ✓Запретить корень, каталог документации и его родительские каталоги.
  • ✓Проверять раскрытые пути и символические ссылки.
  • ✓Сохранять негативные тесты для каждого исправленного сценария.
