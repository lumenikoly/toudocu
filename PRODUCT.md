# Продукт Toudocu

Toudocu — локальный Go CLI для проектной документации в Markdown. Он связывает
исходные документы в проверяемую модель, создаёт портал для чтения и помогает
разработчику работать с документацией рядом с кодом.

## Для кого

Основные пользователи:

- авторы проектной документации;
- разработчики и тестировщики;
- владельцы продукта и архитекторы, которым нужны явные связи между решениями,
  сценариями и реализацией;
- агенты разработки, работающие через установленный навык и локальные команды.

Все они работают с Markdown в Git и должны быстро ответить на три вопроса:
что система делает, как связаны документы и что изменилось сейчас.

## Какую проблему решает Toudocu

Обычный набор Markdown-файлов легко расходится с кодом и превращается в
несвязанные заметки. Toudocu добавляет только те формальные правила, которые
можно проверить: безопасные пути, известные виды документов, стабильные ID,
явные связи, контракты рабочих задач и команды проверки.

Проверка структуры не доказывает правдивость текста. Автор или агент по-прежнему
сверяет смысл с реализацией и прямо отмечает отсутствующие возможности.

## Основные пользовательские пути

### Поддерживать документацию

1. Автор меняет Markdown рядом с кодом.
2. `toudocu check` проверяет структуру и связи.
3. `toudocu serve` показывает результат, диагностические сообщения и
   редактор.
4. После сохранения локальный портал пересобирается.

### Опубликовать портал

1. Автор запускает `toudocu build`.
2. Toudocu создаёт статический портал только для чтения.
3. Каталог публикуется на обычном HTTP(S)-хостинге.
4. После сборки работающий Toudocu-сервер не нужен.

Открытие через `file://` не поддерживается. Для локального чтения
используется `serve`.

### Проверить изменения

1. Разработчик открывает Changes в каноническом `serve`.
2. Он выбирает Git-диапазон и читает Diff или полный UTF-8-файл.
3. Вопрос или запрос на изменение привязывается к документу, строке или
   выделенному фрагменту документации.
4. Сохранение сразу создаёт локальную запись очереди; запрос можно изменить,
   пока агент не забрал его в работу.
5. После отдельного fail-closed вызова `$toudocu feedback` агент берёт работу
   только из `agent next`, а
   ответы появляются в тех же обсуждениях.

Toudocu не выполняет `fetch`, `checkout`, `commit` и другие
операции записи Git.

### Передать работу агенту разработки

Встроенный навык поддерживает `init`, `refresh`,
`translate` и обработку запросов из Toudocu. Это процессы агента, а не
верхнеуровневые команды Go CLI. Выполнение команд рабочей задачи требует
отдельного `task verify --run`.

## Границы продукта

Toudocu намеренно не является:

- облачной системой документации;
- удалённым сервисом совместного редактирования;
- Git-клиентом, который меняет историю или рабочее дерево;
- автономным агентом на основе ИИ;
- конструктором произвольных сайтов;
- доказательством того, что хорошо оформленный текст соответствует коду.

У локального сервера нет TLS и встроенной аутентификации. Переводы остаются
изолированными зеркалами только для чтения. Корневой Go package предназначен
для локального встраивания из исходного дерева, а CLI остаётся основным
публичным интерфейсом. Toudocu устанавливается из GitHub Release или собирается
из исходников.

## Характер продукта

Интерфейс спокойный, точный и инженерный. Он помогает читать сложные связи,
не превращая документацию в декоративную панель управления. Утверждения должны
быть конкретными и подтверждаться репозиторием.

## Принципы интерфейса

- Документ и его связи важнее оформления.
- Основной текст остаётся читаемым при отказе дополнительной функции.
- Ошибка одного блока не скрывает исправные разделы.
- Состояние выражается текстом и формой, а не только цветом.
- Все основные действия доступны с клавиатуры.
- Масштабирование браузера не блокируется.
- Анимация учитывает `prefers-reduced-motion`.
- Статический портал не содержит серверный код и адреса локальных API.
- Один Go-процесс остаётся единственным слоем, который читает файловую систему,
  Git и команды рабочих задач.
