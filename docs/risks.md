# Риски

Актуальные технические и эксплуатационные риски Docu-docu.

## RISK-01: Расхождение с полным Markdown

- Статус: Открыт
- Вероятность: Средняя
- Влияние: Среднее
- Владелец: Команда Docu-docu

Собственный безопасный Markdown-парсер поддерживает только документированное
подмножество синтаксиса. Пользователь может ожидать поведение другого Markdown
движка.

### План снижения риска

- [x] Зафиксировать поддерживаемые конструкции в README.
- [x] Покрыть рендеринг и экранирование поведенческими тестами.
- [ ] Добавлять новый синтаксис только вместе с позитивными и негативными тестами.

## RISK-02: Выполнение доверенных команд задачи

- Статус: Риск принят
- Вероятность: Низкая
- Влияние: Высокое
- Владелец: Пользователь репозитория

Команды в разделе проверки work item исполняются через системную оболочку и
имеют права запустившего Docu-docu пользователя.

### План снижения риска

- [x] Никогда не выполнять команды при `check`, `build` или `task context`.
- [x] Требовать явный вызов `task verify --run`.
- [x] Ограничивать время и объём сохранённого вывода команды.

## RISK-03: Ошибка при очистке output

- Статус: Снижается
- Вероятность: Низкая
- Влияние: Высокое
- Владелец: Команда Docu-docu

Ошибочная реализация `--clean` способна повредить данные вне каталога
генерации.

### План снижения риска

- [x] Запретить корень, каталог документации и его родительские каталоги.
- [x] Проверять раскрытые пути и символические ссылки.
- [x] Сохранять негативные тесты для каждого исправленного сценария.
