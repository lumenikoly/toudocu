# Go API-контракт Docu-docu v1

- Идентификатор: CON-GO-API-V1
- Статус: Готово
- Владелец: Команда Docu-docu
- Последнее обновление: 2026-08-04

Контракт описывает экспортируемый фасад корневого Go-пакета. Он нужен
разработчикам, которые встраивают модель, рендеринг или отчёты Docu-docu без
запуска отдельного процесса.

## Граница публикации

Пакет объявлен модулем `docu-docu` и экспортируется из `api.go`. Канонический
удалённый module path и публичная версия Go-модуля пока не опубликованы;
текущий import path пригоден внутри исходного модуля или через явно настроенный
локальный `replace`. Этот контракт не обещает доступность по удалённому адресу.

`Version` сообщает версию реализации. `EmbeddedFiles` предоставляет встроенные
assets. Экспортируемые типы являются aliases типов реализации из
`internal/app`, чтобы потребитель не зависел от внутреннего расположения
пакетов.

## Операции

| Группа | Операции | Побочные эффекты |
|---|---|---|
| CLI | `PrintHelp`, `ParseArguments`, `RunCLI`, `Main` | определяются выбранной CLI-командой; `Main` завершает процесс через exit code |
| Классификация | `ClassifyDocument`, `StatusFor` | отсутствуют |
| Модель | `BuildDocumentationModel`, `BuildReport` | читают документацию и repository root; исходники не изменяют |
| Markdown | `AnalyzeMarkdown`, `RenderMarkdown`, `RenderMarkdownFragment` | отсутствуют |
| Портал | `GenerateSite` | записывает output; безопасная очистка выполняется только при `Options.Clean` |
| Поиск | `SearchDocumentation` | отсутствуют |
| Создание | `InitTask`, `Scaffold` | атомарно создают один новый файл без перезаписи |
| Жизненный цикл задачи | `MoveTask` | для `archive` или `restore` перемещает один допустимый work item без перезаписи |
| Контекст задачи | `BuildTaskContext`, `BuildTaskReady` | отсутствуют; команды проверки не исполняются |
| Изменения | `BuildDocumentationChanges` | только читает Git и workspace; не выполняет fetch, checkout или запись в index |

Прямой вызов функции получает явно заполненный `Options`. Значения по умолчанию
CLI появляются при `ParseArguments`; библиотечный потребитель не должен считать
неуказанные поля эквивалентными CLI-флагам без проверки конкретной операции.

## Минимальный пример

Пример предназначен для кода внутри текущего исходного модуля или проекта с
явным локальным `replace`:

```go
package main

import (
	"fmt"

	docudocu "docu-docu"
)

func main() {
	model, err := docudocu.BuildDocumentationModel(docudocu.Options{
		InputDirectory: "./docs",
		RepositoryRoot: ".",
	})
	if err != nil {
		panic(err)
	}
	report := docudocu.BuildReport(model)
	fmt.Println(report.Stats.Documents)
}
```

## Ошибки и результаты

Функции с `error` возвращают ошибки аргументов, файловой системы или операции.
Успешно построенная модель и типизированные отчёты могут дополнительно содержать
`Issue` с diagnostics документации. `RunCLI` преобразует результат в exit codes
из [CLI-контракта](cli.md); прямые библиотечные вызовы не завершают процесс, за
исключением `Main`.

`BuildTaskReady` возвращает `TaskReadyReport` со статусом и issues вместо
отдельного `error`. Выполнение команд `task verify --run` доступно через
`RunCLI`; отдельной экспортируемой функции запуска command runner нет.

## Совместимость

Публичную поверхность определяют `api.go`, сигнатуры экспортируемых функций,
aliases типов и JSON tags соответствующих отчётов. Изменение или удаление
экспорта требует одновременного обновления этого контракта и фасадного теста.
Versioned JSON schemas сохраняют собственные правила совместимости из
[CLI-контракта](cli.md).
