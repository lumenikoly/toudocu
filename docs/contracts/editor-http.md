# Editor HTTP API: поведение и границы

- Идентификатор: CON-EDITOR-HTTP-V1
- Статус: Готово
- Владелец: Команда Toudocu
- Последнее обновление: 2026-08-08

[OpenAPI 3.1.0](editor.openapi.yaml) содержит маршруты, параметры, коды ответа
и схемы данных. В canonical `serve` на этой странице также появляется кнопка
для открытия спецификации в Swagger UI.

Здесь описаны гарантии canonical portal services, которые не выражаются одной
HTTP-схемой: граница workspace, защита записи, поведение пересборки и проверка
доступности новой версии Toudocu.

## Доступность

Editor API существует только в canonical `toudocu serve`. Его нет в
статической сборке, locale-разделах и при прямом `serve` translation root.
Go включает editor UI только при capability `editor` и передаёт same-origin API
base в versioned page bootstrap; frontend не выводит endpoint из URL страницы.

Редактор видит только разрешённые `.md`, `.yaml`, `.yml` и `.json` внутри
documentation root. OpenAPI-файлы проверяются тем же валидатором, что и при
`toudocu check`.

## Проверка версии

Canonical `serve` по умолчанию публикует read-only endpoint
`/_toudocu/api/version`. При первом запросе процесс один раз обращается к
фиксированному GitHub Releases API проекта, принимает только stable release с
точной версией `X.Y.Z`, ограничивает время ожидания тремя секундами и тело
ответа 64 KiB, запрещает redirects, затем кеширует результат до завершения
процесса. Произвольный внешний адрес из ответа не используется: ссылка
строится сервером для официальной страницы релиза.

Browser обращается только к same-origin endpoint. При более новой версии он
показывает неблокирующее предложение открыть релиз; скрытие запоминается для
конкретной версии. Ошибка сети, неверный ответ или development version дают
`status: unavailable` и не мешают чтению портала. `--no-update-check`
отключает capability и endpoint. Static build, locale mount и direct
translation serve не содержат проверки версии и не создают внешних запросов.

## Запись файла

Сохранение использует SHA-256 digest для защиты от перезаписи внешних изменений.
Новый файл записывается во временный файл в том же каталоге, наследует mode и
атомарно заменяет исходник. При конфликте редактор сохраняет локальный текст и
требует отдельного подтверждения с актуальным digest.

Создание документа использует тот же реестр шаблонов, что и CLI, и не
перезаписывает существующий файл. Диагностика предупреждает пользователя, но
сама по себе не запрещает сохранение.

## Добавление результата roadmap

Операция чтения состояния roadmap возвращает актуальные digest, revision,
существующие H2-этапы и следующий предложенный `DLV-ROADMAP-NNN`. Операция
добавления принимает только новый незавершённый `DLV-*` для существующего
этапа: ID приводится к uppercase, должен быть уникальным, а формулировка —
непустой однострочной строкой без второго roadmap ID. Маршруты, HTTP-методы,
статусы и JSON-схемы определяет OpenAPI.

Запись использует тот же workspace path guard, digest CAS и atomic replace, что
и обычное сохранение. Элемент вставляется после последнего checklist item этапа,
а при его отсутствии — перед следующим H2; исходный перевод строк и остальной
Markdown не нормализуются. При `stale_digest` автоматического overwrite нет:
ответ содержит свежие этапы, digest и подсказку ID, чтобы browser сохранил поля
формы и предложил повторить действие осознанно.

## Граница доверия

Записывающий запрос должен иметь JSON content type, правильный action header и
same-origin browser context. Это защищает локальный браузерный сценарий, но не
является аутентификацией: сервер, явно открытый на `0.0.0.0`, доступен другим
клиентам доверенной локальной сети.

Для generic Editor допустим только относительный POSIX-путь внутри canonical documentation root.
Пустые и абсолютные пути, `.`, `..`, обратная косая черта, NUL, hidden,
excluded и output paths, а также любой symlink-компонент отклоняются. Editor API
не запускает Git, shell или команды проверки задач.

## Пересборка

После успешного сохранения, создания или добавления roadmap item сервер синхронно перестраивает модель,
HTML, поиск и диагностику. Ошибка пересборки возвращается текущему запросу, но
не останавливает listener. Ручная пересборка использует тот же OpenAPI-контракт,
читает canonical sources и не изменяет Markdown.
