# Changes HTTP API: поведение и границы

- Идентификатор: CON-CHANGES-HTTP-V1
- Статус: Готово
- Владелец: Команда Toudocu
- Последнее обновление: 2026-08-10

[OpenAPI 3.1.0](changes.openapi.yaml) задаёт точные маршруты, параметры, коды
ответов и схемы JSON. Здесь описано то, что одной HTTP-схемой не выразить:
источники версий, границы чтения Git и хранение локальных обсуждений.

В основном `serve` спецификацию можно открыть во встроенном Swagger UI.

## Где API доступен

API просмотра изменений существует только при `serve` и сам ничего не
записывает. При прямом запуске каталога перевода он сравнивает этот каталог, но
в переводах, подключённых к основному порталу, отдельного API нет.

Go включает экран только при возможности `changes` и передаёт браузеру
same-origin адрес API в JSON-блоке страницы. Статическая сборка не содержит ни
адреса, ни клиентского кода.

API обсуждений из того же OpenAPI доступен только в основном `serve`. Любой
обычный диапазон Git можно читать, но создавать обсуждения, пакеты для агента и
очищать состояние разрешено только при конечном состоянии `working-tree`.

## Сравнение Git

API читает локальные коммиты, индекс и рабочее дерево. Он не выполняет `fetch`
или `checkout` и не меняет Git. Параметр `branchBase` вычисляет общую базу
выбранной ветки с `HEAD`; если вместе с ним указан `base`, обе ссылки должны
разрешаться локально.

ETag зависит от отфильтрованного результата, выбранного диапазона, текущей
версии документации, `HEAD`, статуса Git и разрешённых ссылок. Поэтому изменение
индекса или рабочего дерева не возвращает прежний отчёт.

Сводка не содержит полный патч. Детали, полное содержимое и отрисованный
Markdown строятся только после выбора конкретного файла.

## Безопасное чтение файла

Обычный Changes API принимает только относительный POSIX-путь внутри
разрешённого каталога документации. Абсолютный путь, `..`, обратная косая
черта, `.git`, выход через символическую ссылку и любой путь за границей
отклоняются.

Сервер сам задаёт тип ответа, добавляет `X-Content-Type-Options: nosniff` и
строгую политику содержимого. Markdown превращается в HTML только безопасным
движком. SVG не получает права выполнять скрипты, загружать внешние ресурсы или
применять встроенные стили.

Ошибка семантики, Mermaid, OpenAPI, карты или ресурса остаётся сообщением этого
представления и не скрывает точный патч Git.

## Обсуждения всего репозитория

`/_toudocu/api/changes/review/` отдельно перечисляет отслеживаемые и новые
неигнорируемые файлы всего репозитория. Он использует тот же режим Git только
для чтения, но не меняет публичный `ChangeSetReport`, обычную команду `changes`
и Go API.

Полное старое и текущее содержимое и патч загружаются только при обращении.
Go проверяет путь, обычный тип файла, UTF-8, отсутствие NUL, двоичный формат и
предел 2 МиБ. Для документов дополнительно строятся знакомые представления.

Состояние обсуждений хранится вне репозитория. Каждая запись требует JSON,
точного `X-Toudocu-Action`, same-origin контекста браузера, ожидаемой версии и
хеша состояния. Запись берёт межпроцессную блокировку и сверяет значения перед
атомарной заменой.

Основные ответы об ошибках:

- `409` — состояние изменилось;
- `REVIEW_STATE_BUSY` — хранилище занято другим процессом;
- `413` — сообщение или файл слишком велики;
- `415` — двоичный файл;
- `403` — небезопасный путь или символическая ссылка;
- `404` — неизвестный ID;
- `503` — Git недоступен;
- `500` — повреждённое хранилище, которое Toudocu не перезаписывает сам.

ETag обсуждений соединяет сохранённый хеш с текущей версией репозитория. Поэтому
перенос привязок пересчитывается и после изменения Git, даже если сами
обсуждения не менялись.

Кнопка «Отправить агенту» включает все новые сообщения открытых обсуждений в
один пакет. CLI выдаёт пакеты по очереди и повторяет самый старый, пока не
получит полный корректный ответ. Ответ содержит ровно один результат на каждое
сообщение и безопасные относительные `changedPaths`. Результат `fixed` не меняет
состояние обсуждения.

Точные пределы, поля, примеры и HTTP-статусы находятся в
[OpenAPI](changes.openapi.yaml).
