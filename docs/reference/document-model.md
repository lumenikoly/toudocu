# Модель документов и связей

Этот справочник объясняет машинный контракт Markdown: как путь определяет вид
документа, какие ID и связи распознаются и что именно проверяет CLI. Он не
заменяет смысловую вычитку.

Если материалу не нужны стабильный ID, проверяемая связь или специальная
страница портала, используйте обычный Markdown. Успешный `check` подтверждает
структуру, а не правдивость и полезность текста.

## Что обещает исходный текст

| Сигнал | Что автор обещает | Что проверяет Toudocu |
|---|---|---|
| Обычный Markdown | Безопасный читаемый документ | Синтаксис, локальные ссылки и базовые редакционные признаки |
| Зарезервированный путь | Документ известного вида | Контракт этого вида |
| Стабильный ID | Устойчивая сущность | Формат, уникальность и разрешённое расположение |
| Поле с ID или локальная ссылка | Явная связь | Существование и допустимый вид цели |
| Галочка в `roadmap.md` | Часть общего охвата | Один поддерживаемый ID и готовность `UC-*` по статусу и критериям приёмки |
| `task ready` | Полный контракт задачи | Поля, разделы, связи и команды |
| `task verify --run` | Разрешение исполнить команды | Локальный контракт задачи до запуска |

Ошибки защищают пути, уникальность, связи и исполняемые контракты.
Предупреждения указывают на редакционную неполноту, неизвестный статус или
возраст. Не придумывайте данные ради исчезновения предупреждения.

## Как путь определяет вид

| Путь | Значение |
|---|---|
| `index.md` | Главная страница; обязательна в каждом каталоге документации |
| `status.md` | Проверенный текущий снимок; галочки задач здесь запрещены |
| `roadmap.md` | Общие результаты и прогресс |
| `risks.md` | Риски `RISK-*` и меры снижения |
| `ideas.md`, `notes.md` | Свободные идеи и заметки без обязательных метаданных |
| `drafts/**/*.md` | Свободные тексты, ещё не принятые в постоянный раздел; тип `draft` без обязательных ID, метаданных, разделов и жизненного цикла |
| `modules/*.md` | Модуль `MOD-*` и правила `BR-*` |
| `use-cases/*.md` | Пользовательский сценарий `UC-*` |
| `flows/*.md` | Процесс `FLOW-*` с Mermaid |
| `screens/SC-*.md` | Экран `SC-*`, состояния и переходы `TR-*` |
| `screens/index.md` | Входная страница раздела, не сущность `SC-*` |
| `screens/hotspots.json` | Кликабельные области существующих экранов и переходов |
| `decisions/*.md` | Решение `ADR-*` |
| `quality/STD-*.md` | Стандарт `STD-*` |
| `quality/index.md` | Входная страница стандартов |
| `runbooks/RB-*.md` | Эксплуатационная процедура `RB-*` |
| `runbooks/index.md` | Входная страница runbook |
| `work/TASK-*.md`, `work/BUG-*.md`, `work/archive/YYYY/*.md` | Активная или архивная задача |
| `architecture/overview.md` | Обязательная граница системы и карта вопросов |
| Другой `architecture/**/*.md` | Ответ на один архитектурный вопрос |
| `contracts/**/*.openapi.{yaml,yml,json}` | Проверяемый OpenAPI 3.0/3.1 |
| Другой Markdown в `contracts/`, `guides/`, `reference/` | Контракт, руководство или справочник без обязательного ID |
| Корневой `CHANGELOG.md` | Единственный специальный журнал релизов проекта |
| Другой путь | Обычный Markdown |

Неизвестный верхнеуровневый раздел объявляется своим `index.md` с
`Тип: Custom`, описанием и полезным H1. Это добавляет раздел в
навигацию, но не новую встроенную семантику.

Смысловые границы описаны в [справочнике видов](document-types.md).

## Стабильные ID

ID не зависит от заголовка или имени файла. Обычное переименование сохраняет
ID; реальная смена идентичности требует одновременно обновить все ссылки.

| Сущность | Формат | Где уникальна |
|---|---|---|
| Модуль | `MOD-*` | Вся документация |
| Правило | `BR-*` | Вся документация |
| Сценарий | `UC-*` | Вся документация |
| Процесс | `FLOW-*` | Вся документация |
| Экран | `SC-<AREA>-<NAME>` | Вся документация |
| Переход | `TR-<AREA>-<NUMBER>` | Вся документация |
| Решение | `ADR-*` | Вся документация |
| Стандарт | `STD-*` | Вся документация |
| Runbook | `RB-*` | Вся документация |
| Задача | `TASK-<AREA>-<NUMBER>` | Активный каталог и архив вместе |
| Дефект | `BUG-<AREA>-<NUMBER>` | Активный каталог и архив вместе |
| Критерий | `AC-*` | Один рабочий файл |

Относительная ссылка Markdown должна разрешаться внутри корня репозитория. Она
остаётся явной связью, даже если не входит в типизированную модель.

## Основные направления связей

Связь направлена от документа, который объявляет поле или ссылку, к документу
с целевой сущностью. Точные правила перечислены в таблице.

## Матрица связей

«Обратная связь» означает, что Toudocu сам добавит обратное представление; второе
поле в Markdown не нужно.

| Источник | Поле | Цель | Правило | Обратная связь |
|---|---|---|---|---|
| `UC-*` | `Модуль` / `Module` | `MOD-*` | Ровно один | Модуль показывает сценарий |
| `UC-*` | `Начальный экран` / `Start screen` | `SC-*` | Не более одного | Экран входит в граф сценария |
| `UC-*` | `Конечные экраны` / `Terminal screens` | `SC-*` | Список | Экраны входят в граф сценария |
| `UC-*` | `Экраны` / `Screens` | `SC-*` | Необязательный список | Экраны входят в сценарий |
| `FLOW-*` | `Сценарий` / `Scenario` | `UC-*` | Один или несколько для продуктового процесса | Сценарий показывает процесс |
| Архитектурный `FLOW-*` | Прямая Markdown-ссылка | Документ архитектуры | Нужна, если нет `Сценарий` | Обычная обратная ссылка |
| `FLOW-*` | `Модуль` / `Module` | `MOD-*` | Необязательно | Только атрибут и фильтр |
| `SC-*` | `Модуль` / `Module` | `MOD-*` | Ровно один | Экран доступен модулю и сценариям |
| `SC-*` | `Родительский экран` / `Parent screen` | `SC-*` | Не более одного | Создаётся дочерняя связь |
| Строка `TR-*` | `Сценарий` / `Use case` | `UC-*` | Ровно один | Переход входит в граф сценария |
| Строка `TR-*` | `Результат` / `Result` | `SC-*` | Ровно один | Целевой экран получает входящий переход |
| Обычный `TASK-*` | `Модуль` / `Module` | `MOD-*` | Обязателен не для черновика | Входит в контекст задачи |
| `BUG-*` | `Модуль` / `Module` | `MOD-*` | Обязателен всегда | Входит в контекст задачи |
| `Feature` | `Сценарий` / `Use case` | `UC-*` | Обязателен не для черновика | Входит в контекст задачи |
| `BUG-*` | `Сценарий` / `Use case` | `UC-*` | Обязателен либо `Не применяется` с объяснением | Входит в контекст задачи |
| Рабочая задача | `Процесс` / `Flow` | `FLOW-*` | Не более одного | Входит в контекст задачи |
| Рабочая задача | `Экраны` / `Screens` | `SC-*` | Список | Входят в контекст задачи |
| Рабочая задача | `Переходы` / `Transitions` | `TR-*` | Список | Входят в контекст и трассировку |
| Рабочая задача | `Стандарты` / `Standards` | `STD-*` | Список | Становятся обязательным чтением |
| Рабочая задача | `Затронутые runbooks` / `Affected runbooks` | `RB-*` | Список | Становятся обязательным чтением |
| `TASK-*` | `Родительская задача` / `Parent` | `TASK-*` | Не более одного, без циклов | Родитель получает вычисленные `childIds` |
| Рабочая задача | `Зависит от` / `Depends on` | `TASK-*`, `BUG-*` | Список без циклов | Участвуют в графе задач |
| `roadmap.md` | ID в пункте с галочкой | `UC-*`, `CON-*`, `CONTRACT-*`, `DLV-*`, `DELIVERABLE-*` | Ровно один ID | Для `UC-*` готовность вычисляется из сценария |
| Architecture Overview | Прямая ссылка | Каждый другой файл архитектуры | Не менее одной на файл | Документ считается перечисленным |
| Заменённый `STD-*` | `Заменён` / `Superseded by` | `STD-*` | Ровно один другой стандарт | Строится цепочка замены |

Обычная Markdown-ссылка не заменяет обязательное поле, если контракт требует
именно метаданные.

Например, сценарий объявляет связь с модулем в метаданных:

```markdown
# UC-AUTH-01: Войти в систему

- Идентификатор: UC-AUTH-01
- Статус: Запланировано
- Модуль: MOD-AUTH
```

Процесс, который визуализирует этот сценарий, ссылается на него отдельно:

```markdown
# FLOW-AUTH-01: Вход в систему

- Идентификатор: FLOW-AUTH-01
- Сценарий: UC-AUTH-01
```

После проверки Toudocu покажет обратную связь `UC-AUTH-01 → FLOW-AUTH-01` без
дублирующего поля в документе сценария.

## Что вычисляется автоматически

- `FLOW → UC` создаёт обратную связь `UC → FLOW`.
- Строки `TR-*` дают входящие и исходящие переходы, граф и пошаговый режим
  выбранного `UC-*`.
- `Родительский экран` строит иерархию карты.
- `Parent` строит дерево `TASK-*`; `childIds` вычисляется обратным индексом и
  никогда не читается из Markdown.
- `UC-*` в дорожной карте завершён только при статусе группы `done`, хотя бы
  одной галочке в разделе «Критерии приёмки» и всех отмеченных галочках внутри
  него. Вложенные подразделы входят в расчёт, а следующий заголовок того же или
  более высокого уровня завершает раздел. `CON-*`, `CONTRACT-*`, `DLV-*` и
  `DELIVERABLE-*` сохраняют собственную галочку.
- Несовпадение вычисленной готовности `UC-*` с галочкой дорожной карты даёт
  `roadmap-item-completion-mismatch`; завершённый этап с незавершённым пунктом
  даёт `roadmap-section-status-mismatch`.
- Завершённый сценарий без критериев получает
  `done-use-case-missing-acceptance-criteria`, а с открытой галочкой —
  `done-use-case-has-open-acceptance-criteria`.
- Ссылки, ID и поля задачи создают обратные ссылки, контекст и трассировку.
- Mermaid остаётся изображением: его узлы и стрелки связями модели не являются.

HTML, `report.json`, поисковый индекс и карта — производные файлы. Их не
редактируют как источник.

## Ограничения графов

### Архитектура

`architecture/overview.md` напрямую ссылается на каждый другой Markdown-файл
под `architecture/`, включая вложенные каталоги. Каждый такой файл задаёт один
непустой архитектурный вопрос. Ссылка через соседний документ не заменяет
прямую запись в обзоре.

### Экраны

Экран ссылается только на существующие `MOD-*`, `UC-*` и `SC-*`. Внешняя
навигация ведёт на `SC-*` типа «Внешняя страница» с HTTP(S)-маршрутом.
Маршруты регистрозависимы и уникальны. Каждый `TR-*` имеет один `UC-*`, действие
и цель. Переход в тот же экран объясняется новым состоянием, ошибкой или
сообщением.

Сценарий с экранной моделью задаёт начало и конечные экраны. Проверка находит
недостижимые экраны, тупики, циклы без выхода и ошибочные ветки без продолжения.
Формат описан в [руководстве по экранам](../guides/screens.md).

### Задачи

`Parent` означает декомпозицию, а `Dependencies` — порядок завершения. Оба
отношения независимы. Родитель и зависимости должны существовать; иерархия и
объединённый граф завершения не содержат циклов. Активные и архивные файлы
используют общую область ID.

`WorkItem.parentId` равен ID родителя либо `null`; `childIds` всегда является
вычисленным массивом. Завершённая родительская задача имеет только завершённых
непосредственных детей. Отменённая родительская задача не имеет активных детей.

Каждый `AC-*` имеет одну строку команды. Для готовой задачи нужны все `AC-*`,
`ALL`, `DOCS` и, при явно связанных стандартах, `QUALITY`. Трассировка
`AC → TR → verification` дополняет, но не заменяет исполняемую команду.

`Feature` после черновика ссылается на `UC-*`. `Maintenance`, `Documentation`
и `Research` без сценария объясняют его неприменимость. `BUG-*` всегда объявляет
модуль и сценарий либо явное `Не применяется` с описанием связи с поведением.
Полный контракт — в [руководстве по задачам](../guides/work-items.md).

## Что связью не является

- Упоминание ID в обычном тексте или блоке кода без известного поля.
- Имя файла, похожее на ID, когда требуется явный идентификатор.
- Стрелка Mermaid.
- Совпадение пути задачи с областью стандарта.
- Зависимость, угаданная по коду или каталогам.
- Обратная ссылка из портала, скопированная обратно в исходный файл.

Значимые отношения объявляются явно. Toudocu не угадывает применимость
стандарта по glob-шаблону.

## Markdown и пути

Поддерживаются CommonMark, безопасные растровые изображения, таблицы, списки с
галочками, зачёркивание, автоматические ссылки, код в строке и блоки кода.

Не поддерживаются сырой HTML, front matter в начале файла между одинаковыми
строками `---` или `+++`, Markdown-атрибуты, сноски, списки определений,
активные SVG/XML/HTML-ресурсы и JavaScript URL. Ссылки не выходят за корень
репозитория. Текст внутри блока кода не разбирается как заголовок, поле или
связь.

## Рекомендуемый порядок

Создайте цель раньше ссылки: сначала модуль и правила, затем сценарий, после
него процесс или экраны, затем дорожную карту или задачу. После изменения ID
или связей обычный проектный цикл включает:

```bash
toudocu check ./docs --repository-root .
```

Эта команда подтверждает структуру. Полезность, полнота и правильность связей
проверяются человеком.
