# Виды документов Toudocu

Сначала сформулируйте вопрос читателя, затем выберите документ. Toudocu
классифицирует известные виды по пути. Стабильный ID нужен только сущностям,
которые должны участвовать в машинных связях.

Точные ID и направления связей находятся в
[модели документов](document-model.md).

## Быстрый выбор

| Вопрос | Документ |
|---|---|
| С чего начать чтение проекта? | `index.md` |
| В каком состоянии проект сейчас? | `status.md` |
| Какие общие результаты запланированы? | `roadmap.md` |
| Какой результат получает пользователь? | Сценарий `UC-*` |
| Как проходит значимое взаимодействие? | Процесс `FLOW-*` |
| Как пользователь переходит между экранами? | Экран `SC-*` и переходы `TR-*` |
| Где граница компонента и какие правила он защищает? | Модуль `MOD-*` |
| Как устроена система и почему части связаны так? | Архитектура |
| Почему принято долговечное решение? | `ADR-*` |
| Как выглядит внешний интерфейс или формат? | Контракт |
| Где быстро найти точные факты и варианты? | Справочник |
| Как выполнить практическую задачу? | Руководство |
| Какое правило обязательно? | Стандарт `STD-*` |
| Как безопасно выполнить эксплуатационную процедуру? | Runbook `RB-*` |
| Что разрешено изменить и как принять работу? | `TASK-*` или `BUG-*` |
| Где сохранить ещё не принятую возможность? | `ideas.md` |
| Где сохранить полезное временное наблюдение? | `notes.md` |

## Обзор и текущее состояние

| Вид | Зачем нужен | Не использовать для |
|---|---|---|
| `index.md` | Название, краткое описание и основные точки входа. Обязателен | Подробных контрактов и истории решений |
| `status.md` | Проверенный снимок текущего этапа, версии и фокуса | Желаемого будущего и списка работ |
| `roadmap.md` | Общие результаты `UC-*`, `CON-*`/`CONTRACT-*`, `DLV-*`/`DELIVERABLE-*` и вычисляемый прогресс | Плана одной задачи и неподтверждённых идей |
| `risks.md` | Риски `RISK-*`, вероятность, влияние и меры | Дефектов и плана реализации |
| `ideas.md` | Возможности и гипотезы без обещания реализации | Текущего статуса и утверждённых требований |
| `notes.md` | Полезный временный контекст | Нормативных правил и решений |
| `drafts/**/*.md` | Свободный черновик, который ещё не принят в постоянный раздел | Обязательного ID, метаданных, разделов и жизненного цикла |
| Корневой `CHANGELOG.md` | История опубликованных версий | Текущего статуса и дублирующего `docs/changelog.md` |

`status.md` не принимает галочки задач. Общий процент берётся только из
`roadmap.md`; `UC-*` считается завершённым при статусе группы `done`, наличии
хотя бы одной галочки в критериях приёмки и всех отмеченных галочках раздела.

## Продукт и архитектура

| Вид и путь | Зачем нужен | Не использовать для |
|---|---|---|
| Architecture Overview — `architecture/overview.md` | Граница системы и прямая карта всех архитектурных вопросов. Обязателен | Полного описания каждого взаимодействия |
| Архитектура — остальные `architecture/**/*.md` | Короткий ответ на один вопрос об устройстве, границах или зависимостях нескольких частей | API-формата, процедуры, решения или локального правила модуля |
| Модуль — `modules/*.md`, `MOD-*` | Устойчивая ответственность, правила `BR-*` и инварианты | Зеркала каталога кода и списка функций |
| Сценарий — `use-cases/*.md`, `UC-*` | Наблюдаемый путь актора, результат и проверяемые критерии приёмки | Графа вызовов и эксплуатационной процедуры |
| Процесс — `flows/*.md`, `FLOW-*` | Mermaid-схема значимого ветвления или взаимодействия | Всеобъемлющей схемы кода и замены требований |
| Экран — `screens/SC-*.md`, `SC-*`, `TR-*` | Экран, состояния и пользовательские переходы | Внутреннего состояния компонента без пользовательского значения |
| Решение — `decisions/*.md`, `ADR-*` | Контекст, принятое решение и последствия | Оправдания кода задним числом и описания текущего устройства |

Специальный путь сам по себе не делает документ полезным. Не создавайте сущность
ради лишней страницы портала или исчезновения предупреждения.

## Правила, процедуры и объяснения

| Вид и путь | Зачем нужен | Не использовать для |
|---|---|---|
| Контракт — `contracts/` | Точный внешний интерфейс, команда, API, схема или формат | Обучающей последовательности и архитектурного объяснения |
| Стандарт — `quality/STD-*.md` | Обязательные правила с областью и способом проверки | Необязательных советов и разовой процедуры |
| Runbook — `runbooks/RB-*.md` | Реальная эксплуатационная процедура с проверкой и откатом | Общего руководства и вымышленной процедуры |
| Руководство — `guides/` | Шаги к практическому результату | Каталога фактов и нормативного формата |
| Справочник — `reference/` | Точные факты, параметры и варианты для быстрого поиска | Пошагового обучения и обоснования решения |

Требования к стандартам, runbook и собственным разделам описаны в
[отдельном руководстве](../guides/quality-runbooks.md).

## Рабочие и свободные документы

| Вид | Когда нужен | Не использовать для |
|---|---|---|
| `work/TASK-*.md` | Существенная работа с границами, критериями, командами и передачей между исполнителями | Любого небольшого запроса и описания уже существующей функции |
| `work/BUG-*.md` | Подтверждённое расхождение ожидаемого и фактического поведения | Идеи и неподтверждённого предположения об ошибке |
| `drafts/**/*.md` | Свободный текст, который нужно показать в портале и поиске до принятия | Отдельного workflow и автоматического переноса в постоянный раздел |
| Собственный раздел | Устойчивая предметная область, которую не выражает встроенный раздел | Маскировки уже существующего вида |
| Обычный Markdown | Полезный текст и ссылки без машинного контракта | Связей, которые Toudocu должен проверять |

Активные задачи находятся в `work/`, завершённые и отменённые можно переместить
командой в `work/archive/YYYY/`. Полный формат — в
[руководстве по задачам](../guides/work-items.md).

### Вид документа и поле `Тип` задачи

Любой `TASK-*` или `BUG-*` остаётся документом «Рабочая задача». Внутреннее
поле `Тип` говорит о характере работы:

| `Тип` | Значение |
|---|---|
| `Feature` | Новое или изменённое пользовательское поведение |
| `Bug` | Исправление подтверждённого дефекта; требует `BUG-*` и данных воспроизведения |
| `Maintenance` | Техническое обслуживание без обязательного нового поведения |
| `Documentation` | Документация как основной результат |
| `Research` | Исследование с проверяемым результатом без обещания реализации |

После черновика `Feature` связывается с `UC-*`. Технические типы без сценария
объясняют, почему он не применим. Баг связывается со сценарием либо явно
объясняет связь технического дефекта с пользовательским поведением.

## Вспомогательные файлы

- `screens/hotspots.json` добавляет кликабельные области к существующим экранам
  и переходам; это не Markdown-документ.
- `screens/index.md`, `quality/index.md`, `runbooks/index.md` — входные страницы
  разделов, а не сущности `SC-*`, `STD-*` или `RB-*`.
- `screens/map.md` устарел: карта строится из `screens/SC-*.md`.
- HTML, `report.json` и поисковый индекс — производные файлы; их не редактируют
  как источник.

## Главное правило

Если не нужны стабильный ID, проверяемая связь или специальное представление,
оставьте материал обычным Markdown. Структурная проверка подтверждает только
обещанный формат и не делает ненужный документ полезным.
