# Виды документов Docu-docu

Справочник помогает выбрать документ по его назначению. Docu-docu классифицирует
документ по расположению файла. Смысловой выбор начинается с вопроса, на который
должен ответить источник; стабильный ID требуется только отдельным видам
машиночитаемых сущностей.

## Быстрый выбор

| Нужно зафиксировать | Используйте |
|---|---|
| С чего начать чтение проекта | [Обзор проекта](#обзор-и-состояние-проекта) |
| Что происходит в проекте сейчас | [Текущее состояние](#обзор-и-состояние-проекта) |
| Какие глобальные результаты запланированы | [Roadmap](#обзор-и-состояние-проекта) |
| Какую ценность или результат получает актор | [Пользовательский сценарий](#продукт-и-архитектура) |
| Как проходит один значимый сценарий или взаимодействие | [Процесс](#продукт-и-архитектура) |
| Как пользователь перемещается между значимыми экранами | [Экран](#продукт-и-архитектура) |
| Где проходит граница компонента и какие правила он защищает | [Модуль](#продукт-и-архитектура) |
| Как устроена система и почему её части связаны именно так | [Архитектура](#продукт-и-архитектура) |
| Почему принято долговечное техническое решение | [ADR](#продукт-и-архитектура) |
| Как выглядит интерфейс, формат или протокол | [Контракт](#правила-процедуры-и-пояснения) |
| Какие факты и варианты нужно быстро найти | [Справочник](#правила-процедуры-и-пояснения) |
| Как достичь практического результата | [Руководство](#правила-процедуры-и-пояснения) |

## Обзор и состояние проекта

| Вид и расположение | Зачем нужен | Когда создавать | Не использовать для |
|---|---|---|---|
| **Обзор проекта** — `index.md` | Даёт название, краткое описание и основные точки входа | Всегда: это главная страница документации | Детального контракта, истории решений или полного roadmap |
| **Текущее состояние** — `status.md` | Показывает проверенный снимок проекта сейчас: этап, версию, активный фокус | Когда читателю нужен единый актуальный статус | Желаемого будущего, чек-листа работ или истории релизов |
| **Roadmap** — `roadmap.md` | Объявляет глобальные результаты и вычисляемый прогресс | Когда проект управляет общим продуктовым охватом через `UC-*`, `CON-*` и `DLV-*` | Локального плана одной задачи или неподтверждённых идей |
| **Риски** — `risks.md` | Собирает `RISK-*`, вероятность, влияние и меры снижения | Когда рисками нужно управлять явно | Списка дефектов или плана реализации |
| **Идеи** — `ideas.md` | Хранит возможные направления без обещания реализации | Для ещё не принятой возможности или гипотезы | Roadmap, текущего статуса или утверждённого требования |
| **Заметки** — `notes.md` | Сохраняет наблюдения и временный контекст | Когда информация полезна, но ещё не стала устойчивым знанием | Нормативных правил, контрактов и архитектурных решений |
| **Журнал изменений** — корневой `CHANGELOG.md` | Описывает изменения опубликованных версий | Если проект ведёт release history | Текущего статуса или дублирующего `docs/changelog.md` |

`status.md` не принимает task-чек-листы. Глобальный процент готовности берётся
только из `roadmap.md`; состояние связанного `UC-*` определяется самим use case.

## Продукт и архитектура

| Вид и расположение | Зачем нужен | Когда создавать | Не использовать для |
|---|---|---|---|
| **Architecture Overview** — `architecture/overview.md` | Определяет границу системы и служит картой архитектурных вопросов | Всегда; overview напрямую ссылается на каждый подробный документ архитектуры | Полного описания всех взаимодействий, контрактов и локальных правил |
| **Архитектура** — другие `architecture/**/*.md` | Кратко отвечает на один доказуемый архитектурный вопрос | Когда ответ затрагивает устройство системы, границы или зависимости нескольких частей | Последовательности запроса, API-формата, процедуры, ADR или правил одного модуля |
| **Модуль** — `modules/*.md`, ID `MOD-*` | Фиксирует стабильную границу ответственности, бизнес-правила и инварианты | Когда такая граница важна продукту, владельцам или связанным сценариям | Зеркала каталога исходного кода или перечня внутренних функций |
| **Пользовательский сценарий** — `use-cases/*.md`, ID `UC-*` | Описывает наблюдаемое поведение актора и ожидаемый результат | Когда поведение должно быть связано с модулем, правилами, экранами или roadmap | Реализационного call graph и пошаговой эксплуатационной инструкции |
| **Процесс** — `flows/*.md`, ID `FLOW-*` | Визуализирует один повторно используемый сценарий, ветку ошибки или межсистемное взаимодействие | Когда Mermaid-схема действительно упрощает понимание use case или архитектуры | Всеобъемлющей схемы кода или замены текстовых требований |
| **Экран** — `screens/SC-*.md`, ID `SC-*` и `TR-*` | Описывает значимый экран, его состояния и исходящие пользовательские переходы | Когда продукту нужны каталог экранов, Screen Map или traceability | Технического route, layout, redirect либо внутреннего состояния компонента |
| **Архитектурное решение** — `decisions/*.md`, ID `ADR-*` | Сохраняет контекст, принятое решение и его последствия | Когда решение и рассмотренный компромисс действительно были зафиксированы | Ретроспективного оправдания текущего кода или описания устройства системы |

Специальный путь определяет `Document.Type`, но сам по себе не обещает наличие
entity ID. Уникальность ID и явные связи дополнительно проверяются у `MOD-*`,
`UC-*`, `FLOW-*`, `SC-*`/`TR-*`, `ADR-*` и других видов, для которых они явно
заданы. `status.md`, `roadmap.md`, `risks.md` и архитектурные документы имеют
специальное поведение без собственного уникального entity ID. Ни один из этих
видов не следует создавать только ради дополнительной страницы портала или
отсутствия предупреждений.

## Правила, процедуры и пояснения

| Вид и расположение | Зачем нужен | Когда создавать | Не использовать для |
|---|---|---|---|
| **Контракт** — `contracts/` | Фиксирует внешний интерфейс, команду, API, schema или формат обмена | Когда потребителю нужна точная и стабильная граница взаимодействия | Обучающей последовательности, архитектурного объяснения или списка фактов |
| **Стандарт** — `quality/STD-*.md`, ID `STD-*` | Задаёт обязательные и проверяемые правила проекта | Когда правило имеет область действия, владельца и способ проверки | Советов без обязательной силы или разовой процедуры |
| **Runbook** — `runbooks/RB-*.md`, ID `RB-*` | Даёт безопасную эксплуатационную процедуру с проверкой и откатом | Только для реально выполняемой операции с известными средой и риском | Общего руководства, продуктового flow или вымышленной процедуры |
| **Руководство** — `guides/` | Помогает читателю достичь конкретного результата | Для установки, настройки или выполнения последовательности действий | Энциклопедического каталога фактов и нормативного контракта |
| **Справочник** — `reference/` | Собирает факты, варианты и параметры для быстрого поиска | Когда читатель уже понимает задачу и ищет точное значение или выбор | Пошагового обучения, обоснования решения или текущего статуса |

Подробные требования к `STD-*`, `RB-*` и custom-разделам находятся в
[руководстве по стандартам и runbooks](../guides/quality-runbooks.md). Форматы
CLI и HTTP остаются в [контрактах](../contracts/cli.md), а не дублируются здесь.

## Рабочие и свободные документы

| Вид и расположение | Зачем нужен | Когда создавать | Не использовать для |
|---|---|---|---|
| **Рабочая задача** — `work/TASK-*.md` | Определяет разрешённый объём работы, результат, критерии приёмки и проверку | Для существенной работы, которой нужен проверяемый контракт и handoff агенту или CI | Любого небольшого запроса, общего roadmap или описания уже существующей функции |
| **Дефект** — `work/BUG-*.md` | Фиксирует наблюдаемое расхождение и данные для его воспроизведения; по мере готовности добавляет причину и регрессионную проверку | Когда поведение действительно не совпадает с ожидаемым | Идеи, исследовательской задачи или неподтверждённого предположения об ошибке |
| **Custom-раздел** — неизвестный верхнеуровневый каталог | Даёт проекту собственную группу документов без новой встроенной семантики | Когда ни один встроенный раздел не выражает устойчивую предметную область | Маскировки уже существующего встроенного типа |
| **Обычный Markdown** — любой другой безопасный путь | Передаёт полезное знание без typed-контракта | Когда достаточно текста, ссылок и базовой проверки | Объявления машинных связей, которые Docu-docu должен валидировать |

Активные work items находятся в `work/`, а завершённые и отменённые могут быть
перемещены командой Docu-docu в `work/archive/YYYY/`. Полный контракт описан в
[руководстве по рабочим задачам](../guides/work-items.md).

### Тип документа и тип задачи — не одно и то же

Любой `TASK-*` или `BUG-*` является документом вида **Рабочая задача**. Поле
`Тип` внутри него дополнительно определяет характер работы:

| Значение `Тип` | Значение |
|---|---|
| `Feature` | Новое или изменённое пользовательское поведение |
| `Bug` | Исправление наблюдаемого дефекта; использует ID `BUG-*` и обязательные данные воспроизведения |
| `Maintenance` | Техническое обслуживание без обязательного нового поведения |
| `Documentation` | Изменение документации как основной результат |
| `Research` | Исследование с проверяемым результатом, но без заранее обещанной реализации |

Draft использует сокращённый контракт. Начиная с любого non-Draft статуса
`Feature` связывается с use case; `Maintenance`, `Documentation` и `Research`
без use case объясняют, почему сценарий не применяется. Для non-Draft `Bug`
требуются связанный use case либо явное объяснение `Не применяется`, раздел
причины и регрессионное покрытие; у выполненного бага причина уже должна быть
установлена. Поле `Тип` не превращает work item в модуль, руководство или иной
вид документа.

## Вспомогательные источники и manifests

- `screens/hotspots.json` дополняет существующие `SC-*` и `TR-*`
  интерактивными областями в процентах; это не самостоятельный Markdown-документ.
- `screens/index.md` является входной страницей встроенного раздела экранов и
  получает отдельный machine type `screen-index`; это не `SC-*`-сущность.
- `quality/index.md` и `runbooks/index.md` задают входные страницы своих
  разделов. Manifest неизвестного раздела дополнительно объявляет `Тип: Custom`,
  владельца и описание.
- `screens/map.md` считается устаревшим источником. Каталог, Screen Map и
  playable flows строятся из `screens/SC-*.md`; отдельную карту вручную вести не
  нужно.
- Generated HTML, `report.json` и поисковый индекс являются производными
  результатами. Их не редактируют как источник истины.

## Главное правило выбора

Сначала сформулируйте полезный вопрос читателя, затем выберите вид документа.
Если проекту не нужны стабильный ID, проверяемые связи или специальное
представление, оставьте материал обычным Markdown. Структурная проверка
подтверждает заявленный контракт, но не делает ненужный документ полезным.
