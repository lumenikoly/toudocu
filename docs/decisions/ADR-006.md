# ADR-006: Необязательная проверка stable release в canonical serve

- Идентификатор: ADR-006
- Статус: Принято
- Дата: 2026-08-08
- Автор: Команда Toudocu
- Последнее обновление: 2026-08-08

Canonical `serve` выполняет необязательную безопасно ограниченную проверку
latest stable release и сообщает о новой версии в portal UI без самообновления.

## Контекст

Пользователь локального портала не видит, что установленная версия Toudocu
устарела. При этом static output обязан оставаться автономным, browser не должен
напрямую раскрывать внешнему сервису факт просмотра документации, а CLI не
должен скачивать или заменять собственный бинарник без явной команды.

## Решение

Только canonical `toudocu serve` по первому same-origin запросу browser один
раз за время процесса читает latest stable release из фиксированного GitHub API
проекта. Запрос включён по умолчанию и отключается `--no-update-check`.

Go проверяет ограниченный ответ, сравнивает только версии `X.Y.Z` и возвращает
browser schema-v1 status. При наличии обновления portal показывает
неблокирующее предложение открыть официальную страницу релиза. Он не скачивает
артефакты и не выполняет самообновление. Ошибка проверки не влияет на портал.

Static build, translation portals и остальные команды сети не используют.
Timeout, предел ответа, запрет redirects, отсутствие credentials и построение
release URL из проверенной версии удерживают внешнюю границу узкой.

## Рассмотренные варианты

- Browser напрямую обращается к GitHub — отклонено: сложнее ограничить ответ и
  появляется отдельная внешняя граница для каждого посетителя.
- Проверка при `build` — отклонено: делает воспроизводимую сборку зависимой от
  сети и быстро устаревает.
- Только opt-in — отклонено: основная ценность функции теряется из-за низкой
  обнаруживаемости; явный opt-out сохраняет автономный режим.
- Автоматическая установка — отклонено: требует отдельного согласия, проверки
  артефакта и транзакционного lifecycle.

## Последствия

- canonical `serve` получает один необязательный outbound HTTPS-запрос;
- GitHub metadata становится недоверенным вводом с явными лимитами;
- portal узнаёт только статус и проверенную ссылку, а сбой остаётся невидимым;
- dependency-free поставка и автономность static output сохраняются.
