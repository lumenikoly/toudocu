# ADR-006: Необязательная проверка стабильного релиза в `serve`

Основной портал `serve` может проверить последний стабильный релиз и сообщить о
новой версии. Самообновления нет.

<!-- toudocu:section context -->
## Контекст

Пользователь локального портала иначе не узнаёт, что установленная версия
устарела. При этом статическая сборка должна оставаться автономной, браузер не
должен напрямую сообщать внешнему сервису о просмотре документации, а CLI не
должен скачивать и заменять себя без отдельного согласия.

<!-- toudocu:section decision -->
## Решение

Только основной `toudocu serve` по первому запросу браузера один раз за процесс
читает последний стабильный релиз из фиксированного GitHub API. Проверка
включена по умолчанию и отключается `--no-update-check`.

Go ограничивает время и размер ответа, принимает только версии `X.Y.Z` и
возвращает браузеру статус версии 1. Если версия новее, портал предлагает
открыть официальную страницу релиза. Он не загружает бинарник и ничего не
устанавливает. Любая ошибка остаётся незаметной и не мешает порталу.

Статический портал, переводы и остальные команды сеть для этой функции не
используют. Перенаправления запрещены, учётные данные не передаются, а URL
релиза строится из проверенной версии.

## Рассмотренные варианты

- Прямой запрос браузера к GitHub отклонён: он создаёт внешнюю границу для
  каждого посетителя.
- Проверка во время `build` отклонена: она делает воспроизводимую сборку
  зависимой от сети, а результат быстро устаревает.
- Включение только по флагу отклонено из-за низкой заметности; явное отключение
  сохраняет автономный режим.
- Автоустановка отклонена: для неё нужны отдельное согласие и безопасная замена
  проверенного артефакта.

<!-- toudocu:section consequences -->
## Последствия

- У основного `serve` появляется один необязательный исходящий HTTPS-запрос.
- Ответ GitHub считается недоверенным и проходит строгие ограничения.
- Браузер получает только статус и проверенную ссылку.
- Автономная статическая поставка сохраняется.
