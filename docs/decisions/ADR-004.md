# ADR-004: Гибридный source of truth для HTTP API

- Идентификатор: ADR-004
- Статус: Принято
- Дата: 2026-08-05
- Автор: Команда Toudocu
- Последнее обновление: 2026-08-05

Wire-level контракт HTTP API хранится в OpenAPI 3.1.0, а поведение и trust
boundaries — в Markdown-компаньоне.

## Контекст

Таблицы endpoints и вручную повторённые JSON shapes в Markdown расходятся с
handlers и плохо подходят для автоматической parity-проверки. При этом OpenAPI
не выражает полноценно atomic filesystem behavior, local trust model,
comparison semantics и границы generated/canonical/translation portals.

## Решение

Файлы `contracts/**/*.openapi.{yaml,yml,json}` являются отдельным проверяемым
типом источника. Для Editor и Changes YAML владеет paths, methods, parameters,
headers, statuses, media types, examples и JSON schemas. Декларативные route
registries проверяются двусторонне против operations.

Markdown-компаньоны не повторяют wire shapes и владеют поведением, security,
filesystem и failure-isolation invariants. Внутренние `$ref` проверяются
локально; external references не загружаются. Canonical `serve` отображает
контракты через vendored offline Swagger UI; static build копирует сами specs,
но не UI.

## Последствия

- изменение handler требует согласованного изменения registry, OpenAPI и tests;
- `check` и editor diagnostics одинаково проверяют OpenAPI с line/column;
- `ProjectReport` остаётся schemaVersion 1, а positional issue получает
  additive optional `column`;
- translation roots не становятся источником контрактов обычного workflow;
- Swagger UI не расширяет runtime trust boundary и не добавляет CDN.
