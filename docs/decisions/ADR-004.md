# ADR-004: OpenAPI и Markdown вместе описывают HTTP API

OpenAPI 3.1.0 описывает точный HTTP-формат, а соседний Markdown — поведение,
безопасность и работу с файлами.

<!-- toudocu:section context -->
## Контекст

Таблицы маршрутов и вручную переписанные JSON-схемы быстро расходятся с кодом.
Но OpenAPI плохо выражает атомарную запись файлов, локальную модель доверия,
смысл Git-сравнения и различия основного, статического и переводного порталов.

<!-- toudocu:section decision -->
## Решение

Файлы `contracts/**/*.openapi.{yaml,yml,json}` являются отдельным проверяемым
типом источника. Для Editor и Changes они задают пути, методы, параметры,
заголовки, статусы, типы данных, примеры и JSON-схемы. Объявленные в Go маршруты
сопоставляются с операциями в обе стороны.

Markdown не повторяет эти поля. Он описывает поведение, безопасность, файловые
операции и изоляцию ошибок. Внутренние `$ref` проверяются локально, внешние не
загружаются. Основной `serve` показывает контракты во встроенном Swagger UI;
статический `build` копирует сами файлы, но не интерфейс API.

<!-- toudocu:section consequences -->
## Последствия

- Изменение обработчика требует согласованно обновить реестр маршрутов,
  OpenAPI и связанные проверки.
- `check` и редактор одинаково сообщают строку и, когда она известна, колонку
  ошибки OpenAPI.
- `ProjectReport` остаётся схемой версии 1; поле `column` добавляется только при
  наличии.
- Переводы не становятся источником контрактов основного процесса.
- Swagger UI не требует CDN и не расширяет сетевую границу.
