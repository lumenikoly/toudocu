# ADR-012: Единый TypeScript runtime и React-представление

Toudocu использует Node.js и TypeScript runtime, общие React-страницы и React Router,
сохраняя CLI/JSON и Markdown в Git как стабильные границы.

<!-- toudocu:section context -->
## Контекст

Workspace включает редактор, изменения, обсуждения, задачи, Agent Console
и Project Terminal. Прежняя реализация сочетала Go-generated HTML, собственную
навигацию и React islands. Миграция заменила два presentation lifecycle одним, не
изменив Markdown source of truth и публичные CLI/JSON-контракты.

<!-- toudocu:section decision -->
## Решение

Node.js и TypeScript становятся runtime Toudocu, React — единственным слоем
интерфейса. Первая новая поставка требует Node >= 24. Все пакеты используют
ESM и строгие проверки TypeScript. Внутренние пакеты не объявляются публичным SDK.

Чистый compiler определяет семантику документов. Прикладные сервисы выполняют
операции через адаптеры filesystem, Git и процессов. Отдельные преобразования
создают стабильные CLI JSON DTO и модели представления. React получает
последние и не импортирует core или Node. Границы проверяются автоматически.

Build и serve используют одни React page components и единый реестр маршрутов.
React renderer и браузерные ресурсы собираются при разработке и выпуске самого
Toudocu. Пользовательский build не запускает Vite или другой frontend compiler.
Статический HTML остаётся полноценным способом чтения без JavaScript и Node
на стороне hosting. Serve использует React Router и постоянные providers для
терминала и агента.

CLI остаётся главным интерфейсом автоматизации. Skills не обращаются к private
HTTP API; MCP не вводится. Markdown в Git остаётся источником истины. Миграция
не меняет schemaVersion, семантику задач или публичных CLI-команд.

Решение заменяет [ADR-001](001-dependency-free.md), [ADR-005](ADR-005.md) и
[ADR-008](ADR-008.md). Эталонные fixtures и compatibility-корпус сохраняют
поведенческий контракт после удаления Go runtime.

## Рассмотренные варианты

- Сохранить Go и islands: сохраняет автономную поставку, но оставляет два
  presentation lifecycle для одного workspace.
- Перенести всё на TypeScript и React: выбран единый стек с явными границами
  compiler/application/presentation и сохранением статического портала.
- Строить runtime вокруг standalone Node executable: отложено; такой формат
  можно добавить в distribution без изменения core.

<!-- toudocu:section consequences -->
## Последствия

Единый язык и система типов упрощают совместное изменение frontend и backend.
Общий React renderer устраняет дублирование интерфейса; автоматические границы
импортов не дают общему языку смешать семантику с представлением.

Node становится требованием установки. Native PTY поставляется готовыми
артефактами для Linux/macOS/Windows x64/arm64; пользователь не компилирует
зависимости. Проверка этой поставки является обязательным условием релиза.
Автономный исполняемый файл остаётся стратегической возможностью, а не
свойством первой TypeScript-версии. Npm не становится единственным способом
установки: сохраняются release archives и installers.

Эталонные fixtures остаются после удаления временного Go differential runner.
