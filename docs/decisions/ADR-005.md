# ADR-005: Goldmark как единый Markdown-движок

- Идентификатор: ADR-005
- Статус: Принято
- Дата: 2026-08-06
- Автор: Команда Toudocu
- Последнее обновление: 2026-08-06

Toudocu одним cutover заменяет собственный line/regex parser и renderer на
закреплённый pure-Go Goldmark `v1.8.5`, сохраняя один автономный бинарник и
собственную безопасную документную модель.

## Контекст

Собственный Markdown subset расходился с CommonMark на вложенных и loose
списках, escapes, fence-вариантах и inline-конструкциях. Повторный разбор строк
для таблиц, Mermaid и semantic diff создавал несколько конкурирующих трактовок
одного документа. Нужен один AST-источник структуры без передачи типов
сторонней библиотеки в публичный Go facade или JSON schema v1.

## Решение

Использовать `github.com/yuin/goldmark v1.8.5` с CommonMark 0.31.2-совместимым
ядром и только встроенными расширениями Table, TaskList, Strikethrough и
Linkify. `internal/markdown`
владеет циклом `Parse → Analysis → Render`, source ranges и закрытым Goldmark
AST. Toudocu самостоятельно создаёт heading IDs, нормализованную модель,
разрешает repository URL/assets и рендерит portal hooks.

Raw block/inline HTML и ведущий завершённый front matter являются policy
errors. Preview и rendered diff показывают такой source только как escaped
text. `html.WithUnsafe`, attributes, footnotes, definition lists, typographer и
сторонние расширения не включаются. Mermaid распознаётся только по единственному
case-insensitive info string `mermaid` и сохраняет отдельную строгую политику.

Низкоуровневые `AnalyzeMarkdown`, `RenderMarkdown`,
`RenderMarkdownFragment`, `ParsedMarkdown`, `RenderContext`, `RenderOptions`,
`LinkResolver` и `LinkResolution` удаляются из публичного facade. Публичными
остаются высокоуровневые операции модели, отчётов, портала и task workflow;
JSON schema v1 не меняется.

## Последствия

- CommonMark и разрешённые GFM-конструкции получают один AST-контракт;
- structural consumers больше не ищут headings, tables, tasks и fences
  независимыми line/regex parsers;
- обновление Goldmark требует corpus, security, semantic и cross-build review;
- canonical HTML и whitespace могут измениться без изменения высокоуровневой
  модели;
- зависимость связывается внутрь binary и не создаёт runtime service, сеть,
  CGO либо соседний файл.
