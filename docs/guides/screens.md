# Экраны, переходы и пошаговые сценарии

Toudocu строит карту интерфейса, каталог экранов и пошаговое прохождение из
документов `screens/SC-*.md`. Отдельный `screens/map.md` не нужен.

Общую карту можно включить или отключить:

```bash
toudocu build ./docs --screen-map
toudocu build ./docs --no-screen-map
```

Без общей карты отдельные страницы экранов, сценарии `UC-*`, пошаговое
прохождение и JSON-модель сохраняются. В портале `UC-*` находятся в разделе
«Пользовательские сценарии», `FLOW-*` — в «Процессах», а документы `SC-*` и
общая карта — в «Экранах».

## Как описать экран

```md
# SC-AUTH-LOGIN: Вход

- Идентификатор: SC-AUTH-LOGIN
- Тип: Экран
- Модуль: MOD-AUTH
- Статус: В работе
- Маршрут: `/login`
- Превью: `../assets/screens/login.webp`
- Родительский экран: SC-PUBLIC-HOME

## Состояния

| ID | Название | Превью |
|---|---|---|
| DEFAULT | Исходное | `../assets/screens/login.webp` |
| INVALID-CREDENTIALS | Неверные данные | — |

## Переходы

| ID | Сценарий | Действие | Условие | Результат | Состояние | Ошибка |
|---|---|---|---|---|---|---|
| TR-AUTH-001 | UC-AUTH-01 | Войти | Данные верны | SC-ACCOUNT-HOME | DEFAULT | — |
| TR-AUTH-002 | UC-AUTH-01 | Войти | Данные неверны | SC-AUTH-LOGIN | INVALID-CREDENTIALS | INVALID_CREDENTIALS |
```

Обязательны ID, тип, модуль и статус. Поддерживаемые типы: `Экран`, `Страница`,
`Модальное окно`, `Панель`, `Внешняя страница` и `Системное состояние`.
Состояние `DEFAULT` существует даже без явной строки.

`Родительский экран` строит иерархию разделов интерфейса; он не задаёт порядок
прохождения сценария.

## Как описать переход

У каждого `TR-*` есть действие, условие, целевой экран и ровно один существующий
`UC-*`. Глобальные переходы без сценария не поддерживаются. Дополнительно можно
указать состояние целевого экрана, код ошибки, сообщение, контракт и тип линии.

| Тип | Как выглядит на карте |
|---|---|
| `navigation` | Сплошная направленная линия |
| `error` | Пунктирная линия |
| `redirect` | Штриховая линия |
| `return` | Линия с обратным изгибом |
| `external` | Двойная линия |

Переход на тот же экран допустим только тогда, когда состояние, ошибка или
сообщение дают пользователю наблюдаемый новый результат.

Карта прокладывает линии в свободных промежутках между карточками. Короткая
подпись содержит действие и условие не более чем в двух строках; полный текст
виден после выбора стрелки.

## Как связать экран со сценарием

В `UC-*` укажите начало, один или несколько результатов и, только если цикл
действительно нужен, разрешите его:

```md
- Начальный экран: SC-AUTH-LOGIN
- Конечные экраны: SC-ACCOUNT-HOME
- Разрешить цикл: Да
```

Toudocu берёт только переходы этого `UC-*`, находит достижимые экраны, тупики,
циклы и пути к конечным экранам. У каждого достижимого неконечного экрана
должно быть продолжение. Цикл без выхода считается ошибкой, если сценарий не
содержит `Разрешить цикл: Да`.

## Как человек пользуется картой

Карточка показывает превью или заглушку, ID, название, маршрут, статус, модуль
и число входящих и исходящих стрелок. Доступны:

- группировка по модулям;
- фильтр модуля, сценария и статуса;
- поиск;
- режим только незавершённых экранов;
- иерархия по родительским связям.

Один клик выбирает экран и открывает сведения, двойной — открывает его документ.
Стрелку тоже можно выбрать: панель покажет действие, условие, исходный и целевой
экраны, сценарий, состояние и ошибку.

Управление:

- колесо мыши масштабирует карту относительно указателя;
- перетаскивание свободного места перемещает карту;
- кнопки приближают, отдаляют, вписывают карту, сбрасывают вид и включают
  полноэкранный режим;
- с клавиатуры работают `+`, `-`, `0`, `Esc` и `Enter`;
- `Ctrl`/`Cmd` с колесом остаётся обычным масштабом браузера.

## Пошаговое прохождение

1. Пользователь открывает страницу нужного `UC-*` и вкладку «Проиграть».
2. Портал показывает начальный экран и действия из переходов этого сценария.
3. Выбранное действие переводит на целевой экран и применяет указанное
   состояние, сообщение или ошибку.
4. «Назад» возвращает предыдущий шаг, «Сначала» очищает историю.
5. На конечном экране доступны «Начать заново», «Показать карту» и «Открыть
   сценарий».

История живёт только до перезагрузки страницы. Это симуляция описанной
навигации: реальные API-запросы не выполняются.

## Превью и сообщения об ошибках

Коды ошибок объявляются в связанном контракте:

```md
## Ошибки

| ID | Сообщение |
|---|---|
| INVALID_CREDENTIALS | Неверный email или пароль. |
```

Превью может быть PNG, JPG, JPEG, WEBP, AVIF или GIF внутри репозитория.
Отсутствующий файл даёт предупреждение и заглушку. SVG, HTML, XML, JavaScript,
абсолютный путь, выход через `..` и символическая ссылка блокируются.

## Кликабельные зоны превью

Необязательный `screens/hotspots.json` связывает прямоугольник в процентах с
переходом:

```json
{
  "SC-AUTH-LOGIN": [
    {
      "transition": "TR-AUTH-001",
      "x": 31.5,
      "y": 59.2,
      "width": 37,
      "height": 8.4
    }
  ]
}
```

Координаты и размеры положительны, находятся в пределах `0–100` и не выводят
прямоугольник за изображение. Один переход нельзя повторять на экране без
`allowDuplicate`.

Неверная зона не попадает в HTML, но обычная кнопка действия продолжает
работать. Валидная зона доступна с клавиатуры, появляется при наведении или
фокусе; переключатель «Показать интерактивные зоны» делает все зоны видимыми.

## Изменения карты

В разделе Changes можно наложить текущий diff на карту. Новые `SC-*` и `TR-*`
помечаются как `added`, изменённые — `modified`, удалённые элементы старой
версии — `removed`. Состояние подписано текстом и не передаётся одним цветом.
Фильтры применяются к объединённой старой и новой модели, а выбор элемента
открывает его семантическое различие. JSON доступен через
`/_toudocu/api/changes/screen-map`.

## Связь с рабочей задачей

Задача может назвать изменяемый переход и отдельно сопоставить его с критерием
и командой:

```md
- Переходы: TR-AUTH-001

## Проверка

- `AC-01` → `TR-AUTH-001` → `TestSuccessfulLogin`
- `AC-01` → `go test ./... -run TestSuccessfulLogin`
```

Портал создаёт каталог `/screens/index.html`, страницы `SC-*`, вкладки
`#overview`, `#map`, `#play`, `#links` у `UC-*`, `/traceability.html` и экранную
модель в `report.json` версии 1. Всё работает на обычном HTTP-хостинге без
Go-сервера.

## Что проверяет Toudocu

Для экранов проверяются ID, тип, статус, модуль, уникальность маршрута и
безопасность превью. Для переходов — обязательные поля, целевой экран, сценарий,
состояние, код ошибки и осмысленность перехода в самого себя. Для сценария —
начало, конечные экраны, достижимость, тупики и циклы. Для зон — ссылки,
координаты, границы и повторы. В задачах проверяются существование `SC-*`,
`TR-*` и связи критериев с переходами и командами.

Ошибка всего графа скрывает только карту, ошибка одного сценария — только его
пошаговый режим. Остальные документы продолжают собираться. Отсутствующее
превью не останавливает сборку.
