# Локальная работа с порталом

Команда `serve` подходит для повседневной работы: она собирает портал, запускает локальный
HTTP-сервер и добавляет редактор, просмотр изменений, обсуждения и просмотр OpenAPI проекта.

## Полный рабочий путь

1. В корне проекта запустите:

   ```bash
   toudocu serve ./docs
   ```

2. Откройте напечатанный адрес. По умолчанию это `http://127.0.0.1:6419`.
3. Найдите документ через навигацию или поиск. На странице документа доступны действия
   «Редактировать», «Показать изменения» и «Открыть исходник».
4. В редакторе измените файл и сохраните его. Сервер проверит, что версия файла не успела
   измениться, запишет правку и перестроит модель, HTML и поиск.
5. Если файлы меняет внешний редактор или агент, дождитесь автоматического обновления. Портал
   проверяет состояние сервера каждые 15 секунд, пока вкладка видима, и после пересборки подтягивает
   новые данные без перезагрузки страницы. В скрытой вкладке опрос приостанавливается; при
   возвращении портал сразу проверяет состояние. Статусы и действия задач обновляются сами;
   выбранные фильтры и открытый терминал сохраняются. Несохранённый текст во встроенном редакторе не
   пропадает: при конфликте интерфейс просит выбрать дальнейшее действие.
6. Откройте «Изменения», чтобы проверить текущий Git diff. Обсуждение документации можно начать и
   продолжить там либо прямо на странице документа.
7. При необходимости на странице `roadmap.html` нажмите «Добавить результат», выберите существующий
   этап, проверьте предложенный `DLV-ROADMAP-NNN` и введите одну строку результата.
8. После работы остановите сервер сочетанием `Ctrl+C`.

## Работа с внешним агентом и терминалом

1. Откройте задачу и скопируйте команду нужного действия: начало работы, продолжение, уточнение или
   другой доступный запрос.
2. Передайте её своему агенту с установленным навыком Toudocu. Отдельная кнопка «Копировать
   контекст» копирует название и путь документа.
3. Для обработки обсуждений отправьте внешнему агенту `$toudocu feedback`. Сохранение обсуждения
   само по себе не запускает обработку очереди.

Кнопка «Терминал проекта» в шапке открывает панель. «Запустить терминал» запускает обычную оболочку
в корне репозитория; в ней можно самостоятельно ввести `codex`, `opencode`, `claude`, Git или другую
команду. Toudocu не управляет сессиями этих программ. Встроенная Agent Console удалена.

Переходы между страницами и закрытие панели сохраняют терминал. Для завершения процесса нажмите
«Остановить терминал» или остановите `serve`. На широком экране панель занимает соседнюю колонку и
меняет ширину; на узком открывается поверх страницы. Обсуждения и терминал показываются по одному.

Ручная кнопка пересборки полезна, если нужно сразу перечитать документацию. После завершения портал
подтягивает результат без перезагрузки страницы. При временной ошибке загрузки текущие данные
остаются на экране, а портал повторяет попытку автоматически.

## Доступные адреса

- `/` — основной портал;
- `/_toudocu/editor/` — редактор разрешённых исходных файлов;
- `/changes/` — изменения Git и локальные обсуждения;
- `/_toudocu/api-docs/` — просмотр OpenAPI-файлов выбранного проекта;
- `/_toudocu/api/tasks/{taskID}/actions` — доступные действия задачи в `serve`, открытом по
  локальному адресу.

Один запуск `serve` открывает один каталог из `locales.*`. Чтобы работать с другим языком, запустите
`serve` для его каталога; при одновременной работе выберите другой порт через `--port`. Редактор
меняет только выбранный каталог. Действия задач и терминал доступны по тем же правилам для любого
языка: запуск процессов разрешён только на локальном адресе.

## Сеть и безопасность

По умолчанию сервер слушает только `127.0.0.1`, то есть доступен с текущего компьютера. Флаг
`--host 0.0.0.0` открывает его для локальной сети. В Toudocu нет встроенных TLS и авторизации,
поэтому такой режим нельзя выставлять в недоверенную сеть; команда выводит об этом предупреждение.

Терминал проекта доступен только по локальному адресу. При любой другой привязке, включая
`--host 0.0.0.0`, он останется отключён независимо от настроек пользователя.

Новые выпуски Toudocu не проверяются автоматически. Для обновления повторно запустите установщик из
[руководства по установке](installation.md).

## Статическая публикация — другой режим

Отдельной команды `preview` нет. Для публикации выполните `toudocu build` и разместите результат на
[статическом HTTP-хостинге](deployment.md). В такой сборке нет локального API, редактора, просмотра
Git и записи в дорожную карту.
