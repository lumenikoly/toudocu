# Стандарты, runbook и собственные разделы

Глобально обязательны только `index.md` и `architecture/overview.md`. Каталоги
`quality/`, `runbooks/` и любой неизвестный верхнеуровневый раздел становятся
значимыми, когда в них появляется Markdown. Тогда нужен собственный `index.md`;
его отсутствие считается предупреждением и блокирует только строгий режим.

## Стандарты `STD-*`

Каждый файл `quality/STD-*.md` описывает один уникальный
стандарт `STD-*`.

Полезный стандарт содержит:

- канонические поля `id`, `status`, `scope`, `updated`;
- статус `draft`, `active`, `obsolete` или `superseded`;
- непустые разделы с машинными видами `rules` и `automated-checks`;
- для `superseded` — `supersededBy: STD-*` с существующим другим ID.

Неверный или повторяющийся ID и неверная ссылка на замену — ошибки. Пропущенные
описательные поля и разделы — предупреждения. Команды из стандарта сами по себе
не запускаются. Если задача явно указывает `Стандарты`, она должна сопоставить
их со своей целью проверки `QUALITY`.

Имена полей, машинные значения и виды разделов не переводятся. Заголовки и
весь читательский текст могут быть на любом языке.

Например, правило для всего Go-кода оформляют как стандарт, если проект может
однозначно назвать область и проверку:

```markdown
<!-- toudocu
version: 1
id: STD-GO-001
status: active
scope: Go-код и тесты
updated: 2026-08-18
-->

# STD-GO-001: Проверка Go-кода

<!-- toudocu:section rules -->
## Правила

Код должен проходить форматирование и тесты.

<!-- toudocu:section automated-checks -->
## Автоматические проверки

- `gofmt -w .`
- `go test ./...`
```

## Runbook `RB-*`

Runbook — проверенная эксплуатационная процедура. Каждый
`runbooks/RB-*.md` описывает один уникальный `RB-*`.

Он содержит канонические поля `id`, `status`, `risk`, `lastVerified` и
необязательное поле `environment`, а также размеченные разделы:

- `prerequisites`;
- `procedure` с нумерованными шагами;
- `verification`;
- `rollback`.

Для высокого и критического риска нужен ещё `stop-conditions`.
Допустимые статусы: `draft`, `active`, `review-required`, `obsolete`.
Риск: `low`, `medium`, `high`, `critical`.

У действующего runbook дата в пределах `--stale-days` даёт состояние `recent`,
более старая — `overdue`. `--stale-days 0` отключает только проверку возраста.
Отсутствующая, неверная или будущая дата и статус `review-required` дают
`review-required`. Для черновика и устаревшего документа свежесть не
применяется.

Этот репозиторий сейчас не содержит раздела `docs/runbooks/`: эксплуатационные
процедуры здесь пока не заведены.

Runbook нужен только для реально выполняемой операции. Например, восстановление
сервиса после сбоя описывает предварительные условия, нумерованные действия,
проверку результата и откат; общее объяснение запуска сервиса остаётся
руководством и не требует `RB-*`.

## Собственный раздел

Неизвестный верхнеуровневый каталог не получает тип по имени или содержимому.
Его `index.md` должен содержать:

- непустое описание;
- H1, который станет названием раздела в портале.

Остальные файлы остаются обычным Markdown.

## Связь с задачами и JSON

Поля задачи `standards` и `runbooks` принимают только существующие
ID. `task context` добавляет эти документы в типизированные коллекции,
`documents` и `requiredReads`. Toudocu намеренно не угадывает применимость
стандарта по его `Области`: исполнитель выбирает её сам.

`ProjectReport` версии 1 содержит `knowledge.standards`,
`knowledge.runbooks`, связанные ID задач и четыре счётчика свежести runbook.
Пустые коллекции записываются как `[]`.
