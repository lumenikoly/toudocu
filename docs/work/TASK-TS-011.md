# TASK-TS-011: Перенести Editor, Changes и Discussions в SPA

<!-- toudocu:section result -->
## Результат

Пользователь редактирует документацию, изучает изменения и ведёт обсуждения в общих маршрутах
React-приложения.

Это требуемый результат этапа; статус и отмеченные критерии показывают фактическую готовность. Основание — этап и пункты 9; 42; 45–48 исходного ТЗ, преобразованного в [дерево миграции](TASK-TS-001.md).

<!-- toudocu:section use-case-omission-reason -->
## Почему нет отдельного сценария

Миграция реализации сохраняет существующие пользовательские сценарии и публичные CLI/JSON-контракты. Новый сценарий ради смены языка не вводится.

<!-- toudocu:section scope -->
## Область изменения

Исходные точки переноса: `internal/`, `web/`, `scripts/`, `skills/` и `docs/`.
Новые пакеты создаются в пределах репозитория согласно результату этапа.

Editor read/preview/validate/save/create, revision conflicts, Git source/semantic/rendered diff, discussion queue.

<!-- toudocu:section out-of-scope -->
## Не входит в задачу

Изменение семантики CLI, документационного формата и модели задач, MCP, база данных, облачный backend, Next.js, Astro и автоматический запуск агента ядром. Другие этапы выполняются по зависимостям родительской задачи.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] `AC-01` Предпросмотр использует общий компилятор; устаревшая ревизия возвращает явный конфликт без потери чужих изменений.
- [x] `AC-02` Раздел Changes сохраняет все режимы сравнения Git, исходное, семантическое и отрисованное представления различий и связь с задачами.
- [x] `AC-03` Обсуждения доступны через интерфейс, а внешний агент работает только через прежние команды CLI `next` и `respond`; отдельного многостраничного приложения нет.

<!-- toudocu:section plan -->
## План

1. Перенести чтение, предпросмотр, проверку, сохранение и создание документов в прикладные сервисы редактора.
2. Использовать общий компилятор и модели представления; сохранить конфликты ревизий, все способы сравнения Git и связи с задачами.
3. Разместить редактор, изменения и обсуждения в общих React-маршрутах; сохранить доставку запросов внешнему агенту через CLI.
4. Проверить устаревшие ревизии, режимы сравнения, действия обсуждения и переходы между страницами; обновить руководства.

<!-- toudocu:section verification -->
## Проверка

- `AC-01` -> `pnpm test`
- `AC-02` -> `pnpm test:browser`
- `AC-03` -> `pnpm test:browser`
- `ALL` -> `pnpm check`
- `DOCS` -> `node apps/cli/dist/main.js check ./docs --repository-root . --strict --stale-days 0`
- `QUALITY` -> `pnpm check`

Проверки охватывают общий компилятор предпросмотра, защиту от устаревшей записи, режимы сравнения,
отрисованные различия, очередь обсуждений и переходы между рабочими разделами. До окончательного
переключения CLI проверка документации остаётся на действующей команде Go.

<!-- toudocu:section documentation-impact -->
## Влияние на документацию

Описание рабочей границы обновлено в модуле сайта, архитектурном обзоре браузерной части и
руководстве по разработке интерфейса. Документы сохраняют различие между действующим Go runtime и
TypeScript runtime до окончательного переключения CLI. Общие ограничения находятся в
[родительской задаче](TASK-TS-001.md).
