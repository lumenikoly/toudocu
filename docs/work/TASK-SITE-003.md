# TASK-SITE-003: Разделить Go-ядро и браузерную часть портала

<!-- toudocu:section result -->
## Результат

Пользователь по-прежнему получает один исполняемый файл Toudocu. Команда
`build` создаёт многостраничный портал только для чтения, который работает на
обычном HTTP(S)-сервере без запущенного Toudocu. `serve` использует тот же
портал, но добавляет локальные редактор, просмотр изменений и пересборку.

Go остаётся единственным источником проектной модели и единственным слоем,
который обращается к файловой системе, Git и командам рабочих задач.
TypeScript и CSS отвечают только за поведение и внешний вид в браузере. Они
собираются заранее и входят в исполняемый файл как готовые ресурсы.

<!-- toudocu:section behavior-change -->
## Изменение поведения

<!-- toudocu:section before -->
### Было

HTML-оболочка и большие фрагменты рабочих страниц собирались строками рядом с
прикладной логикой в `internal/app`. CSS и браузерный JavaScript лежали в
`internal/app/assets`, имели несколько несвязанных точек входа и зависели от
глобальных переменных и признаков в DOM. Статический портал обещал работу через
`file://`, поэтому поисковые данные выдавались как исполняемый JavaScript.
Существующая Node-сборка готовила лишь отдельные встроенные библиотеки и не
образовывала самостоятельную браузерную часть.

<!-- toudocu:section after -->
### Станет

Go строит проектную модель, данные страниц, безопасную HTML-оболочку, JSON для
запуска страницы и данные статического портала. Отдельный каталог `web/` со
строгим TypeScript и обычным CSS реализует поведение в браузере. Результат
сборки хранится в репозитории и встраивается через `go:embed`; Node.js нужен
только разработчику браузерной части.

`build` не содержит редактор, локальные API и код пересборки и работает в корне
или во вложенном пути HTTP(S)-сайта. `serve` использует ту же отрисовку и явно
включает дополнительные возможности и маршруты с тем же origin. `file://`
больше не входит в поддерживаемый контракт: для локальной работы используется
`toudocu serve`.

Внутренние пакеты, функции, DOM-зацепки и имена старых ресурсов сохранять не
требуется. Публичными остаются команды `build` и `serve`, их параметры и коды
завершения, стабильные маршруты на основе идентификаторов и существующие
JSON-схемы. Новая команда `preview` не появляется.

<!-- toudocu:section scope -->
## Область изменения

- новый каталог `web/` с TypeScript/CSS, lockfile, esbuild, проверкой типов и
  модульными и браузерными тестами;
- новый слой `internal/site/` для шаблонов и встроенных ресурсов;
- необходимые изменения `internal/app/` для подготовки данных страниц,
  статических JSON, маршрутов и возможностей `serve`;
- подключение нового слоя в `api.go` и `cmd/toudocu/` без переноса проектных
  правил в браузер;
- `internal/site/assets/generated/`, манифест и `go:embed`; старые ресурсы
  удаляются после полного перехода;
- `Makefile`, CI и при необходимости скрипты релиза для воспроизводимой сборки
  браузерной части;
- Go-, TypeScript-, браузерные и защитные тесты;
- README, журнал изменений, уведомления о зависимостях и связанные
  архитектурные, модульные, пользовательские и справочные документы.

## Не входит в задачу

- перенос в TypeScript разбора Markdown, классификации документов, проверки
  связей, готовности задач, смыслового diff, нормализации путей, прав доступа,
  сравнения Git и выбора команд проверки;
- вторая модель документации в TypeScript, SPA и обязательная клиентская
  маршрутизация;
- React, Vue, Svelte или другой прикладной фреймворк без отдельного ADR;
- Node.js, npm, сервер разработки, CDN, база данных или внешний сервер как
  зависимость пользователя и релизного архива;
- команда `preview`, отдельная команда статического сервера и обязательный
  параметр `baseURL`;
- адреса локальных API, действия записи и запуск команд задач в статическом
  портале;
- ослабление проверок путей, символических ссылок, хеша, размера, Git только
  для чтения и явного `task verify --run`;
- произвольные CSS, веб-шрифты, плагины тем и пользовательский JavaScript;
- облачный сервер, аутентификация и удалённая совместная работа;
- полный визуальный редизайн;
- поддержка и CI-проверка открытия через `file://`;
- сохранение старой внутренней реализации после миграции.

## Критерии приёмки

- [x] `AC-01` Go остаётся единственным источником `ProjectModel`,
  диагностических сообщений, связей, готовности задач и смыслового diff.
  Браузер получает только подготовленные данные страниц, статические данные,
  JSON запуска и ответы API и не повторяет проектные или защитные правила.
- [x] `AC-02` Централизованная отрисовка использует `html/template`,
  типизированные данные страниц и части шаблонов вместо больших строк в
  HTTP-обработчиках. Основной Markdown уже находится в HTML и читается даже при
  ошибке JavaScript.
- [x] `AC-03` Интерактивная страница получает безопасный JSON с
  `schemaVersion`, видом окружения, относительными путями ресурсов, локалью,
  оформлением и доступными возможностями. Абсолютные пути не попадают в него;
  неизвестные поля игнорируются, необязательные можно пропустить.
- [x] `AC-04` `web/` использует строгий TypeScript, стандартный DOM API,
  обычный CSS, CSS custom properties, esbuild и `tsc --noEmit`. Канонические
  команды: `npm run typecheck`, `npm run test`, `npm run build`,
  `npm run watch`, `make web` и `make web-check`.
- [x] `AC-05` Сборка создаёт воспроизводимые `manifest`, `portal.css`,
  `portal.js`, `serve.js`, `editor.js`, `changes.js` и части с именами по
  содержимому в `internal/site/assets/generated/`. В них нет времени и
  случайных значений, а Go находит ресурсы только через манифест.
- [x] `AC-06` После клонирования `go build ./...` не требует Node.js и
  встраивает готовые ресурсы через `go:embed`. Исходный TypeScript и
  `node_modules` не попадают в программу; CI замечает расхождение исходников и
  сгенерированных файлов.
- [x] `AC-07` `toudocu build` создаёт автономный многостраничный портал со
  всеми HTML, CSS, JavaScript, JSON и локальными ресурсами. В нём нет клиентов
  редактора и пересборки, адресов API, `localhost`, сетевых запросов времени
  выполнения, записи и запуска команд задач.
- [x] `AC-08` Статический портал работает по HTTP(S) в корне и во вложенном
  пути. Ссылки, динамические части и JSON разрешаются относительно базовых
  путей, переданных Go, без жёстких `/assets/`, `/data/` и обязательного
  `baseURL`.
- [x] `AC-09` Поиск и дополнительные данные навигации, связей, экранов и
  сценариев строятся из той же `ProjectModel`. Они загружаются относительным
  `fetch` и не содержат секреты, переменные среды, абсолютные пути, хеши
  редактора и лишний контекст репозитория.
- [x] `AC-10` `toudocu serve` использует ту же отрисовку и `portal.js`, но Go
  явно включает `serve`, `editor`, `changes`, `rebuild` и `taskWorkspace` и
  только нужные дополнительные файлы. Адреса приходят из JSON запуска,
  остаются на том же origin и не выводятся браузером из URL или путей ОС.
- [x] `AC-11` Файлы портала, `serve`, редактора и Changes изолированы.
  Статический портал не обращается к локальному API, тяжёлые функции
  загружаются только при необходимости, а ошибка Mermaid, предпросмотра или
  специального diff не скрывает Markdown и обычный diff.
- [x] `AC-12` Общие элементы Button, IconButton, Badge, Tabs, Disclosure,
  Dialog, Tooltip, CommandMenu, Tree, DataTable, EmptyState, Diagnostic и
  DiffBlock не знают о `ProjectModel`. Темы и настройки оформления сохраняют
  смысл; клавиатура, фокус, `Escape`, стрелки, reduced motion и состояния без
  опоры только на цвет покрыты тестами.
- [x] `AC-13` Браузер определяет вид страницы только по стабильным значениям
  `document`, `architecture`, `module`, `use-case`, `flow`, `screen`,
  `standard`, `runbook` и `task`, а не по H1. Подписи берутся из единого
  словаря локали без разветвления прикладной логики по языку.
- [x] `AC-14` Для JSON запуска, статических данных и функций `serve` есть
  отдельные понятные состояния: данных нет, версия схемы не поддерживается,
  диаграмма не построилась, API недоступен, пересборка не удалась, сохранение
  конфликтует, файл или diff недоступен, коллекция пуста или функция
  выключена. Ошибка одного блока не скрывает основной Markdown.
- [x] `AC-15` Защитные тесты покрывают внедрение скрипта через Markdown,
  опасные URL, завершение HTML внутри JSON, отсутствие локального API и
  абсолютных путей в `build`, слишком большие и устаревшие записи редактора и
  невозможность запустить команду задачи через интерфейс. Прежние проверки
  путей, ссылок, хеша, размера и команд не ослаблены.
- [x] `AC-16` Публичные `build` и `serve`, параметры, коды завершения,
  ID-маршруты и схемы `ProjectReport`, `ChangeSetReport` и `TaskVerifyReport`
  сохраняются. Команда `preview` отсутствует. Внутренние детали совместимыми
  быть не обязаны.
- [x] `AC-17` Браузерный smoke-тест открывает `build` через HTTP и проверяет
  главную, вложенный документ, CSS/JS, поиск, оформление, вкладки сценария,
  Mermaid и запасной вывод ошибки. Тот же путь повторяется во вложенном URL.
  `file://` в тесте не используется.
- [x] `AC-18` Браузерный smoke-тест `serve` проверяет пересборку, открытие и
  сохранение в редакторе, конфликт хеша, представления Changes и отсутствие
  серверных функций без соответствующей возможности.
- [x] `AC-19` README и связанные руководства, модули, сценарии, процессы,
  архитектурные ответы, контракты и справочники указывают `serve` для локальной
  работы и `build` с HTTP(S)-размещением для публикации и больше не обещают
  `file://`.
- [x] `AC-20` После перехода в репозитории нет старых встроенных скриптов,
  мёртвых CSS-селекторов, дублирующей браузерной логики и двух параллельных UI.
  Лицензии новых браузерных зависимостей актуальны.

## Влияние на документацию

Изменился продуктовый контракт портала: автономность `build` означает, что
после сборки Toudocu не нужен, но сам портал публикуется по HTTP(S). Для
локальной работы используется `serve`. Были обновлены архитектура, MOD-SITE,
пользовательские сценарии и процессы `build`/`serve`, README, CLI- и
API-справочники и руководства по тестированию, размещению и разработке
браузерной части. Переводы не входили в историческую задачу и обновляются
отдельным явным вызовом локализации.
