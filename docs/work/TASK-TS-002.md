# TASK-TS-002: Зафиксировать функциональную совместимость Go-версии

<!-- toudocu:section result -->
## Результат

Создать воспроизводимый корпус исходных проектов и эталонные результаты legacy CLI до переноса реализации.

Это требуемый результат этапа; статус и отмеченные критерии показывают фактическую готовность. Основание — этап 0 и пункты 64–70 исходного ТЗ, преобразованного в [дерево миграции](TASK-TS-001.md).

<!-- toudocu:section use-case-omission-reason -->
## Почему нет отдельного сценария

Миграция реализации сохраняет существующие пользовательские сценарии и публичные CLI/JSON-контракты. Новый сценарий ради смены языка не вводится.

<!-- toudocu:section scope -->
## Область изменения

Исходные точки переноса: `internal/`, `web/`, `scripts/`, `skills/` и `docs/`.
Новые пакеты создаются в пределах репозитория согласно результату этапа.

JSON, диагностика, задачи, Git staged/unstaged/untracked/rename, позиции Unicode, статические маршруты и отрицательные случаи безопасности.

<!-- toudocu:section out-of-scope -->
## Не входит в задачу

Измерения времени, памяти и производительности не требуются по решению пользователя.

Изменение семантики CLI, документационного формата и модели задач, MCP, база данных, облачный backend, Next.js, Astro и автоматический запуск агента ядром. Другие этапы выполняются по зависимостям родительской задачи.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] `AC-01` Эталонные stdout, stderr и exit code покрывают все публичные команды и существенные ошибочные случаи.
- [x] `AC-02` Механизм сравнения эталона с кандидатом нормализует только время, временные пути и версию генератора; тесты подтверждают обнаружение несовпадений вывода, exit code, записанных файлов и контрольных сумм.

<!-- toudocu:section plan -->
## План

1. Зафиксировать список публичных команд, JSON, exit codes, диагностику,
   Unicode ranges, Git states, routes и отрицательные security cases.
2. Собрать representative fixtures и legacy outputs; документировать только
   допустимые нормализации времени, временных путей и версии генератора.
3. Запустить compatibility corpus и сохранить expected results как baseline
   для TypeScript compiler и CLI.
4. Обновить описание baseline и передать точные fixtures следующим этапам.

<!-- toudocu:section verification -->
## Проверка

- `AC-01` -> `node scripts/compatibility.mjs`
- `AC-02` -> `node --test scripts/compatibility.test.mjs`
- `ALL` -> `node scripts/compatibility.mjs`
- `DOCS` -> `node apps/cli/dist/main.js check ./docs --repository-root . --strict --stale-days 0`
- `QUALITY` -> `pnpm check`

Команды новой системы являются целевыми проверками этапа. До появления соответствующих тестов их успешный запуск не подтверждает критерии. При удалении Go документационные проверки переводятся на новый CLI; совпадение отчётов проверяется до переключения.

Проверено 19 сентября 2026: 49 эталонных сценариев и пять тестов самого
сравнения проходят. Корпус включает чтение, запись в изолированные проекты,
Git, статическую сборку, локальный сервер, skill и протокол очереди агента.
Точный состав и нормализации описаны в `fixtures/README.md`.
Проверяются характерные сценарии всех публичных операций, а не все сочетания
флагов или платформ. Полная проверка Unicode-позиций и браузера выполняется
на следующих этапах.

`changeSetDigest` проверяется по исходному отчёту, затем пересчитывается после
нормализации временного корня. Некорректная контрольная сумма не скрывается.
Режим сравнения готового кандидата работает без установленного Go.
Независимая проверка корпуса и этих границ завершена; совместимость самого
TypeScript CLI этим этапом не заявляется.
