# MOD-CHANGES: Изменения документации

- Идентификатор: MOD-CHANGES
- Статус: Готово
- Владелец: Команда Toudocu
- Последнее обновление: 2026-08-10

Модуль сравнивает два явно выбранных состояния локального Git и создаёт один
воспроизводимый отчёт для CLI, CI и локального портала.

## Назначение

Точно показать патч Git, а для известных документов дополнить его различиями
структуры, связей и отрисованного результата. Анализ не использует AI-модель.

## Расположение в коде

- `internal/app/changes_*.go` — чтение Git, сравнение, отчёт и специальные
  представления;
- `internal/app/server.go` — локальный API и обновление отчёта после изменения
  рабочего дерева;
- `internal/app/changes_http.go` — список HTTP-маршрутов и единый формат ошибок
  версии 1;
- `web/src/features/changes/`, `web/src/styles/changes.css` — интерфейс,
  доступный только при `serve`. Собранные ресурсы встраиваются из
  `internal/site/assets/generated/`.

## Границы

Модуль не меняет рабочее дерево, индекс, ссылки и историю Git. Статический
`build` не читает историю и не содержит API изменений. Markdown отображает
`MOD-MARKDOWN`, а общую оболочку страницы создаёт `MOD-SITE`.

## Бизнес-правила

Пути, HTTP-методы и схемы ответов закреплены в
[Changes OpenAPI](../contracts/changes.openapi.yaml). Здесь описано поведение
самого сравнения и изоляция его ошибок.

### BR-CHANGES-001: Git является единственным источником версий

Старая сторона читается из базы объектов Git или индекса, новая — из явно
выбранного коммита, индекса или рабочего дерева. Собственной истории документов
у Toudocu нет.

### BR-CHANGES-002: Исходный diff имеет приоритет

Ошибка семантического анализа, отрисовки Markdown, Mermaid или OpenAPI не
скрывает доступный патч Git и статистику строк.

### BR-CHANGES-003: Диапазон всегда явный

Отчёт и интерфейс показывают введённые и разрешённые начало и конец сравнения,
ветку, `HEAD` и наличие локальных правок. Если базовую ветку нельзя определить
однозначно, её выбирает пользователь.

### BR-CHANGES-004: Публичный отчёт ограничен каталогами документации

`ChangeSetReport`, обычные команды `changes` и специальные представления
документов охватывают только настроенные каталоги документации. Все пути
записаны относительно корня репозитория; по ним нельзя прочитать `.git` или
выйти за разрешённые каталоги.

Список файлов всего репозитория и обсуждения принадлежат отдельному
[MOD-REVIEW](MOD-REVIEW.md). Они не расширяют публичную схему
`ChangeSetReport` и не добавляют исходный код в документационные отчёты CLI.

## Инварианты

- Git запускается напрямую, без системной оболочки, внешнего обработчика diff,
  `textconv` и `fetch`.
- Семантическое сравнение воспроизводимо и не использует AI-модель.
- Файл `TASK-*` не считается постоянной проектной документацией.
- Полное содержимое и отрисованные версии загружаются только при обращении к
  ним.
- Поведение существующих `check` и статического `build` от модуля не зависит.

## Стабильные интерфейсы

- `ChangeSetReport` версии 1;
- команды `changes` и `task changes`, включая `--include-assets` и полный набор
  входных файлов перевода `--translation-input`;
- API чтения `/_toudocu/api/changes/`;
- коды диагностических сообщений и значения диапазона сравнения.
