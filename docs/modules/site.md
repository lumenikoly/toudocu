# Статический портал и локальный workspace

Модуль превращает проверенную модель проекта в HTML, навигацию, поиск, browser assets и
`report.json`. `build` создаёт read-only портал, а `serve` использует те же React-страницы и
добавляет локальные инструменты.

<!-- toudocu:section code-location -->

## Расположение в коде

- `packages/portal/` — snapshot, page views и route registry;
- `apps/web/renderer/` — server-side render общих React-страниц;
- `apps/web/` — React Router, страницы и локальные рабочие поверхности;
- `packages/server/` — HTTP/WebSocket, watcher и runtime capabilities;
- `packages/platform-node/` — безопасная запись, Git, reviews, providers и PTY.

<!-- toudocu:section boundaries -->

## Границы

Presentation не читает Markdown и не повторяет правила модели. React получает готовые view models и
capabilities, но не решает, можно ли записать файл, запустить процесс или изменить задачу.
Статический портал никогда не содержит editor, Changes API, Discussions, Agent Console или Project
Terminal.

Главная страница служит рабочей сводкой: показывает до шести незавершённых неархивных задач, разделы
знаний с числом документов и результаты структурной проверки. Задачи в работе и заблокированные
задачи стоят перед готовыми и черновиками. Если рабочих задач нет, сводка использует текущую работу
из модели проекта; отсутствие данных отображается явно. Статус документации не означает проверку
достоверности её содержания.

На широком экране закреплённая шапка высотой `64px` содержит знак и название проекта из snapshot,
поиск и действия в одной строке. Немодальный список результатов привязан к полю, показывает до 12
совпадений из snapshot и доступен
с клавиатуры. `/` вне полей ввода и `Ctrl/Cmd+K` переводят фокус в поиск. На ширине до `52rem`
шапка занимает две строки общей высотой `112px`: бренд с действиями и поиск. Agent Console и
Terminal открываются отдельными действиями только при
наличии соответствующей runtime capability. Кнопка солнца или луны открывает отдельное меню
оформления: превью Classic, Paper и Terminal, выбор светлой, тёмной или системной схемы, акцента и
плотности. Обсуждения, печать и доступная в `serve` пересборка находятся в меню настроек. Выбор
оформления и ширина боковой панели сохраняются локально и не меняют конфигурацию проекта.

Боковая панель имеет начальную ширину `240px` и содержит ссылки Home, Editor, Changes и Health,
дерево разделов, группу «Проект» и текущую сущность без повторного блока с названием проекта. Она
остаётся видимой также на страницах Editor и Changes; на узком экране раскрывается под шапкой. Шрифт
Golos Text поставляется вместе с порталом
для кириллицы и латиницы. Основная область расположена на слегка тонированном холсте; белые панели
со скруглением `12px` объединяют рабочие разделы, а тёмная схема сохраняет ту же иерархию.
Семантические статусы различаются цветом, значком и текстом.

На главной заголовок «Обзор проекта» отделяет страницу от названия проекта в шапке. Текущая работа
и разделы знаний занимают основную колонку, состояние проекта и свёрнутый исходный обзор — соседнюю.
Карта реальных связей модулей и сценариев расположена ниже. Под заголовком страницы показано
доступное описание проекта. Раскрытый обзор показывает исходный документ целиком.
Страницы процессов и экранов берут связи и переходы из snapshot, не восстанавливая
их из текста в browser.

На странице документа название и действия расположены на холсте над содержимым; ID, статус, тип и
доступные атрибуты находятся под названием. Основная панель содержит текст и связи, а соседняя
колонка — метаданные «О документе» или «О задаче» и оглавление. На узком экране оба блока
раскрываются по действию пользователя. Вводный абзац остаётся в основном тексте и не дублируется
в заголовке, включая Markdown с выделением и ссылками. Текст ограничен колонкой `72ch`; разделы
и блоки кода имеют клавиатурно доступные действия. Связанные документы и обратные ссылки идут
после текста разделёнными линиями списками, сохраняя ID. На странице задачи дополнительно видны
зависимости и критерии приёмки.

Значок редактирования открывает исходный файл текущего документа; путь в адресе редактора определяет
выбор файла и при последующей навигации. Счётчики ошибок и предупреждений раскрывают диагностики
этого документа: код, сообщение и доступное расположение. В локальном workspace расположение ведёт к
исходному файлу в редакторе.

Над текстом задачи расположены компактные действия по её текущему состоянию, включая уточнение через
`$toudocu clarify <ID>`. Действия агента позволяют скопировать промпт с ID задачи; при доступной
Agent Console нажатие на название передаёт тот же промпт в сайдбар. Копирование доступно и в
статическом портале. Архивные и отменённые задачи не показывают эти действия.

Корневые списки разделов ограничены по ширине и центрируются в рабочей области. Строки сохраняют
сетку и внутренние отступы даже без доступного маршрута документа; недоступный документ не
получает фиктивную ссылку. Заголовки встроенных разделов и известные поля метаданных с их
перечислимыми значениями переводятся на язык интерфейса. Пользовательские поля и свободный текст
сохраняют исходное написание.

Task Workspace показывает быстрые состояния и поиск, а дополнительные фильтры раскрывает по
действию пользователя; активные дополнительные условия отмечает счётчиком. Board, list и tree
используют общую строку: ID над названием, доступные приоритет и модуль, описание результата,
прогресс критериев, статус и ссылку на задачу. Дополнительные действия находятся в раскрываемом
меню; критерии и зависимости можно раскрыть в строке. Вычисленную готовность, причины ожидания,
прогресс ветви и допустимость завершения он получает из общей доменной модели; браузер не выводит
их из цвета или записанного статуса.

Оставшиеся рабочие области используют общую иерархию заголовка, панели действий и
содержимого. В диагностике отдельно показаны код, серьёзность, сообщение и документ;
пустая выборка фильтра отличается от отсутствия диагностик. Дорожная карта отмечает
вычисленную завершённость каждого пункта и связывает известные ID с документами.
Форма добавления результата открывается в модальном диалоге, который закрывается по Escape.
Трассировка сохраняет табличное сопоставление и прокручивается по горизонтали на узком экране.
API-контракты имеют компактную панель выбора и ссылку на исходник; при отсутствии спецификаций
панель выбора скрыта. В обсуждениях состояние, расположение и доставка отделены от текста
сообщений; консоль различает разговор, команды и результаты проверок.

Каталоги ищут документы по ID, названию и пути. Строка показывает ID над названием, доступное
описание, статус и дату изменения из документа; длинные названия переносятся. Известные ID и пути
в метаданных, ссылки на модули и сценарии
в задачах, экраны и задачи в трассировке ведут к соответствующим документам.

Карта экранов показывает превью, подписи узлов и переходов и группы по модулям; поддерживает
фильтры, автоматическую подгонку карты, масштабирование, полноэкранный режим и инспектор сущности.
Колесо мыши масштабирует карту к курсору, перетаскивание сдвигает её, а жест двумя пальцами меняет
масштаб. Ссылка на карту находится в группе «Экраны» боковой навигации. Карта сценария использует
тот же компонент для связанных экранов и переходов; связанные FLOW-документы показываются отдельно,
их Mermaid-диаграммы инициализируются при появлении содержимого.
Ошибка одной Mermaid-диаграммы не мешает рендерингу остальных:
портал восстанавливает её исходный код и показывает раскрываемую причину ошибки, полученную от
рендерера. В режиме `serve` превью и вложения раздаются по явному списку файлов проекта;
список обновляется при пересборке. Режим Play использует
объявленные preview, state preview, hotspots, сообщения, ошибки и терминальные состояния. Editor
использует CodeMirror, вложенное дерево исходников, диагностику, Preview и Split и сохраняет
пользовательский текст при конфликте внешнего изменения. Changes сохраняет Git range в URL, строит
дерево файлов, поддерживает unified и side-by-side hunks, inline review и отдельные source, file,
rendered, semantic, relation, map, asset и diagnostic представления. API Docs получает список
OpenAPI-контрактов из snapshot. Один селектор переключает отображаемый контракт и сохраняет его
путь в параметре `spec` URL. Локальный Swagger UI разрешает `Try it out` только для `GET` и `HEAD`.

Repository review в Changes использует отдельные read-only Git endpoints: поиск ограничен корнем
репозитория, а просмотр возвращает bounded UTF-8 содержимое сторон `before` и `current`. Поэтому
удалённые, переименованные и недокументационные файлы доступны без расширения прав Editor API.
Контракты OpenAPI, Mermaid-блоки, изображения и изменённые Markdown-разделы получают собственные
представления вместо необработанного JSON.

Discussions хранит привязку к документу или точному диапазону diff, показывает смещённые и
устаревшие anchors, очередь доставки и ответы агента. Изменение сообщения разрешено только до
захвата delivery; все мутации защищены revision и state digest. Agent Console остаётся в shell над
route outlet и показывает отдельные представления агента и Project Terminal в общей боковой панели.
На широком экране панель занимает соседнюю колонку и сужает страницу; при ширине до `72rem` она
закрепляется поверх страницы сбоку. Нижняя панель показывает значки режимов и только действия
выбранного режима: запуск, остановку и историю агента либо запуск и остановку Project Terminal.
Настройки провайдера, уровня доступа, модели и поддерживаемого уровня рассуждения находятся в
раскрываемом блоке нижней панели Agent. Выбор полного доступа требует подтверждения перед
сохранением. Открытие панели или
представления не запускает агента и терминал: каждый процесс начинается только после отдельного
действия запуска. Закрытие панели и переключение представлений не размонтируют workspace, поэтому
текущий черновик сообщения и активный сеанс сохраняются в памяти. Консоль показывает поток событий,
команды и terminal, а также позволяет проверить активную задачу: план не выполняет команды, запуск
требует отдельного подтверждения, а отчёт об ошибке можно передать активному агенту.

Настройки `classic`, `paper`, `terminal`, цветовой схемы, акцента и плотности передаются через
snapshot и применяются к общим компонентам. Classic использует прохладные серо-голубые поверхности;
Paper — тёплый холст и Georgia для основного текста; Terminal — моноширинный интерфейс и более
угловатые панели. Все три темы используют выбранную светлую или тёмную схему. Настроенная
иллюстрация проекта занимает небольшую область заголовка.

## Бизнес-правила

### BR-SITE-001: Очистка выходного каталога не затрагивает защищённые пути

`build --clean` отклоняет корень файловой системы, source root, его родителя и небезопасные
symlink-пути. Готовый staging публикуется атомарно.

### BR-SITE-002: Портал работает на обычном статическом HTTP-хостинге

Статический портал использует относительные URL, работает в корне и под префиксом, читаем без
JavaScript и не требует запущенный Toudocu.

### BR-SITE-003: Локальный сервер открывает файлы только через явные интерфейсы

`serve` раздаёт только известные маршруты и assets; файловые операции проходят через PathPolicy,
revision/digest и atomic replace.

### BR-SITE-004: Mermaid работает автономно и в строгом режиме

Mermaid использует локальный runtime; небезопасные directives и HTML не попадают в страницу.

### BR-SITE-005: Карта экранов работает автономно

Карта экранов и проигрывание сценариев не требуют сети и внешних runtime-ресурсов.

### BR-SITE-006: Темы не расширяют доверенную поверхность

Визуальные настройки не добавляют произвольный код или внешние ресурсы.

### BR-SITE-007: build и serve имеют разные возможности

`build` остаётся read-only; Editor, Changes, Discussions, Agent Console и Project Terminal доступны
только в каноническом loopback `serve`.

### BR-SITE-008: Запись защищена проверкой версии файла

Изменяющие операции проверяют revision или digest перед атомарной заменой.

### BR-SITE-009: Локали являются равноправными рабочими областями

Выбранный translation root строится как отдельный read-only snapshot.

### BR-SITE-010: Мягкая навигация доступна только в каноническом serve

React Router переключает маршруты `serve`; статический портал остаётся обычными HTML-страницами.

### BR-SITE-014: Дорожная карта изменяется только ограниченной операцией

Roadmap изменяется только операцией `roadmap-add` с CAS.

### BR-SITE-015: Проверка версии не влияет на доступность портала

Проверка версии необязательна, ограничена основным `serve` и не влияет на доступность портала.

### BR-SITE-018: Work items получают специализированное рабочее представление

Task Workspace получает из `packages/core` вычисленные work state, причины готовности, прогресс
критериев и потомков и допустимость завершения. CLI передаёт адаптер проверки repository paths. В
`serve` прямое завершение повторно валидирует актуальный документ и сохраняет его по digest;
остальные действия передают типизированный контекст в Agent Console.

### BR-SITE-023: Agent Console скрывает протокол провайдера

Agent Console доступна только в основном loopback `serve`. Browser не получает executable, argv,
cwd, environment или provider protocol. Проверка задачи использует тот же планировщик и command
runner, что и CLI; выполнение требует явного подтверждения и отменяется вместе с сессией.

### BR-SITE-024: Project Terminal запускается только после явного открытия

Project Terminal имеет отдельный lifecycle и лениво загружает xterm.

## Инварианты

- `index.md` становится главной страницей без дублирования H1 и метаданных.
- Маршруты статического и server режима происходят из одного registry.
- Main content и обычные ссылки доступны до hydration.
- React Router управляет навигацией, но не доменной моделью и безопасностью.
- Agent Console остаётся смонтированной над route outlet при навигации; закрытие панели не
  сбрасывает черновик сообщения или активный сеанс.
- Provider, PTY, watcher и WebSocket закрываются вместе с сервером.
- Переводной портал остаётся отдельным read-only snapshot.
- `file://` не является поддерживаемым режимом просмотра.

<!-- toudocu:section stable-interfaces -->

## Стабильные интерфейсы

- `PortalSnapshotV1`, `PageViewV1` и `RuntimeCapabilitiesV1`;
- статические маршруты и `report.json`;
- Editor, Changes, Agent Feedback и Agent Console OpenAPI/HTTP contracts;
- semantic HTML и доступная клавиатурная навигация.
