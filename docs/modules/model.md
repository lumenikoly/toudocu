# Проектная модель и валидация

- Идентификатор: MOD-MODEL
- Статус: Готово
- Владелец: Команда Docgent
- Последнее обновление: 2026-07-31

Модуль читает каталог документации, строит связанную модель проекта и формирует
диагностику структуры, идентификаторов, путей и зависимостей.

## Назначение

Преобразовать набор независимых Markdown-файлов в предсказуемую модель,
пригодную для проверки, HTML-рендеринга и машинного отчёта.

## Расположение в коде

- модель документов: `docs_core.go`, `types.go`;
- знания и work items: `knowledge.go`;
- разрешение ссылок: `documentation_links.go`;
- общие безопасные операции с путями: `utils.go`.

## Границы

Модуль не генерирует HTML-файлы и не запускает команды задач. Он возвращает
модель и diagnostics, не изменяя исходную документацию.

## Бизнес-правила

### BR-MODEL-001: Roadmap является единственным источником глобального охвата

Глобальный прогресс учитывает только элементы `roadmap.md`. Для связанного
`UC-*` выполнение берётся из статуса use case, а `CON-*` и `DLV-*` сохраняют
состояние собственного checkbox.

### BR-MODEL-002: Ссылки не выходят за repository root

Локальная ссылка может покинуть каталог документации только внутри явно
определённого repository root. Выход за его границы блокируется и отражается в
diagnostics.

### BR-MODEL-003: Готовая к работе задача имеет полный проверяемый контракт

Начиная со статуса «Готово к работе», work item содержит scope, ограничения,
критерии `AC-*`, план, команды проверки и влияние на документацию.

### BR-MODEL-004: Документы экранов являются источником графа

Метаданные, состояния и таблицы переходов из `screens/SC-*.md` образуют
типизированную модель `SC-*` и `TR-*`. Произвольная Mermaid-грамматика не
разбирается как требования или связи.

## Инварианты

- каждый стабильный ID уникален в своей проектной модели;
- стандарты `STD-*` и runbook `RB-*` уникальны, а work item ссылается только на
  существующие typed documents;
- минимальная документация требует только `index.md`; manifest появившегося
  quality, runbooks или custom-раздела проверяется предупреждениями;
- экранные переходы ссылаются только на существующие `SC-*`;
- screen routes уникальны, а previews и hotspots не выходят за repository root;
- каждый проигрываемый сценарий достигает terminal screen либо содержит diagnostic;
- один файл `work/*.md` содержит ровно один рабочий элемент `TASK-*` или `BUG-*`;
- номера строк в публичных отчётах начинаются с единицы;
- обычная сборка модели не выполняет команды;
- исходные Markdown-файлы никогда не перезаписываются вычисляемым состоянием.

## Стабильные интерфейсы

- `BuildDocumentationModel(Options)`;
- `ProjectReport` schema v1;
- коды `Issue`;
- правила ID и структуры, описанные в [CLI-контракте](../contracts/cli.md).
- статусы, типы и формат задач из [руководства по рабочим задачам](../guides/work-items.md).
- [стандарты качества](../quality/).
