# Проектная модель и проверка

- Идентификатор: MOD-MODEL
- Статус: Готово
- Владелец: Команда Toudocu
- Последнее обновление: 2026-08-10

Модуль читает каталог документации, связывает известные сущности и создаёт
сообщения о структуре, ID, путях и зависимостях. Результат используют `check`,
портал и JSON-отчёты.

## Расположение в коде

- `internal/app/docs_core.go`, `types.go` — документы и модель;
- `internal/app/knowledge.go` — известные сущности и задачи;
- `internal/app/documentation_links.go` — ссылки;
- `internal/app/utils.go` — безопасные пути.

## Границы

Модель не создаёт HTML и не запускает команды задач. Она возвращает данные и
сообщения, не меняя исходники. Редактор может передать одну версию файла в
памяти для предварительного просмотра; обычная сборка читает файловую систему.

## Бизнес-правила

### BR-MODEL-001: Дорожная карта является единственным источником общего охвата

Общий прогресс учитывает только пункты `roadmap.md`. У связанного `UC-*`
завершённость берётся из статуса сценария, а `CON-*` и `DLV-*` сохраняют свою
галочку.

### BR-MODEL-002: Ссылки не выходят за корень репозитория

Локальная ссылка может выйти из документации только к файлу внутри явно
выбранного корня репозитория. Более дальний путь блокируется.

### BR-MODEL-003: Готовая к работе задача имеет полный проверяемый контракт

Начиная с «Готово к работе» задача содержит границы, исключения, критерии
`AC-*`, план, команды и влияние на документацию.

### BR-MODEL-004: Документы экранов являются источником графа

Метаданные, состояния и таблицы `screens/SC-*.md` создают `SC-*` и `TR-*`.
Произвольная Mermaid-диаграмма не превращается в требования или связи.

### BR-MODEL-005: Архитектурный обзор является прямой картой вопросов

`architecture/overview.md` обязателен и имеет тип `Architecture Overview`.
Каждый другой файл архитектуры задаёт непустой вопрос и связан из обзора
напрямую; транзитивной ссылки недостаточно.

### BR-MODEL-006: OpenAPI-контракты проверяются как отдельный тип источника

Только `contracts/**/*.openapi.{yaml,yml,json}` получает проверку OpenAPI
3.0/3.1. Проверяются корневые поля, операции и ответы, уникальность
`operationId`, параметры пути и внутренние `$ref`. Внешние ссылки не
загружаются. Для произвольного YAML общая схема не придумывается.

## Инварианты

- Каждый стабильный ID уникален в своей области.
- `STD-*` и `RB-*` уникальны; задача ссылается только на существующие документы
  нужного вида.
- Минимальный проект требует `index.md` и `architecture/overview.md`.
- Появившиеся `quality/`, `runbooks/` и собственный раздел без полного
  `index.md` дают предупреждение.
- Опасная или неработающая архитектурная ссылка — ошибка; смысл вопроса
  проверяет человек.
- Переход ведёт только на существующий `SC-*`; маршруты экранов уникальны.
- Превью и кликабельные зоны не выходят за корень репозитория.
- Пошаговый сценарий достигает конечного экрана либо получает сообщение об
  ошибке графа.
- Один файл `work/*.md` содержит одну задачу `TASK-*` или `BUG-*`.
- Строки публичных отчётов нумеруются от единицы; колонка OpenAPI добавляется,
  когда она известна.
- Сборка модели не выполняет команды и не записывает вычисленное состояние
  обратно в Markdown.
