# CLI и процессы задач

- Идентификатор: MOD-CLI
- Статус: Готово
- Владелец: Команда Toudocu
- Последнее обновление: 2026-08-10

Модуль объединяет команды проверки, сборки, локального просмотра, поиска,
изменений и задач. Его результаты воспроизводимы, коды завершения стабильны, а
машинные ответы используют JSON версии 1.

## Расположение в коде

- `api.go`, `cmd/toudocu/main.go` — публичный Go-фасад и точка входа;
- `internal/app/cli.go`, `internal/app/server.go` — CLI и локальный сервер;
- `internal/app/task_context.go`, `task_ready.go`, `task_verify.go`,
  `task_archive.go` — процессы задач;
- `internal/app/search.go`, `scaffold.go` — поиск и каркасы;
- `internal/app/command_process_*.go` — запуск и остановка процессов;
- `skills/bundle.go`, `internal/skillinstall/`, `internal/app/skill_cli.go` —
  встроенный skill, планирование и файловые операции.

## Границы

CLI не понимает запрос на естественном языке. `task ready` и `task context`
только читают. Команды проекта запускает лишь `task verify --run` после
проверки задачи и отдельного разрешения пользователя.

`$toudocu init`, `$toudocu refresh`, `$toudocu translate` и `$toudocu feedback`
выполняет AI-агент; таких команд в Go CLI нет. `skill` только размещает
встроенные файлы и не исполняет их содержимое. Этот процесс не экспортируется
через публичный Go-фасад.

## Бизнес-правила

### BR-CLI-001: Контекст задачи не исполняет команды

`task context` возвращает задачу, нужные документы, связи и найденные проблемы,
но не вызывает системную оболочку.

### BR-CLI-002: Проверки запускаются только явно

Команды `AC-*`, `ALL`, `DOCS` и условный `QUALITY` выполняются только через
`task verify --run`. Одинаковая команда запускается один раз, а отчёт сохраняет
все связанные цели.

### BR-CLI-003: Превышение времени завершает дерево процессов

После превышения `--timeout` останавливаются системная оболочка и все созданные
ею дочерние процессы. Результат получает `timed_out`.

### BR-CLI-004: Toudocu не интерпретирует пользовательский запрос

Toudocu создаёт нейтральный каркас и проверяет формат. Исполнитель выбирает
связи, пишет требования, меняет статус и подтверждает критерии.

### BR-CLI-005: Браузер и CLI используют один реестр каркасов

`task init`, варианты `scaffold` и редактор получают порядок, поля, правила,
путь и шаблон из одного реестра. Новый файл создаётся атомарно с запретом
перезаписи (`O_EXCL`).

### BR-CLI-006: Корень перевода не является рабочим контекстом

Каталог перевода можно проверять, собирать, искать, сравнивать и открывать в
`serve` только для чтения. Команды задач, `scaffold` и запись Editor заранее
возвращают `TRANSLATION_ROOT_READ_ONLY`. Переведённые задачи — только зеркало;
контекст и CI используют основной каталог.

### BR-CLI-007: Архивирование не изменяет контракт задачи

`task archive` и `task restore` перемещают один файл без перезаписи и не меняют
Markdown или статус. Если прямая ссылка после переноса разрешалась бы иначе,
операция блокируется.

### BR-CLI-008: Управляемый skill не перезаписывает изменения пользователя

Жизненный цикл меняет только отсутствующую или точную управляемую копию с
действительным манифестом. Дополнительный, изменённый или удалённый файл,
неверные права, символическая ссылка, неизвестный каталог, повреждённый
манифест и более новая версия блокируют запись. Флага `--force` нет.

### BR-CLI-009: Жизненный цикл skill работает без сети

Один пакет встроен в бинарник. `skill install`, `status`, `update` и
`uninstall` не используют сеть, системную оболочку или каталог расширений и не
запускают сценарии из пакета.

### BR-CLI-010: Все назначения планируются до записи

Для `--agent all` сначала разрешаются и проверяются все уникальные назначения.
После этого каждое обрабатывается независимо; ошибка одного не останавливает
остальные, но частичный результат возвращает код `1`.

## Инварианты

- JSON-ответ не смешивается с потоковым текстом.
- Команды задачи выполняются последовательно и продолжаются после сбоя одной.
- Каждая команда запускается из корня репозитория.
- Сохраняется не более последнего 1 МиБ stdout и 1 МиБ stderr каждой команды.
- Сборка требует явного `toudocu build`; путь без команды отклоняется.
- Имена `init`, `refresh`, `translate` и `feedback` не принимаются как команды
  верхнего уровня.
- Создание задач и документов не использует каталог перевода.
- `serve` по умолчанию слушает только loopback; внешний адрес включается явно.
- Браузер не открывается без `--open`; флагов `--no-open` и `--edit` нет.
- `skill status` ничего не пишет. Изменяющие команды перед публикацией ещё раз
  сверяют назначение и восстанавливают резервную копию при ошибке.

## Стабильные интерфейсы

- команды и параметры из [CLI-контракта](../contracts/cli.md);
- `ProjectReport`, `TaskContextReport`, `SearchReport`, `TaskInitReport`,
  `ScaffoldReport`, `TaskReadyReport`, `TaskMoveReport` и `TaskVerifyReport`
  версии 1;
- код `0` только для успешного результата или допустимой операции без
  изменения.
