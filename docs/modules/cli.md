# CLI и workflow задач

- Идентификатор: MOD-CLI
- Статус: Готово
- Владелец: Команда Docgent
- Последнее обновление: 2026-07-26

Модуль предоставляет команды Docgent, компактный контекст задачи и управляемое
выполнение объявленных проверок.

## Назначение

Объединить операции инициализации, проверки, сборки и task workflow в
предсказуемом CLI с устойчивыми exit codes и JSON-выводом.

## Расположение в коде

- CLI: `cli.go`, `cmd/docgent/main.go`;
- read-only контекст: `task_context.go`;
- выполнение проверок: `task_check.go`;
- управление процессами: `command_process_unix.go`, `command_process_windows.go`.

## Границы

CLI не содержит собственных правил документационной модели. `task context`
только читает данные, а `task check` запускает команды после локального
validation gate.

## Бизнес-правила

### BR-CLI-001: Контекст задачи не исполняет команды

`task context` возвращает задачу, связанные сущности, документы и diagnostics,
но не вызывает системную оболочку.

### BR-CLI-002: Проверки запускаются только явно

Команды `AC-*`, `ALL` и `DOCS` исполняются только через `task check`. Повторяющаяся
команда выполняется один раз и сохраняет все связанные targets.

### BR-CLI-003: Timeout завершает дерево процессов

При превышении timeout завершается не только shell, но и созданные им дочерние
процессы; отчёт получает статус `timed_out`.

## Инварианты

- JSON-режим не смешивает отчёт с потоковым текстовым выводом;
- команды выполняются последовательно даже после ошибки;
- каждая команда запускается из repository root;
- stdout и stderr ограничены последним 1 MiB каждого потока;
- обратная совместимость вызова `docgent ./docs ...` сохраняется.

## Стабильные интерфейсы

- команды и параметры из [CLI-контракта](../contracts/cli.md);
- `TaskContextReport` schema v1;
- `TaskCheckReport` schema v1;
- exit code `0` только при успешном результате операции.
