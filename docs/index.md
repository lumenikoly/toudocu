# Docu-docu

Docu-docu — dependency-free CLI на Go с публичным Go-фасадом для проверяемой
проектной документации в структурированном Markdown и автономного HTML-портала,
работающего через `file://`.

## Проблема

Проектная документация быстро расходится с кодом, когда статусы, связи,
критерии приёмки и команды проверки хранятся в несогласованных файлах или
требуют ручной синхронизации.

## Решение

Docu-docu строит единую модель из Markdown, проверяет стабильные идентификаторы,
ссылки, бизнес-правила, roadmap и work items, а затем отдаёт результат человеку
в HTML и автоматизации в JSON ProjectReport schema v1.

## Основные возможности

- минимальный старт с `docs/index.md` и обязательной карты
  `docs/architecture/overview.md`;
- вопросно-ориентированные подробные архитектурные документы;
- строгая структурная и ссылочная валидация;
- Git-backed просмотр изменений исходной документации;
- вычисляемое состояние roadmap и активной работы;
- раздельные каталоги `UC-*` и `FLOW-*` с двусторонними связями;
- опциональные стандарты `STD-*`, runbook `RB-*` и управляемые custom-разделы;
- автономные Mermaid-диаграммы и типизированные `FLOW-*` процессы;
- типизированный каталог `SC-*`, интерактивная карта и проигрываемые сценарии;
- traceability `UC → SC → TR → TASK → AC → verification`;
- безопасный статический HTML с поиском, темами и адаптивной навигацией;
- компактный read-only контекст задачи для LLM-агента;
- подготовка, архивирование и восстановление проверяемых рабочих задач;
- выполнение явно объявленных проверок выбранной задачи;
- полный и HEAD-diff refresh актуальности через устанавливаемый AI-skill;
- versioned JSON schema для проекта, task context и task workflow;
- публичный Go API для встраивания модели, рендеринга и типизированных отчётов;
- работа одним бинарником без внешних runtime-зависимостей; закреплённые
  Go-модули связываются внутрь бинарника.

## Целевая аудитория

- разработчики и технические руководители;
- команды, ведущие документацию рядом с кодом;
- LLM-агенты, которым нужен ограниченный и машиночитаемый контекст;
- CI-системы, проверяющие документационный контракт;
- Go-разработчики, встраивающие Docu-docu из исходного модуля.

## Ограничения

- поддерживается намеренно ограниченное подмножество Markdown;
- команды `task verify --run` считаются доверенным кодом репозитория;
- результат `build` является статическим и не редактирует исходные документы;
- режим `serve` изменяет только явно выбранные canonical workspace-файлы через
  editor API и не предоставляет запись в translation roots;
- глобальный прогресс определяется только `roadmap.md`.
