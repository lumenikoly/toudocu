# UC-TASK-01: Получить контекст рабочей задачи

- Идентификатор: UC-TASK-01
- Статус: Готово
- Актор: Исполнитель — разработчик или программный агент
- Модуль: MOD-CLI
- Приоритет: Высокий
- Последнее обновление: 2026-07-27

Исполнитель получает ограниченный контекст одной рабочей задачи перед
изменением кода или документации.

## Входные данные

- стабильный `TASK-*` ID;
- каталог документации;
- repository root;
- формат результата `text` или `json`.

## Предусловия

- Docgent доступен для запуска;
- исполнитель имеет права чтения документации и репозитория.

## Основной сценарий

1. Исполнитель вызывает
   `docgent task context TASK-ID ./docs --format json`.
2. Docgent находит ровно одну задачу с указанным ID.
3. Docgent собирает задачу, модуль, сценарий, бизнес-правила, зависимости,
   зависимые задачи, связанные документы и относящиеся к ним diagnostics.
4. Docgent возвращает `TaskContextReport`.
5. Исполнитель использует результат, область изменений и ограничения задачи
   для планирования работы.

## Ошибочные сценарии

- на шаге 2 отсутствующий ID завершает команду с кодом `1`;
- несколько задач с одинаковым ID делают запрос неоднозначным и завершают
  команду с кодом `1`;
- проблемы связанной документации остаются в `issues` отчёта и доступны
  исполнителю до начала работы;
- ошибка чтения проекта завершает команду до формирования контекста.

## Постусловия

Исполнитель получил контекст выбранной задачи. Исходные файлы не изменены,
команды из раздела `Проверка` не выполнены.

## Проверка

- JSON-тест состава `TaskContextReport`;
- тест отсутствующего и неоднозначного `TASK-*`;
- проверка связанных правил, зависимостей и документов;
- отдельный тест отсутствия исполнения команд.
