# UC-TASK-02: Выполнить проверки рабочей задачи

- Идентификатор: UC-TASK-02
- Статус: Готово
- Актор: Исполнитель — разработчик или программный агент
- Модуль: MOD-CLI
- Приоритет: Высокий
- Последнее обновление: 2026-07-28

Исполнитель явно запускает команды проверки выбранной задачи и получает полный
отчёт по критериям приёмки.

## Входные данные

- стабильный `TASK-*` ID;
- каталог документации и repository root;
- timeout каждой команды;
- необязательный путь JSON-отчёта.

## Предусловия

- задача подготовлена как минимум до статуса `Готово к работе`;
- владелец репозитория доверяет командам из раздела `Проверка`;
- исполнитель осознаёт, что команды запускаются с его правами.

## Основной сценарий

1. Исполнитель вызывает
   `docgent task check TASK-ID ./docs --format json`.
2. Docgent находит задачу и применяет к ней task-local validation gate.
3. Docgent составляет список уникальных команд `AC-*`, `ALL` и `DOCS`.
4. Docgent последовательно запускает команды из repository root.
5. Docgent связывает результаты команд с критериями и формирует
   `TaskCheckReport`.
6. Исполнитель использует итоговый status, exit code и вывод команд для
   принятия результата.

## Ошибочные сценарии

- отсутствующий или неоднозначный ID завершает команду с кодом `1`;
- ошибка контракта выбранной задачи блокирует запуск всех команд и даёт status
  `blocked`;
- команда, которую невозможно запустить, получает status `start_error`;
- ненулевой exit code команды даёт ей status `failed`;
- превышение timeout завершает дерево процессов и даёт status `timed_out`;
- ошибка одной команды не останавливает остальные проверки;
- ошибка записи `--report` даёт ненулевой exit code, даже если проверки прошли.

## Постусловия

Все запланированные команды получили результат, если validation gate не
заблокировал запуск. Итоговый status равен `passed`, `failed` или `blocked`;
exit code `0` возвращается только для `passed`. Команды могут изменять
репозиторий, поскольку выполняются как обычный доверенный код.
