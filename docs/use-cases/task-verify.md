# UC-TASK-02: Проверить рабочую задачу

- Идентификатор: UC-TASK-02
- Статус: Готово
- Актор: Исполнитель — разработчик или программный агент
- Модуль: MOD-CLI
- Приоритет: Высокий
- Последнее обновление: 2026-08-09

Исполнитель сначала получает план проверок без выполнения, а затем при явном
выборе запускает все или один target и получает полный отчёт.

## Входные данные

- стабильный `TASK-*` ID;
- каталог документации и repository root;
- timeout каждой команды;
- режим `--dry-run` или `--run`;
- необязательный target `AC-*`, `ALL`, `DOCS` или `QUALITY`;
- необязательный путь JSON-отчёта.

## Предусловия

- для `--run` задача подготовлена как минимум до статуса `Готово к работе`;
- `--dry-run` разрешён для полного Draft и не исполняет команды;
- владелец репозитория доверяет командам из раздела `Проверка`;
- исполнитель осознаёт, что команды запускаются с его правами.

## Основной сценарий

1. Исполнитель вызывает
   `toudocu task verify TASK-ID ./docs --dry-run --format json`.
2. Toudocu находит задачу и применяет к ней task-local validation gate.
3. Toudocu составляет список уникальных команд `AC-*`, `ALL`, `DOCS` и
   условного `QUALITY` для явно связанных стандартов.
4. Dry-run возвращает команды со status `planned`, ничего не выполняя.
5. После проверки плана исполнитель явно вызывает `task verify --run`.
6. Toudocu последовательно запускает выбранные команды из repository root.
7. Toudocu связывает результаты команд с критериями и формирует
   `TaskVerifyReport`.
8. Исполнитель использует итоговый status, exit code и вывод команд для
   принятия результата.

## Ошибочные сценарии

- отсутствующий или неоднозначный ID завершает команду с кодом `1`;
- Draft и Cancelled блокируют `--run` без выполнения команд;
- ошибка контракта выбранной задачи блокирует запуск всех команд и даёт status
  `blocked`;
- команда, которую невозможно запустить, получает status `start_error`;
- ненулевой exit code команды даёт ей status `failed`;
- превышение timeout завершает дерево процессов и даёт status `timed_out`;
- ошибка одной команды не останавливает остальные проверки;
- ошибка записи `--report` даёт ненулевой exit code, даже если проверки прошли.

## Постусловия

Dry-run без `--report` не имеет внешних эффектов; с `--report` он атомарно
записывает только выбранный JSON-файл вне documentation root. В режиме run все
выбранные команды получили результат, если validation gate не заблокировал
запуск. Итоговый status равен
`planned`, `passed`, `failed` или `blocked`; exit code `0` возвращается для
`planned` и `passed`. Команды в режиме run могут изменять
репозиторий, поскольку выполняются как обычный доверенный код.
