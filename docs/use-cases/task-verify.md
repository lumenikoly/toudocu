# UC-TASK-02: Проверить рабочую задачу

Актор: исполнитель — разработчик или программный агент.

Исполнитель сначала читает точный план команд без запуска, а затем отдельным
явным действием выполняет все команды или одну выбранную цель.

## Входные данные

- стабильный ID `TASK-*`;
- каталог документации и корень репозитория;
- предел времени для каждой команды;
- режим `--dry-run` или `--run`;
- необязательная цель `AC-*`, `ALL`, `DOCS` или `QUALITY`;
- необязательный файл JSON-отчёта.

<!-- toudocu:section prerequisites -->
## Предусловия

- для `--run` задача имеет как минимум статус «Готово к работе»;
- полный черновик можно посмотреть через `--dry-run`, команды при этом не
  выполняются;
- владелец репозитория прочитал и считает доверенными команды из раздела
  «Проверка»;
- исполнитель понимает, что они получат его права и могут менять репозиторий.

<!-- toudocu:section main-scenario -->
## Основной сценарий

1. Исполнитель запускает:

   ```bash
   toudocu task verify TASK-ID ./docs --dry-run --format json
   ```

2. Toudocu находит задачу и проверяет только её контракт и прямые связи.
3. Утилита собирает уникальные команды `AC-*`, `ALL`, `DOCS` и, если он нужен,
   `QUALITY` из явно связанных стандартов.
4. Ответ показывает команды со статусом `planned`; ничего не запускается.
5. После чтения плана и отдельного разрешения исполнитель повторяет команду с
   `--run`.
6. Команды выполняются последовательно из корня репозитория, а результаты
   связываются с критериями в `TaskVerifyReport`.
7. Исполнитель принимает результат по состоянию, коду завершения и фактическому
   выводу команд.

## Ошибочные сценарии

- Отсутствующий или повторяющийся ID даёт код `1`.
- Черновик и отменённая задача блокируют `--run` до запуска команд.
- Ошибка контракта выбранной задачи даёт `blocked` и не запускает ни одну
  команду.
- Невозможность запустить команду даёт `start_error`, ненулевой код — `failed`,
  превышение времени — `timed_out` с остановкой дерева процессов.
- Ошибка одной команды не отменяет остальные.
- Ошибка записи `--report` возвращает ненулевой код, даже если сами команды
  прошли.

<!-- toudocu:section postconditions -->
## Постусловия

`--dry-run` без `--report` ничего не меняет; с `--report` он атомарно записывает
только выбранный JSON-файл вне документации. При `--run` каждая допущенная
команда получает результат. Итог бывает `planned`, `passed`, `failed` или
`blocked`; код `0` возвращается только для `planned` и `passed`.

<!-- toudocu:section acceptance-criteria -->
## Критерии приёмки

- [x] `--dry-run` без `--report` ничего не меняет, а с `--report` атомарно
  записывает только выбранный JSON-файл вне документации.
- [x] В режиме `--run` каждая допущенная команда получает результат.
- [x] Итог имеет значение `planned`, `passed`, `failed` или `blocked`; код `0`
  возвращается только для `planned` и `passed`.

## Проверка сценария

Покрываются план без запуска, дедупликация команд, ошибка старта, продолжение
после сбоя, остановка дерева процессов по времени, связь результатов с
критериями и сборка для Windows amd64.
