# UC-DOCS-05: Просматривать изменения документации

- Идентификатор: UC-DOCS-05
- Статус: Готово
- Актор: Разработчик
- Модуль: MOD-CHANGES
- Приоритет: Высокий
- Экраны: SC-SITE-HOME, SC-CHANGES-WORKSPACE
- Начальный экран: SC-SITE-HOME
- Конечные экраны: SC-CHANGES-WORKSPACE
- Последнее обновление: 2026-08-12

Перед завершением работы разработчик видит, какие файлы изменены, как поменялся
текст и что эти правки значат для структуры документации.

## Входные данные

- каталог документации;
- явно выбранные начальное и конечное состояния либо сравнение по умолчанию
  `HEAD → working-tree`;
- необязательные фильтры, ресурсы, полный набор входных файлов для перевода или
  связанная задача.

## Предусловия

- Git установлен, а каталог документации находится внутри локального
  репозитория;
- выбранные коммиты или ссылки уже есть в локальном репозитории.

## Основной сценарий

1. Для работы в браузере разработчик запускает `toudocu serve ./docs` и
   открывает раздел «Изменения» по адресу `/changes/`. Для отчёта в терминале он
   вместо этого запускает `toudocu changes ./docs`.
2. По умолчанию Toudocu сравнивает `HEAD` со всем рабочим деревом, включая
   индекс, незаписанные в индекс правки, удаления и новые файлы. Другой диапазон
   выбирается явно.
3. В браузере разработчик видит число файлов и строк, затем при необходимости
   отбирает файлы по имени, состоянию, области и типу: все, документация или
   остальные файлы репозитория.
4. Он выбирает файл из раздела «Изменённые» или вручную добавленный файл из
   раздела «Связанные».
5. Вкладка «Diff» показывает точный патч Git, а «Файл целиком» — текущий UTF-8
   файл или последнюю версию удалённого файла. Для документации дополнительно
   доступны «До и после», «Семантика» и «Связи». Для подходящих файлов могут
   появиться представления OpenAPI, Mermaid, ресурсов или карты экранов.
6. Если работа связана с `TASK-*`, разработчик отдельно запускает
   `toudocu task changes <ID> ./docs` и сравнивает заявленные в задаче документы
   с реальным Git diff. Предупреждение требует внимания, но само по себе не
   доказывает ошибку.

## Альтернативные сценарии

- Если Git недоступен, остальной портал продолжает работать, а раздел
  «Изменения» объясняет причину.
- Если одну из версий документа не удалось разобрать, точный патч Git остаётся
  доступным, а ошибку получает только дополнительное представление.
- Для слишком большого или двоичного файла показываются известные сведения и
  понятное сообщение вместо попытки вывести текст.
- Когда рабочее дерево меняется, страница получает новый отчёт и по возможности
  сохраняет выбранные фильтры.

## Постусловия

- Репозиторий Git не изменён.
- Браузер, CLI и CI получают один и тот же версионированный отчёт.
- Предупреждения о влиянии задачи остаются подсказками для человека, а не
  автоматическим решением.

## Критерии приёмки

- [x] Просмотр изменений не меняет состояние Git.
- [x] Браузер, CLI и CI получают один и тот же версионированный отчёт.
- [x] Предупреждение о влиянии задачи не принимает решение вместо человека.
