# UC-REVIEW-01: Обсудить документацию и изменения с агентом

- Идентификатор: UC-REVIEW-01
- Статус: Готово
- Актор: Разработчик
- Модуль: MOD-REVIEW
- Приоритет: Высокий
- Экраны: SC-SITE-DOCUMENT, SC-CHANGES-WORKSPACE
- Начальный экран: SC-SITE-DOCUMENT
- Конечные экраны: SC-SITE-DOCUMENT, SC-CHANGES-WORKSPACE
- Последнее обновление: 2026-08-11

Разработчик задаёт вопрос по документации или комментирует изменения во всём
локальном репозитории, передаёт подготовленные сообщения AI-агенту и получает
его ответ в тех же обсуждениях.

## Предусловия

- основной портал запущен через `serve` внутри Git-репозитория;
- конечное состояние сравнения — `working-tree`. Для коммита или индекса
  обсуждения доступны только для чтения.

## Основной сценарий

1. Разработчик открывает страницу документа в основном портале `serve`,
   выделяет фрагмент и выбирает «Добавить вопрос».
2. Toudocu сохраняет вопрос с точным диапазоном исходного Markdown. Если
   выделение нельзя сопоставить однозначно, вопрос привязывается ко всему файлу,
   а выбранный фрагмент добавляется в сообщение.
3. На текущей странице открывается панель обсуждений документа. Разработчик
   читает ветки, отвечает, закрывает, открывает заново или удаляет их без
   перехода в `/changes/`. В разделе «Изменения» те же ветки доступны рядом с
   комментариями ко всему набору, файлу, строке патча или выделенному фрагменту.
4. Toudocu сохраняет путь, строки, выделенный текст и окружающий контекст в
   локальном пользовательском состоянии вне репозитория.
5. Пока сообщение не отправлено, разработчик может изменить или удалить его.
   После ответа агента обсуждение можно продолжить новым сообщением. Любую
   ветку можно удалить целиком в любом состоянии.
6. Кнопка «Отправить агенту» в Портале или «Изменениях» создаёт неизменяемый
   пакет ожидающих комментариев.
   Она не запускает агента. Интерфейс показывает фразу «Обработай комментарии из
   Toudocu Changes», которую можно скопировать.
7. Разработчик передаёт эту фразу подключённому агенту или явно вызывает
   `$toudocu feedback`. Агент получает самый старый ожидающий пакет, проверяет
   замечания по репозиторию, при необходимости меняет файлы и возвращает один
   результат для каждого сообщения.
8. Ответы агента появляются в исходных обсуждениях. Разработчик сам просматривает
   изменения и закрывает обсуждение либо оставляет его открытым; ответ агента
   не закрывает обсуждение автоматически.

## Альтернативные сценарии

- Для конечного состояния `commit` или `index` форма отключена и объясняет, что
  комментарии разрешены только для рабочего дерева.
- При необходимости разработчик открывает `/changes/` и продолжает те же
  обсуждения рядом с изменениями репозитория.
- В статическом и переводном порталах контекстное меню обсуждения не создаётся;
  обычное выделение и копирование текста браузером остаются доступны.
- Файл из раздела «Связанные» не попадает в состояние обсуждений, пока для него
  не сохранено первое сообщение.
- После изменения файла Toudocu переносит привязку только при однозначном
  совпадении. Иначе она помечается как устаревшая (`stale`), а для удалённого
  файла — как `deleted`.
- Неверный или неполный ответ агента не меняет ни одного обсуждения.
- Удаление ветки из ожидающего пакета отменяет пакет целиком и возвращает
  сообщения остальных веток в неотправленное состояние.
- Повреждённое локальное хранилище не перезаписывается; пользователь получает
  диагностическое сообщение.

## Постусловия

- Обсуждения остаются локальными и не записываются в репозиторий.
- Отправленные сообщения и ответы нельзя редактировать; ветку можно удалить
  только целиком.
- Результат `fixed`, `notFixed` или `needsClarification` не закрывает обсуждение
  автоматически.
