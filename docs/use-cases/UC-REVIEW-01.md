# UC-REVIEW-01: Обсудить изменения и передать комментарии агенту

- Идентификатор: UC-REVIEW-01
- Статус: Готово
- Актор: Разработчик
- Модуль: MOD-REVIEW
- Приоритет: Высокий
- Экраны: SC-CHANGES-WORKSPACE
- Начальный экран: SC-CHANGES-WORKSPACE
- Конечные экраны: SC-CHANGES-WORKSPACE
- Последнее обновление: 2026-08-10

Разработчик комментирует изменения во всём локальном репозитории, передаёт
подготовленные сообщения AI-агенту и получает его ответ в тех же обсуждениях.

## Предусловия

- основной портал запущен через `serve` внутри Git-репозитория;
- конечное состояние сравнения — `working-tree`. Для коммита или индекса
  обсуждения доступны только для чтения.

## Основной сценарий

1. Разработчик открывает `/changes/` и оставляет выбранным конечное состояние
   `working-tree`.
2. Он комментирует весь набор изменений, целый файл, строку патча или выделенный
   фрагмент во вкладке «Файл целиком». Дополнительный тип выбирать не нужно:
   форма принимает только текст сообщения.
3. Toudocu сам сохраняет путь, строки, выделенный текст и окружающий контекст в
   локальном пользовательском состоянии вне репозитория.
4. Пока сообщение не отправлено, разработчик может изменить или удалить его,
   а также добавить ответы в обсуждение.
5. Кнопка «Отправить агенту» создаёт неизменяемый пакет ожидающих комментариев.
   Она не запускает агента. Интерфейс показывает фразу «Обработай комментарии из
   Toudocu Changes», которую можно скопировать.
6. Разработчик передаёт эту фразу подключённому агенту или явно вызывает
   `$toudocu feedback`. Агент получает самый старый ожидающий пакет, проверяет
   замечания по репозиторию, при необходимости меняет файлы и возвращает один
   результат для каждого сообщения.
7. Ответы агента появляются в исходных обсуждениях. Разработчик сам просматривает
   изменения и закрывает обсуждение либо оставляет его открытым; ответ агента
   не закрывает обсуждение автоматически.

## Альтернативные сценарии

- Для конечного состояния `commit` или `index` форма отключена и объясняет, что
  комментарии разрешены только для рабочего дерева.
- Файл из раздела «Связанные» не попадает в состояние обсуждений, пока для него
  не сохранено первое сообщение.
- После изменения файла Toudocu переносит привязку только при однозначном
  совпадении. Иначе она помечается как устаревшая (`stale`), а для удалённого
  файла — как `deleted`.
- Неверный или неполный ответ агента не меняет ни одного обсуждения.
- Повреждённое локальное хранилище не перезаписывается; пользователь получает
  диагностическое сообщение.

## Постусловия

- Обсуждения остаются локальными и не записываются в репозиторий.
- Отправленные пакеты и ответы нельзя изменить задним числом.
- Результат `fixed`, `notFixed` или `needsClarification` не закрывает обсуждение
  автоматически.
