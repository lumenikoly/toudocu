# UC-DOCS-01: Создать автономный портал

- Идентификатор: UC-DOCS-01
- Статус: Готово
- Актор: Разработчик
- Модуль: MOD-SITE
- Приоритет: Высокий
- Последнее обновление: 2026-07-27

Разработчик преобразует проверяемые Markdown-документы в локальный портал и
машиночитаемый отчёт.

## Входные данные

- каталог проектной документации;
- output directory;
- опциональные repository URL, ref, excludes и stale threshold.

## Предусловия

- каталог документации существует и доступен для чтения;
- output не совпадает с защищённым каталогом;
- пользователь доверяет содержимому собственного репозитория.

## Основной сценарий

1. Пользователь вызывает `docgent build ./docs`.
2. CLI строит и валидирует проектную модель.
3. Генератор создаёт HTML, assets, поиск и `report.json`.
4. Пользователь открывает `index.html` через `file://`.

Для локальной разработки пользователь может вызвать `docgent serve ./docs`.
Команда выполняет первоначальную сборку, раздаёт только output-каталог и
пересобирает портал при обновлении HTML-страницы. По умолчанию доступ разрешён
только с текущего компьютера; `--host 0.0.0.0` явно открывает доступ локальной
сети.

## Ошибочные сценарии

- отсутствующий каталог завершает команду с ошибкой;
- небезопасный output отклоняется до удаления или записи;
- ошибки модели отражаются в отчёте и ненулевом exit code;
- при `--strict` предупреждения также дают ненулевой exit code.
- ошибка первоначальной сборки или запуска listener не оставляет работающий
  сервер;
- ошибка пересборки возвращается HTTP 500 и может быть исправлена без
  перезапуска процесса.

## Постусловия

При успехе output содержит автономный портал и `ProjectReport` schema v1.
Исходный Markdown не изменён.
