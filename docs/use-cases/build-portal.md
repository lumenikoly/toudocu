# UC-DOCS-01: Создать статический HTTP-портал

- Идентификатор: UC-DOCS-01
- Статус: Готово
- Актор: Разработчик
- Модуль: MOD-SITE
- Приоритет: Высокий
- Последнее обновление: 2026-08-05

Разработчик преобразует каталог проектной документации в read-only портал,
который публикуется на обычном HTTP(S) static hosting и после сборки не требует
Docu-docu backend.

## Входные данные

- каталог проектной документации;
- выходной каталог;
- необязательные настройки repository URL, ref, excludes и stale threshold.

## Предусловия

- Docu-docu доступен для запуска;
- у разработчика есть права чтения исходного каталога и записи в выходной.

## Основной сценарий

1. Разработчик вызывает `docu-docu build ./docs --output ./build/project-docs`.
2. Docu-docu читает документы и проверяет структуру, ссылки и связанные сущности.
3. Docu-docu создаёт HTML-страницы, CSS/JavaScript, статические JSON-ресурсы и
   `report.json` из одной project model.
4. Docu-docu сообщает путь к созданному `index.html` и итоговую статистику.
5. Разработчик публикует output на HTTP(S) static hosting.
6. Браузер открывает портал из корня host или вложенного URL-пути.

## Ошибочные сценарии

- на шаге 2 недоступный исходный каталог завершает команду с кодом `1`, портал
  не создаётся;
- перед шагом 3 небезопасный путь `--output` или `--clean` отклоняется до
  удаления и записи файлов;
- если модель содержит ошибки, портал и `report.json` создаются с diagnostics,
  а команда завершается с кодом `1`;
- при `--strict` наличие предупреждений также приводит к коду `1`;
- ошибка записи или генерации прерывает сборку и выводится в stderr.

## Постусловия

При успешной генерации выходной каталог содержит backend-independent портал,
static data и `ProjectReport` schema v1. Исходный Markdown не изменён. Для
локальной работы используется `docu-docu serve`; новая preview-команда не нужна.

## Проверка

- интеграционная генерация HTML и JSON;
- негативные тесты output, симлинков и активных assets;
- сборка минимального проекта с `index.md` и `architecture/overview.md`;
- browser smoke на static HTTP server в корне и во вложенном URL-пути;
- отсутствие editor/rebuild/API assets и URL в static output;
- повторная frontend-сборка с идентичным manifest и assets.
