# UC-DOCS-01: Создать статический HTTP-портал

- Идентификатор: UC-DOCS-01
- Статус: Готово
- Актор: Разработчик
- Модуль: MOD-SITE
- Приоритет: Высокий
- Последнее обновление: 2026-08-12

Разработчик превращает каталог документации в портал только для чтения,
который можно разместить на обычном HTTP(S)-хостинге. После сборки запущенный
Toudocu не нужен.

## Входные данные

- каталог документации;
- выходной каталог;
- необязательные настройки URL репозитория, ссылки Git, исключений и срока
  устаревания документов.

## Предусловия

- Toudocu доступен для запуска;
- разработчик может читать исходный каталог и записывать в выходной.

## Основной сценарий

1. Разработчик запускает:

   ```bash
   toudocu build ./docs --output ./build/project-docs
   ```

2. Toudocu читает документы и проверяет структуру, ссылки и связи.
3. Из одной модели создаются HTML-страницы, CSS, JavaScript, статические
   JSON-данные и `report.json`.
4. Команда печатает путь к `index.html` и итоговую статистику.
5. Разработчик публикует весь выходной каталог на HTTP(S)-хостинге.
6. Пользователь открывает портал в корне сайта или по вложенному URL.

## Ошибочные сценарии

- Недоступный исходный каталог завершает команду с кодом `1`; портал не
  создаётся.
- Опасный путь `--output` или `--clean` отклоняется до удаления или записи.
- Если модель содержит ошибки, портал и `report.json` всё равно сохраняют
  понятные сообщения, но команда возвращает код `1`.
- С `--strict` предупреждение также приводит к коду `1`.
- Ошибка записи или генерации прерывает сборку и выводится в stderr.

## Постусловия

Выходной каталог содержит автономный портал и `ProjectReport` версии 1.
Исходный Markdown не меняется. Прямое открытие через `file://` не является
поддерживаемым путём; для локальной работы используется `toudocu serve`.

## Критерии приёмки

- [x] Выходной каталог содержит автономный портал и `ProjectReport` версии 1.
- [x] Сборка не меняет исходный Markdown.
- [x] Локальный просмотр выполняется через `toudocu serve`, а не через
  `file://`.
