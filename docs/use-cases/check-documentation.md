# UC-DOCS-02: Проверить документацию

- Идентификатор: UC-DOCS-02
- Статус: Готово
- Актор: Разработчик или CI
- Модуль: MOD-MODEL
- Приоритет: Высокий
- Последнее обновление: 2026-07-26

Разработчик или CI проверяет документационный контракт без генерации сайта и
без выполнения команд задач.

## Входные данные

- каталог документации;
- repository root;
- режим `--strict`;
- формат `text` или `json`.

## Предусловия

- Markdown-файлы находятся внутри доступного каталога;
- repository root соответствует проверяемому репозиторию.

## Основной сценарий

1. Пользователь вызывает `docgent check ./docs --strict`.
2. Сканер безопасно читает Markdown-файлы.
3. Валидаторы проверяют структуру, ID, ссылки, roadmap и work items.
4. CLI печатает diagnostics или полный `ProjectReport`.
5. CI принимает решение по exit code.

## Ошибочные сценарии

- битая или заблокированная ссылка создаёт diagnostic;
- дублирующий или висячий ID создаёт ошибку модели;
- неполный non-draft work item блокирует строгую проверку;
- недоступный входной каталог завершает операцию до построения модели.

## Постусловия

Никакие команды из work items не выполнены, исходные документы не изменены, а
каждый diagnostic содержит стабильный code и, когда возможно, путь и строку.

## Бизнес-правила

Правила определены в документах соответствующих модулей:

- [BR-MODEL-001](../modules/model.md#br-model-001-roadmap-является-единственным-источником-глобального-охвата) — roadmap является единственным источником глобального охвата.
- [BR-MODEL-002](../modules/model.md#br-model-002-ссылки-не-выходят-за-repository-root) — ссылки не выходят за repository root.
- [BR-MODEL-003](../modules/model.md#br-model-003-готовая-к-работе-задача-имеет-полный-проверяемый-контракт) — готовая к работе задача имеет полный проверяемый контракт.
- [BR-CLI-002](../modules/cli.md#br-cli-002-проверки-запускаются-только-явно) — проверки запускаются только явно.

## Проверка

- позитивные fixtures полной и минимальной модели;
- негативные тесты каждого правила валидации;
- отдельный тест, что обычный `check` не вызывает command runner.
