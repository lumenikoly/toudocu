# UC-AGENT-01: Установить AI-skill Toudocu

- Идентификатор: UC-AGENT-01
- Статус: Готово
- Актор: Пользователь Toudocu
- Модуль: MOD-CLI
- Приоритет: Высокий
- Последнее обновление: 2026-08-12

Пользователь устанавливает встроенный пакет `toudocu` для поддерживаемого
AI-агента, проверяет его состояние, обновляет или удаляет. Пакет берётся из
текущего бинарника: сеть и системная оболочка не используются.

## Входные данные

- операция `install`, `status`, `update` или `uninstall`;
- агент либо режим `auto`/`all`;
- место установки `project` или `user`;
- необязательный корень репозитория для установки в проект.

## Предусловия

- текущий пользователь может читать и, для изменяющих операций, записывать в
  выбранный каталог;
- неизвестная или изменённая вручную копия заранее разрешается пользователем:
  Toudocu не перезапишет её сам.

## Основной сценарий

1. Пользователь при необходимости запускает `toudocu skill status`, чтобы
   увидеть найденные назначения и их состояние.
2. Он выбирает агента и область установки и запускает нужную операцию, например
   `toudocu skill install`.
3. CLI определяет точный каталог и печатает его абсолютный путь.
4. Перед любой записью Toudocu проверяет все выбранные назначения. Для
   `--agent all` этот этап полностью заканчивается до изменения первого
   каталога.
5. `install` создаёт отсутствующую копию или обновляет неизменённую управляемую;
   `update` требует уже установленную управляемую копию; `uninstall` удаляет
   только неизменённую управляемую копию. `status` ничего не записывает.
6. CLI показывает результат для каждого назначения. Код `0` означает, что все
   операции успешны или изменение уже не требовалось.

## Ошибочные сценарии

- Если `auto` неоднозначен и терминал не позволяет спросить пользователя,
  возвращается `SKILL_AGENT_REQUIRED`.
- Символическая ссылка, выход за разрешённый каталог или совпадение с самой
  границей возвращает `SKILL_PATH_UNSAFE`; назначение не меняется.
- Неуправляемая, изменённая, повреждённая или более новая копия не
  перезаписывается.
- Если назначение изменилось после планирования, публикация отменяется.
- При ошибке прежняя копия восстанавливается. Если восстановление невозможно,
  резервная копия сохраняется, её путь выводится пользователю, а команда
  возвращает `SKILL_RESTORE_FAILED`.

## Постусловия

После успешного `install`, `update` или `uninstall` назначение либо отсутствует,
либо содержит точную управляемую копию встроенного пакета с манифестом версии
1. `status` только сообщает состояние. При конфликте пользовательские файлы
остаются на месте.

## Критерии приёмки

- [x] После успешного `install`, `update` или `uninstall` назначение отсутствует
  либо содержит точную управляемую копию встроенного пакета с манифестом
  версии 1.
- [x] При конфликте пользовательские файлы остаются на месте.

## Проверка сценария

Покрываются корректность встроенного пакета и манифеста, установка в проект и
профиль пользователя, несколько назначений, опасные пути и ссылки, подмена
назначения между планом и записью, восстановление после ошибки и сборка для
поддерживаемых платформ без CGO.
