# UC-TASK-03: Подготовить новую рабочую задачу

- Идентификатор: UC-TASK-03
- Статус: Готово
- Актор: Исполнитель — разработчик или программный агент
- Модуль: MOD-CLI
- Приоритет: Высокий
- Последнее обновление: 2026-08-10

Исполнитель находит связанные документы, создаёт пустой по смыслу каркас задачи
и заполняет его до состояния, которое можно вручную перевести в «Готово к
работе».

## Входные данные

- запрос пользователя;
- каталог документации;
- область, заголовок и тип задачи;
- необязательный язык каркаса.

## Предусловия

- Toudocu доступен, а каталог документации существует;
- исполнитель сам понял запрос и выбрал действительно связанные сущности.

## Основной сценарий

1. Исполнитель запускает `toudocu search <запрос> ./docs` и читает найденные
   исходные документы.
2. Он создаёт черновик через `toudocu task init`, явно указывая область,
   заголовок и тип.
3. Если задаче действительно нужны новые документы, исполнитель создаёт только
   выбранные каркасы через `toudocu scaffold`.
4. В `TASK-*` он своими словами заполняет область работы, то, что не входит в
   неё, изменение поведения, ограничения, критерии `AC-*`, план, команды
   проверки и влияние на документацию.
5. Команда `toudocu task ready TASK-ID ./docs` проверяет полноту, но ничего не
   меняет. Для полного черновика она возвращает `contract_ready`.
6. Исполнитель ещё раз проверяет смысл и выполнимость задачи и вручную меняет
   статус на «Готово к работе».
7. Повторный `task ready` возвращает `ready`.

## Ошибочные сценарии

- Неверный тип, язык, ID или предел результатов завершает команду с кодом `1`.
- Существующий целевой файл не перезаписывается.
- Незаполненный контракт получает `contract_incomplete` с перечнем недостающих
  частей.
- Ошибка связанной документации блокирует готовность.
- Любой статус, кроме черновика и «Готово к работе», возвращает
  `invalid_state`.

## Постусловия

Каркас не содержит придуманных Toudocu связей или требований. Только
исполнитель выбирает документы, пишет смысловые поля и меняет статус.

- [BR-MODEL-003](../modules/model.md#br-model-003-готовая-к-работе-задача-имеет-полный-проверяемый-контракт) — готовность означает полный проверяемый контракт.

## Проверка сценария

Покрываются поиск, нормализация запроса, безопасное создание файла и выделение
ID, а также результаты `contract_incomplete`, `contract_ready` и `ready`.
