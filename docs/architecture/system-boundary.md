# Системная граница Toudocu

Toudocu работает как один локальный Go-процесс. Он читает документацию и
разрешённые данные репозитория, строит модель и возвращает сообщения об ошибках,
JSON-отчёт или готовый портал. Программа, использующая Go-пакет, вызывает тот же
фасад без отдельного процесса.

В режиме `serve` процесс дополнительно принимает ограниченные запросы редактора,
раздела «Изменения» и API обратной связи с агентом. Обсуждения, привязки и записи очереди он
хранит в пользовательском каталоге операционной системы, а не в репозитории.
Команды читают то же состояние даже при остановленном `serve`.

Основной портал `serve` может один раз запросить у GitHub метаданные последнего
стабильного релиза. Это единственный исходящий сетевой запрос работающего
портала, и его можно отключить флагом. Установщики релиза находятся вне
Go-процесса: они используют сеть до запуска Toudocu.

## Область

Документ описывает границу Go-процесса, доступного через CLI и публичный пакет.
Точные команды и форматы находятся в [CLI-контракте](../contracts/cli.md),
Go-фасад — в [справочнике возможностей](../reference/features.md#публичный-go-api),
а причина поставки без сторонних зависимостей — в
[ADR-001](../decisions/001-dependency-free.md).

## Кто взаимодействует с Toudocu

- Разработчик или агент выбирает каталог, корень репозитория и операцию.
- Программа на Go вызывает экспортируемые функции `api.go` и получает модель
  или типизированный отчёт.
- CI использует код завершения и `ProjectReport` версии 1.
- Файловая система предоставляет Markdown, локальные ресурсы и явно разрешённые
  файлы репозитория.
- Браузер читает статический HTTP-портал. При `serve` он также обращается к
  локальным API редактора, изменений и OpenAPI-справки.
- GitHub Releases API, если проверка версии не отключена, возвращает недоверенные
  метаданные стабильного релиза. Браузер получает только обработанный
  same-origin ответ локального сервера.
- Системная оболочка и дочерние процессы используются только после явного
  `task verify --run`.
- Команды `skill install`, `update` и `uninstall` ограниченно меняют выбранную
  копию встроенного навыка; `status` только читает её состояние.
- Установленный навык через командную строку получает старейшую незавершённую запись и
  возвращает структурированный ответ. Toudocu не запускает агента и не
  вызывает внешнюю модель ИИ.

## Что остаётся снаружи

Toudocu не хранит серверное состояние в репозитории, не использует базу данных
и не решает, что имел в виду пользователь. Смысловую работу выполняет человек
или агент; эта граница закреплена в [ADR-002](../decisions/ADR-002.md).

Загрузка релиза и запись бинарника относятся к отдельному
[процессу установки](../guides/installation.md). Размещение встроенного навыка
по явной команде описано в
[руководстве по его установке](../guides/skill-installation.md).
