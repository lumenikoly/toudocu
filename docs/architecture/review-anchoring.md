# Привязка комментариев к меняющимся файлам

- Тип документа: Architecture
- Архитектурный вопрос: Как комментарий остаётся привязанным к меняющемуся файлу?

Для каждого обсуждения Toudocu неизменно хранит исходную привязку, а её текущее
положение вычисляет заново. Браузер передаёт только вид привязки и координаты
Unicode, начиная с единицы. Выделенный текст, соседние строки и хеш содержимого
Go-процесс сам извлекает из проверенного файла, поэтому браузер не может
подменить их.

## Исходный anchor

Для привязок `diff`, `fileRange` и `file` сохраняются исходный путь, старая или
новая сторона сравнения, диапазон, выделенный текст, до 2 КиБ контекста с каждой
стороны, хеш содержимого и версия репозитория. Также создаётся снимок файла с
именем по его содержимому. Он появляется только после сохранения комментария,
не может быть больше 2 МиБ и лежит в пользовательском состоянии вне
репозитория. У общей привязки `global` снимка файла нет.

## Поиск текущего положения

После изменения файла сервер последовательно пробует следующие способы:

1. Если хеш содержимого не изменился, сохраняются исходные координаты.
2. Если Git однозначно распознал переименование, меняется путь; карта строк Git
   переносит диапазон.
3. Выделенный текст ищется в пределах 20 строк от прежнего места.
4. Если рядом совпадения нет, принимается единственное точное совпадение во всём
   файле.
5. Затем ищется единственная пара сохранённых контекстов с расстоянием не более
   32 КиБ.
6. Неоднозначная или изменившаяся привязка получает состояние `stale`, а
   удалённый файл — `deleted`.

Вычисленное положение не изменяет исходную привязку. Оно пересчитывается при
каждом чтении относительно текущего состояния репозитория. Список
`changedPaths`, который вернул агент, нужен только для ссылки «Посмотреть
исправление»: реальное изменение всегда определяется по текущему Git diff.
