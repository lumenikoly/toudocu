# Границы доверия Toudocu

Содержимое документации всегда считается недоверенным. Пути к репозиторию,
выходному каталогу и отчёту задают границу файловых операций. Команда из рабочей
задачи становится доверенным кодом только после отдельного явного разрешения на
`task verify --run`. Установщик релиза до запуска Toudocu отдельно доверяет
выбранному GitHub Release как источнику архива и контрольной суммы.

## Недоверенное содержимое

Текст и метаданные экранируются при создании HTML. Опасные схемы ссылок,
активные локальные ресурсы и выход пути за корень репозитория блокируются.
Mermaid использует встроенный пакет и строгий режим; диаграмма остаётся
картинкой и не становится источником требований.

Точные правила Markdown описаны в [MOD-MARKDOWN](../modules/markdown.md), а
ошибки CLI — в [CLI-контракте](../contracts/cli.md).

## Файловая система

Все входные и выходные пути нормализуются до чтения, записи или очистки.
Символическая ссылка не может подменить защищённый каталог, а созданный портал
никогда не читается обратно как исходная документация.

Назначение встроенного skill ограничено основным каталогом проекта или
пользовательским каталогом. Символические ссылки, специальные файлы и выход за
эту границу блокируют установку. Манифест версии 1 и таблица SHA-256 отличают
неизменённую управляемую копию от неизвестной или изменённой вручную. Конфликт
автоматически не перезаписывается.

Редактор `serve` принимает только обычный относительный POSIX-путь к `.md`,
`.yaml`, `.yml` или `.json` внутри основного каталога документации. Скрытые,
исключённые и выходные каталоги, переход `..`, остатки кодирования и любые
символические ссылки запрещены. Хеш SHA-256 и атомарная замена защищают от
случайной потери параллельной правки.

Обсуждения принимают только обычные пути относительно репозитория. Абсолютные
пути, `..`, процентное кодирование, `.git`, специальные и двоичные файлы и
символические ссылки отклоняются. Снимок UTF-8 файла не может быть больше
2 МиБ. Состояние хранится с закрытыми правами `0700`/`0600`; повреждённый файл
не перезаписывается автоматически, а параллельные записи согласуются блокировкой
и сверкой версии.

## Локальный HTTP-сервер

Запись редактора и обсуждений требует JSON, точного заголовка действия и
same-origin контекста браузера. Размер запроса и содержимого ограничен, CORS не
выдаётся. Эти меры защищают от чужой веб-страницы, но не аутентифицируют прямой
HTTP-клиент. Поэтому `--host 0.0.0.0` включает всех доступных клиентов локальной
сети в доверенную область; встроенных TLS и авторизации нет.

Комментарии можно менять только для `target=working-tree`. Сравнение с
коммитом или индексом остаётся только для чтения.

Каждый запуск выбирает один настроенный каталог документации. Остальные
каталоги локалей исключаются из его модели. Редактор пишет только в выбранный
каталог; язык не меняет сетевые ограничения и доступность локальных функций.

Кнопки задачи копируют короткую инструкцию с её ID, а кнопка контекста —
название и путь документа. Копирование не отправляет данные внешнему сервису
и не запускает процесс. Инструкция только для чтения не является sandbox:
внешний агент сам определяет и применяет свои разрешения.

Страница API загружает Swagger UI и OpenAPI-файл выбранного проекта локально.
Из интерфейса разрешены только методы `GET` и `HEAD`. Адрес пробного запроса
определяет спецификация; интерфейс не ограничивает его адресом Toudocu.
Перед запросом пользователь должен проверить указанный сервер.

Автоматического запроса к GitHub для проверки новых выпусков в текущей
реализации нет.

## Запуск внешних программ

Project Terminal доступен только в `serve`, привязанном к loopback-адресу.
Сервер по явному действию запускает обычную оболочку из своего окружения в
корне репозитория. Браузер и репозиторий не задают executable, argv, cwd или
environment. Последующие команды вводит пользователь.

Terminal API проверяет loopback Host и адрес соединения, same-origin контекст,
а для POST — известный X-Toudocu-Action. WebSocket принимает только ввод,
прерывание и ограниченные размеры терминала. Скрытие панели не останавливает
PTY; закрытие сервера останавливает его. Статическая сборка и non-loopback
`serve` не предоставляют эту возможность.

Agent Console и её поставщики удалены. Кнопки задач копируют инструкции для
внешнего агента. Прямое завершение использует валидацию и digest Editor API;
оно не запускает проверку задачи. См. [контракт терминала](../contracts/terminal.md).

Раздел изменений запускает установленный `git` напрямую с отключёнными внешним
diff, `textconv` и цветом. Он не вызывает системную оболочку, hooks, `fetch`,
`checkout` и не пишет в индекс. Ссылки Git проверяются, а содержимое читается
из локальной базы
объектов или рабочего дерева.

Обсуждения используют ту же границу для разрешённых файлов всего репозитория.
CLI обратной связи читает и записывает только локальное состояние обсуждений;
агента, AI-модель и команды проекта он не запускает.

Обычные `check`, `build`, `serve`, редактор, `search`, `task ready`,
`task candidates` и `task context` не исполняют команды из Markdown. Такая
возможность появляется только у `task verify --run` после проверки локального
контракта задачи. Правила описаны в [MOD-CLI](../modules/cli.md).

## Установщик релиза

POSIX- и PowerShell-установщики работают с правами текущего пользователя. Они
проверяют Node.js 24+, загружают архив и `checksums.txt` из одного HTTPS-релиза,
требуют ровно одну подходящую запись SHA-256, проверяют версию и только потом
активируют установленный пакет. Общий источник архива и суммы позволяет заметить повреждение при
загрузке, но не заменяет независимую цифровую подпись.

По умолчанию `sudo` не используется. Явный `TOUDOCU_INSTALL_DIR` может указать
другой доступный каталог, но не меняет профиль системной оболочки. Ошибка до
активации не повреждает существующую установку. Команды вида `curl | sh` и
`irm | iex`
означают, что пользователь доверяет удалённому тексту установщика.

## Встроенный AI-skill

Пакет skill входит в release-архив и после установки не требует сети. Перед записью
проверяются относительные пути, размер каждого файла, общий размер пакета и имя
в `SKILL.md`. Сценарии из пакета не выполняются при установке.

Новая версия готовится в соседнем временном каталоге. При обновлении или
удалении прежняя копия сначала перемещается в уникальную резервную. Любая ошибка
или параллельная подмена запускает восстановление; если оно невозможно,
резервная копия сохраняется, а её точный путь выводится пользователю.
