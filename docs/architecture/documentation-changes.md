# Архитектура просмотра изменений документации

Toudocu сравнивает два явно выбранных локальных состояния Git. Содержимое каждой
стороны загружается только по мере необходимости, а итог собирается в один
версионированный отчёт `ChangeSetReport`. В нём обычные сведения Git дополнены
данными о документах, экранах, связях и других известных сущностях Toudocu.

## Область

Здесь описано, откуда берутся состояния Git, как читаются файлы и кто получает
готовый отчёт. Формат HTTP и JSON закреплён в контрактах, пользовательский путь
описан в `UC-DOCS-05`, а правила анализа — в `MOD-CHANGES`.

## Компоненты

| Компонент | Ответственность |
|---|---|
| Источник изменений Git | Находит репозиторий, ссылки, общую базу веток, статус, патчи и содержимое файлов. Использует только команды чтения |
| Снимок документации | Безопасно читает нужные файлы из коммита, индекса или рабочего дерева внутри разрешённых каталогов |
| Сборщик отчёта | Объединяет состояния файлов, статистику строк, переименования известных сущностей и диагностические сообщения |
| Анализаторы различий | Строят исходный патч, различия разделов, семантический отчёт и специальные представления OpenAPI, Mermaid, карт экранов и ресурсов |
| Сервис изменений | Повторно использует отчёт, пока Git и рабочие файлы не изменились, и отдаёт его CLI и локальному HTTP API |
| Процесс перевода | Берёт изменения канонической документации по одному файлу и после строгой проверки записывает отдельный каталог локали |

## Поток данных

Git определяет список файлов и точный патч. Загрузчик читает содержимое нужного
состояния без переключения ветки и без изменения рабочего дерева. Анализаторы
разбирают только документы, необходимые для текущего представления. Интерфейс
и JSON-отчёт используют один результат и не пересчитывают изменения сами.

## Состояние и инвалидация

Сравнение двух коммитов неизменно, поэтому его можно безопасно кэшировать. Для
сравнения с рабочим деревом ключ кэша учитывает выбранный диапазон, версию
рабочего пространства, `HEAD`, вывод `git status --porcelain=v2` и разрешённые
ссылки Git. После любого изменения следующий запрос строит новый отчёт и новый
хеш. Toudocu не сохраняет прежнее содержимое рабочего дерева как историю.

## Границы

- удалённые ссылки Git не загружаются;
- индекс, ссылки и рабочее дерево Git не изменяются;
- у статического портала нет HTTP API раздела «Изменения»;
- ошибка специального анализатора не скрывает исходный патч;
- содержимое файла из Git не получает прав редактора или дополнительных
  возможностей отображения;
- процесс перевода не добавляет клиент AI-модели или многоязычную сущность в
  Go-модель. Его манифест и хеш хранятся отдельно от схемы
  `ChangeSetReport` версии 1.
