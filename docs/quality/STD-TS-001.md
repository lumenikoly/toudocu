# STD-TS-001: Качество TypeScript-кода

Стандарт сохраняет runtime Toudocu небольшим, предсказуемым и безопасным.

<!-- toudocu:section rules -->
## Правила

1. Production-код использует ESM и строгий TypeScript с
   `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.
2. Неизвестные данные проверяются на границе до передачи в core и application.
3. Core не импортирует React, HTTP или Node.js-адаптеры; UI не вычисляет
   доменную готовность задач.
4. Новое правило проверки или исправление безопасности подтверждается тестом,
   который обнаруживает нарушение. Используйте существующий тест, если он уже
   проверяет нужный случай; отдельный новый тест не обязателен.
5. Файловые пути нормализуются и проверяются до чтения, записи или очистки.
6. Операции с процессами учитывают `AbortSignal` и освобождают ресурсы.
7. Обычные `check`, `build`, `serve` и `task context` не выполняют команды из
   рабочих задач.

<!-- toudocu:section automated-checks -->
## Автоматические проверки

Выбирайте минимальный набор проверок по изменённому поведению и его рискам:

- форматирование, lint и проверка типов — для изменённого кода;
- затронутые тесты — для изменённой логики и контрактов;
- `pnpm test:browser` — когда изменённое браузерное поведение нельзя надёжно
  подтвердить более простой проверкой;
- `pnpm build` — для изменений сборки, упаковки или связей пакетов;
- `pnpm check` — для общего прогона перед выпуском или при изменениях,
  затрагивающих несколько подсистем.

`pnpm check` уже включает форматирование, lint, типы, тесты, совместимость и
проверку документации. Не запускайте эти же проверки отдельно после успешного
общего прогона без новых изменений или обнаруженной проблемы. Добавляйте тесты
для непокрытого поведения и существенных рисков, а не по числу критериев,
файлов или переходов. Простая правка без новой логики не требует нового теста.

Команды запускает разработчик, рабочая задача или доверенный CI. Запрет
пользователя на запуск сохраняется; план проверки не означает её выполнение.
