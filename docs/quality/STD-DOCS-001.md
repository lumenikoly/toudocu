# STD-DOCS-001: Проверяемая документация

- Идентификатор: STD-DOCS-001
- Статус: Действует
- Владелец: Команда Docu-docu
- Область: Исходная документация, шаблоны skill и отслеживаемые порталы
- Последнее обновление: 2026-07-31

Стандарт удерживает Markdown источником истины и отделяет подтверждённые
глобальные правила от локальных или сгенерированных представлений.

## Правила

1. Глобальный охват определяет `roadmap.md`; состояние явно связанного `UC-*`
   берётся из use case. Остальные локальные чек-листы не агрегируются.
2. Сгенерированные `build/`, `dist/`, `example/site/`, `project-docs/` и
   `example/project-docs/` не редактируются как источник истины.
3. Отслеживаемые порталы пересобираются из Markdown после semantic review и
   структурной проверки.
4. Типизированный документ создаётся только для подтверждённой семантики;
   неизвестные владелец, дата, статус или процедура не изобретаются ради
   отсутствия предупреждения.
5. Явно связанные стандарты и runbook читаются вместе с task context; область
   других применимых стандартов проверяется автором без glob-эвристик CLI.
6. `docs/runbooks/` создаётся только при наличии реальной эксплуатационной
   процедуры.
7. `docs/architecture/overview.md` является обязательной картой; каждый другой
   Markdown-файл в `architecture/` отвечает на один явный архитектурный вопрос
   и добавляется прямой ссылкой из overview.
8. Подробности FLOW, CONTRACT, REFERENCE, RUNBOOK, ADR и MODULE остаются в
   соответствующих источниках истины, а semantic gate проверяет архитектурную
   форму и смысл по `ARCH001`–`ARCH013`.
9. `$docu-docu refresh` и `$docu-docu refresh diff` обновляют исходную
   документацию только по текущим repository evidence; даты меняются вместе с
   содержанием или связями, а `Last verified` требует фактической проверки
   runbook.
10. Корневой `CHANGELOG.md`, если он существует, является единственным
    специальным источником релизных изменений. Его нельзя дублировать в
    `docs/changelog.md`: такой файл остаётся обычным Markdown-документом.
    Не создавайте корневой журнал только ради portal-вкладки.

## Автоматические проверки

- `go run ./cmd/docu-docu check ./docs --strict --stale-days 0`;
- тесты целостности шаблонов и публичного JSON schema;
- тесты ссылок, стабильных ID, task context и портальной навигации.

Команды запускаются из work item или доверенного CI workflow, а не напрямую из
этого стандарта.
