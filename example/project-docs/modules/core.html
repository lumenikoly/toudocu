MOD-CORE

Основной модуль объединяет backend-логику создания обращений и стабильный контракт, используемый Web Frontend.

#Назначение

Проверяет входные данные, создаёт обращение в PostgreSQL и возвращает идентификатор для отображения пользователю.

#Расположение в коде

  • Backend API: backend/internal/requests/
  • SQL repository: backend/internal/storage/
  • Web Frontend: frontend/src/features/requests/
  • Тесты: backend/internal/requests/*_test.go, frontend/src/**/*.test.*

#Границы

Модуль владеет сценарием создания обращения и схемой его хранения. Он не отвечает за содержимое внешнего Support Center, инфраструктуру PostgreSQL или доставку статических файлов фронтенда.

#Бизнес-правила

#BR-CORE-001: Результат создаётся только после проверки входных данных

Некорректные входные данные не изменяют состояние системы.

#BR-CORE-002: Идентификатор обращения создаётся на сервере

Frontend не может передать или переопределить id, status и createdAt.

#Инварианты

  • Состояние остаётся согласованным после любой ошибки.
  • Успешный ответ означает, что транзакция PostgreSQL зафиксирована.
  • Повторная серверная валидация обязательна даже после проверки во фронтенде.
