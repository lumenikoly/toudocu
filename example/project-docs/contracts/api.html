API-контракт

REST-контракт между Web Frontend и Backend API. Все ответы имеют Content-Type: application/json ; время передаётся в UTC по RFC 3339.

Идентификатор
CON-CORE-API

REST-контракт между Web Frontend и Backend API. Все ответы имеют Content-Type: application/json; время передаётся в UTC по RFC 3339.

#Создать обращение

POST /api/v1/requests

#Запрос

json
{
  "title": "Не открывается отчёт",
  "description": "После входа страница отчёта возвращает ошибку."
}
ПолеТипОбязательноеОграничения
titlestringДаОт 3 до 120 символов
descriptionstringДаОт 10 до 4000 символов

Неизвестные поля игнорируются для обратной совместимости в пределах API v1.

#Успешный ответ

201 Created

json
{
  "id": "1f0f45a4-1f85-4aa7-9348-c4902f2537fd",
  "status": "new",
  "createdAt": "2026-07-29T18:00:00Z"
}

#Ошибки

IDСообщение
INVALID_INPUTПроверьте заполнение обязательных полей.
UNSUPPORTED_MEDIA_TYPEОжидается тело запроса в формате JSON.
INTERNAL_ERRORНе удалось обработать обращение.
STORAGE_UNAVAILABLEХранилище временно недоступно.

#Формат ошибки

Все ошибки имеют единую структуру:

json
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "Проверьте заполнение обязательных полей.",
    "fields": {
      "title": "Минимальная длина — 3 символа."
    }
  }
}

#HTTP-ответы

HTTPКодКогда возвращается
400INVALID_INPUTПоля отсутствуют или нарушают ограничения
415UNSUPPORTED_MEDIA_TYPEТело запроса не является JSON
500INTERNAL_ERRORНеобработанная внутренняя ошибка
503STORAGE_UNAVAILABLEPostgreSQL временно недоступна

При любом ответе, кроме 201, обращение считается несозданным.

#Совместимость

  • префикс /api/v1 фиксирует major-версию;
  • новые необязательные поля могут добавляться без смены major-версии;
  • удаление поля или изменение его смысла требует новой major-версии.
