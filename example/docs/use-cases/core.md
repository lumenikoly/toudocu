- Экраны: SC-CORE-HOME, SC-CORE-REQUEST, SC-CORE-HELP, SC-CORE-RESULT

- Последнее обновление: 2026-07-29

Пользователь регистрирует обращение и получает его номер.

## Входные данные

- заголовок обращения;
- подробное описание проблемы.

## Предусловия

- Система доступна.

## Основной сценарий

1. Пользователь открывает форму нового обращения.
2. При необходимости пользователь открывает и закрывает контекстную подсказку.
3. Пользователь вводит заголовок и описание.
4. Web Frontend проверяет заполнение обязательных полей и отправляет запрос.
5. Backend API повторно проверяет данные и сохраняет обращение в PostgreSQL.
6. Система показывает номер и время создания обращения.

## Ошибочные сценарии

При неверных данных система выделяет проблемные поля и не создаёт запись. Если
PostgreSQL временно недоступна, система сообщает о технической ошибке и
предлагает повторить попытку.

## Постусловия

При успехе обращение сохранено со статусом `new`; при ошибке новая запись
отсутствует.

## Бизнес-правила

- BR-CORE-001 — правило проверки входных данных.
- BR-CORE-002 — сервер формирует системные поля обращения.
