# ADR-000: Разделить Web Frontend, Backend API и PostgreSQL

- Идентификатор: ADR-000
- Статус: Принято
- Дата: 2026-07-25
- Автор: Architecture Team
- Последнее обновление: 2026-07-29

Service Desk реализуется как три изолированных слоя с явными интерфейсами.

## Контекст

Пользовательский интерфейс должен независимо развиваться и публиковаться как
статическое приложение, а правила валидации и сохранения не должны зависеть от
браузера. Прямой доступ фронтенда к данным сделал бы невозможно централизованно
защищать инварианты и секреты подключения.

## Решение

Принята следующая граница:

1. Web Frontend отвечает за отображение и предварительную проверку формы.
2. Backend API является единственной публичной точкой бизнес-операций.
3. PostgreSQL доступна только Backend API через приватное подключение.
4. Взаимодействие Frontend и Backend версионируется префиксом `/api/v1`.

## Причины

- серверная валидация одинакова для всех будущих клиентов;
- схема данных и учётные данные БД не раскрываются браузеру;
- фронтенд можно публиковать независимо от backend-релиза;
- транзакционная БД обеспечивает однозначное создание обращения.

## Последствия

### Положительные

- компоненты можно тестировать и развёртывать независимо;
- публичная поверхность ограничена HTTPS API;
- бизнес-правила и транзакции сосредоточены в Backend API.

### Отрицательные

- требуется поддерживать API-контракт и совместимость версий;
- появляется отдельное сетевое взаимодействие между UI и Backend;
- миграции PostgreSQL необходимо координировать с backend-релизами.
