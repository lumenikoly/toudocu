# Топология развёртывания Service Desk

- Тип документа: Architecture
- Архитектурный вопрос: Как компоненты размещаются в целевой топологии MVP?

Статический Web Frontend публикуется за HTTPS reverse proxy, Backend API
работает в приватном сегменте за тем же публичным входом, а PostgreSQL —
в отдельном приватном сегменте с доступом только от backend.

## Область

Это целевая топология демонстрационного MVP, а не эксплуатационный runbook или
справочник конфигурации. Последовательность релиза, миграций и отката, работа с
секретами, высокая доступность, репликация, фоновые workers и конкретная
платформа развёртывания не определены. Параметры компонентов остаются в
[справочнике конфигурации](../reference/configuration.md).

## Узлы и соединения

- reverse proxy завершает публичный HTTPS и раздаёт frontend;
- запросы `/api/v1` направляются в Backend API по внутреннему соединению;
- Backend API открывает приватное SQL-подключение к PostgreSQL.

Причины независимого размещения слоёв и последствие в виде координации миграций
зафиксированы в [ADR-000](../decisions/000-decision.md).
