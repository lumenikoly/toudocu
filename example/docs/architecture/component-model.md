# Компонентная модель Service Desk

- Тип документа: Architecture
- Архитектурный вопрос: Как компоненты Service Desk делят ответственность?

Web Frontend отвечает за представление и предварительную проверку, Backend API
повторно валидирует запрос и владеет бизнес-операцией, PostgreSQL обеспечивает
транзакционное хранение. Ни один слой не принимает ответственность соседнего.

## Область

Ответ фиксирует архитектурное разделение трёх компонентов. Причина выбора
разделения находится в [ADR-000](../decisions/000-decision.md), локальные
правила — в [MOD-CORE](../modules/core.md).

## Ответственность

| Компонент | Владеет | Не владеет |
|---|---|---|
| Web Frontend | Формой, локальными состояниями загрузки и ошибок | Серверным ID, фиксацией обращения, SQL |
| Backend API | Серверной валидацией, бизнес-правилами и транзакцией создания | Отображением и публикацией статических файлов |
| PostgreSQL | Согласованным хранением обращений | Публичным API и UI-логикой |

Подробное взаимодействие компонентов показано в
[FLOW-CORE-REQUEST](../flows/FLOW-CORE-REQUEST.md), а публичные поля и ответы
зафиксированы в [API-контракте](../contracts/api.md).
