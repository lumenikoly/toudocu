# ADR-006: Optional Stable Release Check in Canonical Serve


Canonical `serve` performs an optional, safely constrained check for the latest
stable release and reports a newer version in the portal UI without updating
itself.

<!-- toudocu:section context -->
## Context

A local portal user cannot see that the installed Toudocu version is out of
date. At the same time, static output must remain self-contained, the browser
must not reveal documentation viewing directly to an external service, and the
CLI must not download or replace its own binary without an explicit command.

<!-- toudocu:section decision -->
## Decision

Only canonical `toudocu serve`, upon the browser's first same-origin request,
reads the latest stable release once per process from the project's fixed
GitHub API. The request is enabled by default and disabled by
`--no-update-check`.

Go validates the bounded response, compares only `X.Y.Z` versions, and returns
a schema-v1 status to the browser. When an update exists, the portal shows a
non-blocking suggestion to open the official release page. It neither downloads
artifacts nor performs a self-update. A failed check does not affect the portal.

Static builds, translation portals, and other commands do not use the network.
A timeout, response-size limit, redirect prohibition, absence of credentials,
and construction of the release URL from the validated version keep the
external boundary narrow.

## Considered alternatives

- Browser contacts GitHub directly — rejected because constraining the response
  is harder and every visitor gains a separate external boundary.
- Check during `build` — rejected because it makes a reproducible build depend
  on the network and the result quickly becomes stale.
- Opt-in only — rejected because poor discoverability removes most of the
  feature's value; explicit opt-out preserves the self-contained mode.
- Automatic installation — rejected because it requires separate consent,
  artifact verification, and a transactional lifecycle.

<!-- toudocu:section consequences -->
## Consequences

- Canonical `serve` gains one optional outbound HTTPS request.
- GitHub metadata becomes untrusted input with explicit limits.
- The portal receives only a status and validated link, while failures remain
  invisible.
- Dependency-free delivery and self-contained static output are preserved.
