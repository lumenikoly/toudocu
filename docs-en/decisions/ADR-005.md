# ADR-005: Goldmark as the Single Markdown Engine


In one cutover, Toudocu replaces its own line/regex parser and renderer with
pinned pure-Go Goldmark `v1.8.5`, preserving a single self-contained binary and
its own safe document model.

<!-- toudocu:section context -->
## Context

The custom Markdown subset diverged from CommonMark for nested and loose lists,
escapes, fence variants, and inline constructs. Re-parsing lines for tables,
Mermaid, and semantic diffs created several competing interpretations of one
document. One AST source of structure is needed without exposing third-party
library types through the public Go facade or JSON schema v1.

<!-- toudocu:section decision -->
## Decision

Use `github.com/yuin/goldmark v1.8.5` with its CommonMark 0.31.2-compatible core
and only the built-in Table, TaskList, Strikethrough, and Linkify extensions.
`internal/markdown` owns the `Parse → Analysis → Render` cycle, source ranges,
and the private Goldmark AST. Toudocu creates heading IDs and the normalized
model itself, resolves repository URLs/assets, and renders portal hooks.

Raw block/inline HTML and leading closed front matter are policy errors. Preview
and rendered diff show such source only as escaped text. `html.WithUnsafe`,
attributes, footnotes, definition lists, typographer, and third-party extensions
are not enabled. Mermaid is recognized only by the single case-insensitive info
string `mermaid` and retains a separate strict policy.

The low-level `AnalyzeMarkdown`, `RenderMarkdown`,
`RenderMarkdownFragment`, `ParsedMarkdown`, `RenderContext`, `RenderOptions`,
`LinkResolver`, and `LinkResolution` are removed from the public facade. The
high-level model, reporting, portal, and task-workflow operations remain public;
JSON schema v1 is unchanged.

<!-- toudocu:section consequences -->
## Consequences

- CommonMark and allowed GFM constructs share one AST contract.
- Structural consumers no longer find headings, tables, tasks, and fences with
  independent line/regex parsers.
- Updating Goldmark requires corpus, security, semantic, and cross-build review.
- Canonical HTML and whitespace may change without changing the high-level
  model.
- The dependency is linked into the binary and creates no runtime service,
  network access, CGO, or adjacent file.
